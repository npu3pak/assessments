# Лекция 04: Антисанкции — автономная разработка Flutter

**Цель лекции:** Ознакомиться с методами и инструментами, позволяющими выполнять разработку мобильных приложений на Flutter в условиях ограниченного или отсутствующего доступа к интернету. Это особенно актуально для разработчиков, работающих в закрытых сетях, на удаленных объектах или с ограниченным трафиком.

---

## 📌 Введение

Разработка мобильных приложений — это процесс, который обычно предполагает активное использование интернета: скачивание зависимостей, обновления фреймворков, установка SDK и т.д. Однако в некоторых условиях (например, в закрытых сетях, на удалённых станциях или с ограниченным интернетом) требуется работать **в автономном режиме**, без доступа к интернету.

Такая ситуация требует внедрения специальных механизмов и инструментов для обеспечения независимости от внешних ресурсов. В этой лекции мы рассмотрим:

1. **Офлайн установка VSCode, FVM и Flutter**
2. **Авангардная инфраструктура для автономного хранения плагинов Flutter**
3. **Автономное хранение Android SDK**
4. **Инфраструктура для хранения Gradle-артефактов**

---

## 1. Офлайн установка VSCode, FVM и Flutter

### 🛠️ Что нужно знать?

Для работы в автономном режиме важно подготовить:

- IDE (VS Code)
- Управление версиями Flutter (FVM — Flutter Version Manager)
- Сам фреймворк Flutter

Все эти компоненты должны быть доступны **в локальном окружении** без подключения к интернету.

---

### ✅ Установка VS Code офлайн

#### Шаги:

1. Скачайте установочный файл **VSCode** для вашей ОС (например, `code-win32-x64-<version>.zip`).
2. Распакуйте его в локальную директорию.
3. Установите дополнительные плагины (предварительно скачанные `.vsix` файлы):

```bash
code --install-extension flutter.flutter
code --install-extension dart-code.dart-code
```

> 💡 **Примечание:** Плагины можно скачивать с официального сайта [Visual Studio Marketplace](https://marketplace.visualstudio.com/vscode).

---

### ✅ Установка FVM офлайн

#### Шаги:

1. Скачайте архив с репозиторием FVM:
   - GitHub: https://github.com/FlutterVx/fvm
2. Распакуйте его в локальный каталог.
3. Запустите установку через `pub get` или `flutter pub get`:

```bash
cd fvm
flutter pub get
```

4. Добавьте FVM в `PATH` (если нужно) и используйте команды:

```bash
fvm install 3.10.0
fvm use 3.10.0
```

> 🧠 **FVM** позволяет управлять несколькими версиями Flutter локально, что удобно при работе с проектами на разных версиях.

---

### ✅ Установка Flutter офлайн

#### Шаги:

1. Скачайте архив с Flutter SDK:
   - https://github.com/flutter/flutter/releases
2. Распакуйте его в директорию (например, `~/flutter`).
3. Убедитесь, что `flutter/bin` добавлен в `PATH`.
4. Запустите:

```bash
flutter doctor
```

> ⚠️ При первом запуске может потребоваться ручная установка зависимостей, таких как Android SDK и Java.

## 2. Инфраструктура для автономного хранения плагинов Flutter

### 🧩 Что такое плагины?

Flutter использует **pub.dev** для управления пакетами (плагинами). Для работы без интернета необходимо:

- Хранить зависимости локально
- Использовать **свою собственную pub-репозиторий** или **кэш**

---

### ✅ Локальный кэш плагинов

#### 1. Подготовка кэша

Создайте папку, например:

```bash
mkdir ~/flutter_cache
```

Затем настройте переменную окружения:

```bash
export PUB_CACHE=~/flutter_cache
```

#### 2. Использование в проекте

В файле `pubspec.yaml` можно указать зависимости, и они будут загружаться из кэша:

```yaml
dependencies:
  flutter:
    sdk: flutter
  http: ^0.13.5
```

При первом запуске `flutter pub get` скачает зависимости в кэш.

---

### ✅ Локальный pub-репозиторий

Для полного контроля:

1. Создайте собственный **pub-сервер** или используйте **Pub Server (например, Artifactory или Nexus)**
2. Настройте `pubspec.yaml` на использование локального репозитория:

```yaml
dependency_overrides:
  http:
    path: ./packages/http
```

> 💡 Вариант: можно использовать `git submodule`, чтобы хранить зависимости внутри проекта.

## 3. Инфраструктура для автономного хранения Android SDK

### 🧱 Зачем это нужно?

Android SDK необходим для сборки Android-приложений. Он включает:

- Компиляторы
- Системные библиотеки
- Адаптеры устройств и т.д.

---

### ✅ Установка Android SDK офлайн

#### Шаги:

1. Скачайте **Android Studio** (или SDK отдельно) в архиве.
2. Распакуйте его в локальный каталог:

```bash
mkdir ~/android_sdk
unzip android-sdk.zip -d ~/android_sdk
```

3. Установите переменные окружения:

```bash
export ANDROID_HOME=~/android_sdk
export PATH=$PATH:$ANDROID_HOME/cmdline-tools/latest/bin
```

> 📌 Важно: `cmdline-tools` и `platform-tools` должны быть доступны в `$PATH`.

---

### ✅ Пример: Проверка установки

```bash
sdkmanager --list
```

Если всё настроено, список установленных пакетов отобразится.

## 4. Инфраструктура для автономного хранения Gradle-артефактов

### 🧠 Что такое Gradle?

Gradle — это система сборки для Android проектов. Она скачивает зависимости (например, библиотеки из Maven), и для работы офлайн нужно:

- Хранить кэш Gradle
- Использовать локальный репозиторий

---

### ✅ Локальный Gradle кэш

#### Шаги:

1. Запустите проект впервые, чтобы Gradle скачал зависимости.
2. Найдите папку кэша:

```bash
# Linux / macOS:
~/.gradle/caches/modules-2/files-2.1/

# Windows:
%USERPROFILE%\.gradle\caches\modules-2\files-2.1\
```

3. Скопируйте эту папку на другой компьютер или в резервную копию.

---

### ✅ Использование локального репозитория Gradle

Если вы используете **Maven** или **JCenter**, можно:

1. Загрузить зависимости локально.
2. Настроить `build.gradle`:

```gradle
repositories {
    flatDir {
        dirs 'libs'
    }
}
```

Или использовать локальный **Artifactory / Nexus**.
