# Лекция: Сложность алгоритмов (Big O)

## Введение

Когда вы начинаете изучать программирование, особенно в контексте мобильной разработки на Flutter, важно понимать, **насколько эффективны ваши алгоритмы**. Эффективность алгоритма напрямую влияет на производительность вашего приложения — от быстроты загрузки данных до отзывчивости интерфейса.

Одним из ключевых инструментов для оценки эффективности алгоритмов является **Big O нотация**. Она позволяет охарактеризовать, как растет время выполнения или использование памяти алгоритма по мере увеличения входных данных.

---

## Что такое Big O?

**Big O нотация** — это математическая нотация, используемая для описания **асимптотического поведения функции**, то есть поведения алгоритма при увеличении размера входных данных. Мы используем её, чтобы понять, как быстро работает ваш код и как он масштабируется.

### Пример:

Если у вас есть массив из 100 элементов и вы хотите найти определённый элемент, вам может потребоваться проверить все 100 элементов. В худшем случае, это будет **O(n)** — линейное время выполнения.

## Основные классы сложности

Вот список наиболее распространённых классов сложности:

| Класс сложности | Название        | Примерная оценка       |
|------------------|------------------|------------------------|
| O(1)             | Константное время | Доступ к элементу по индексу |
| O(log n)         | Логарифмическое   | Бинарный поиск         |
| O(n)             | Линейное          | Обход массива          |
| O(n log n)       | Линейно-логарифмическое | Сортировка слиянием |
| O(n²)            | Квадратичное      | Вложенные циклы        |
| O(2ⁿ)            | Экспоненциальное  | Рекурсивные задачи     |

## Основные примеры с объяснением

### 1. O(1) — Константное время

**Описание**: Время выполнения алгоритма **не зависит от размера входных данных**.

**Пример на Dart:**

```dart
int getElement(List<int> list, int index) {
  return list[index]; // Всегда выполняется за одно действие
}
```

Независимо от того, сколько элементов в списке, мы получаем элемент за один шаг.

---

### 2. O(log n) — Логарифмическое время

**Описание**: Количество шагов растёт логарифмически по размеру входных данных. Обычно используется при **разделении данных на части** (например, в бинарном поиске).

**Пример: Бинарный поиск**

```dart
int binarySearch(List<int> list, int target) {
  int left = 0;
  int right = list.length - 1;

  while (left <= right) {
    int mid = (left + right) ~/ 2;
    if (list[mid] == target) return mid;
    if (list[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }

  return -1; // Не найдено
}
```

**Примечание**: В каждом шаге мы сокращаем количество возможных вариантов вдвое. Поэтому, если у нас есть 1024 элемента, нам нужно максимум **10 шагов** (log₂(1024) = 10).

---

### 3. O(n) — Линейное время

**Описание**: Время выполнения растёт **прямо пропорционально количеству элементов**.

**Пример: Поиск элемента в списке**

```dart
bool contains(List<int> list, int target) {
  for (int i = 0; i < list.length; i++) {
    if (list[i] == target) return true;
  }
  return false;
}
```

Если список содержит 100 элементов, в худшем случае мы проверим все 100. Следовательно — **O(n)**.

---

### 4. O(n log n) — Линейно-логарифмическое время

**Описание**: Часто встречается при **эффективных алгоритмах сортировки**, таких как **merge sort** или **heap sort**.

**Пример: Сортировка с использованием Dart**

```dart
List<int> mergeSort(List<int> list) {
  if (list.length <= 1) return list;

  int mid = list.length ~/ 2;
  List<int> left = mergeSort(list.sublist(0, mid));
  List<int> right = mergeSort(list.sublist(mid));

  return merge(left, right);
}

List<int> merge(List<int> left, List<int> right) {
  List<int> result = [];
  int i = 0, j = 0;

  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) {
      result.add(left[i++]);
    } else {
      result.add(right[j++]);
    }
  }

  result.addAll(left.sublist(i));
  result.addAll(right.sublist(j));

  return result;
}
```

**Сложность**: O(n log n) — основное время уходит на рекурсию и объединение.

---

### 5. O(n²) — Квадратичное время

**Описание**: Алгоритм выполняет вложенные операции, зависящие от количества элементов.

**Пример: Поиск пары чисел, сумма которых равна целевому значению**

```dart
bool hasPairWithSum(List<int> list, int target) {
  for (int i = 0; i < list.length; i++) {
    for (int j = i + 1; j < list.length; j++) {
      if (list[i] + list[j] == target) return true;
    }
  }
  return false;
}
```

В худшем случае, если у нас 100 элементов, мы проверим около **100 × 100 = 10,000 пар** — это O(n²).

---

### 6. O(2ⁿ) — Экспоненциальное время

**Описание**: Сложность растёт экспоненциально — очень медленно при увеличении размера данных.

**Пример: Рекурсивный подсчёт Фибоначчи**

```dart
int fibonacci(int n) {
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}
```

Для `fibonacci(5)` вызывается около **15 раз** — это уже экспоненциальный рост. Это неэффективно, и его можно оптимизировать с помощью мемоизации.

## Как анализировать сложность алгоритмов?

### Шаги:

1. **Определите количество шагов**, которые выполняет ваш алгоритм.
2. **Сосредоточьтесь на доминирующем члене** — то есть том, который растёт быстрее всего.
3. **Игнорируйте константы и меньшие члены**, потому что при больших n они становятся незначительными.

### Пример:

```dart
for (int i = 0; i < n; i++) {
  for (int j = 0; j < n; j++) {
    print(i * j);
  }
}
```

Здесь два цикла — каждый выполняется `n` раз. Общее количество операций: `n × n = n²`. Следовательно, сложность — **O(n²)**.
