# Лекция: Dart. Sound Null Safety

Привет, будущий Flutter-разработчик! Сегодня мы поговорим о **Sound Null Safety** — одной из самых важных и значимых особенностей в языке Dart. Это изменение внесло огромный вклад в улучшение безопасности кода, помогая избежать множества ошибок, связанных с `null` значениями.

---

## 1. Что такое nullable типы?

В старых версиях Dart (до версии 2.12) все переменные могли содержать значение `null`, что приводило к множеству проблем во время выполнения, таких как `NullPointerException`.

С появлением **Sound Null Safety**, Dart стал строго типизированным языком. Теперь мы можем явно указать, может ли переменная быть `null` или нет.

### Основные особенности:

- **Нулевые типы (nullable types)**: переменная может быть равна `null`.
  - Пример: `String? name;` — переменная `name` может быть `null`.
  
- **Не нулевые типы (non-nullable types)**: переменная не может быть `null`.
  - Пример: `String name;` — переменная `name` **обязана** содержать строку.

### Пример:

```dart
void main() {
  // Не нулевой тип
  String name = "Анна";

  // Nullable тип
  String? email;

  // Ошибка компиляции, если не инициализировано
  // print(name.length); // OK

  // Если мы попробуем использовать nullable тип без проверки:
  // print(email.length); // ОШИБКА: Нельзя вызвать .length у null

  // Для безопасного использования nullable типа нужно проверить на null
}
```

> ⚠️ Важно: если переменная не инициализирована, но объявлена как `String?`, то она **по умолчанию равна null**.

## 2. Проверка на null

В Dart есть несколько способов проверить, является ли переменная `null` или нет. Это необходимо, чтобы избежать ошибок при работе с nullable типами.

### Способ 1: Условный оператор `if`

```dart
String? email;

if (email != null) {
  print("Email: ${email.toLowerCase()}");
} else {
  print("Email не задан");
}
```

### Способ 2: Оператор `??` (null-ориентированный оператор)

Позволяет указать значение по умолчанию, если переменная равна `null`.

```dart
String? name;
String safeName = name ?? "Неизвестный пользователь";
print(safeName); // Неизвестный пользователь
```

### Способ 3: Оператор `?.` (оператор безопасного вызова)

Используется для безопасного вызова методов или свойств, если объект не равен `null`.

```dart
String? name;

// Безопасный вызов
print(name?.length); // null

name = "Алексей";
print(name?.length); // 6
```

### Способ 4: Оператор `!` (предполагающий не-null)

Если вы уверены, что переменная не равна `null`, можно использовать оператор `!` для принудительного приведения к типу без `null`.

```dart
String? name = "Мария";

// Явно говорим: "Да, это не null"
print(name!.length); // 5

// Но если name == null, будет ошибка времени выполнения!
```

> 🚨 Осторожно с `!`. Используйте только тогда, когда уверены, что значение не равно `null`.

## 3. Модификатор `late` и ленивая инициализация

В некоторых случаях мы хотим объявить переменную **до её инициализации**, но использовать её позже — например, в `initState()` Flutter-виджета.

Для таких случаев есть ключевое слово `late`.

### Что такое `late`?

Ключевое слово `late` говорит компилятору: *"Я инициализирую эту переменную позже, но уверен, что она будет проинициализирована до использования"*.

```dart
class MyWidget extends StatefulWidget {
  @override
  State<MyWidget> createState() => _MyWidgetState();
}

class _MyWidgetState extends State<MyWidget> {
  late String apiUrl; // Объявлено, но не инициализировано

  @override
  void initState() {
    super.initState();
    apiUrl = "https://api.example.com/data"; // Инициализация здесь
  }

  @override
  Widget build(BuildContext context) {
    print(apiUrl); // Безопасно, потому что инициализировано до использования
    return Container();
  }
}
```

### Основные моменты:

- Переменная **должна быть проинициализирована** до первого использования.
- Если вы попытаетесь использовать `late` переменную до её инициализации — получите ошибку времени выполнения.
- `late` можно использовать только с не-nullable типами (например, `String`, `int`, `Widget`, и т.п.).

### Пример с `late` в Flutter:

```dart
class UserScreen extends StatefulWidget {
  @override
  _UserScreenState createState() => _UserScreenState();
}

class _UserScreenState extends State<UserScreen> {
  late User currentUser; // Не будет инициализировано сразу

  @override
  void initState() {
    super.initState();
    fetchCurrentUser(); // Асинхронная функция
  }

  Future<void> fetchCurrentUser() async {
    currentUser = await fetchUserFromAPI(); // Здесь происходит инициализация
    setState(() {}); // Обновляем UI после получения данных
  }

  @override
  Widget build(BuildContext context) {
    return Text(currentUser.name); // Безопасно, потому что currentUser уже проинициализирован
  }
}
```

## Практическое задание

### Задача: Создать простой Flutter-виджет с использованием null safety

1. Создайте `StatefulWidget` с названием `UserCard`.
2. В состоянии укажите:
   - `late String fullName`;
   - `String? email;`
   - `int? age;`
3. Используйте `initState()` для инициализации `fullName`.
4. Добавьте проверку на `null` при выводе информации.
5. Реализуйте метод, который будет выводить данные пользователя в `Text`.

Пример:
```dart
class UserCard extends StatefulWidget {
  @override
  _UserCardState createState() => _UserCardState();
}

class _UserCardState extends State<UserCard> {
  late String fullName;
  String? email;
  int? age;

  @override
  void initState() {
    super.initState();
    fullName = "Иван Петров";
    email = "ivan@example.com";
    age = 30;
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Text("Имя: $fullName"),
        Text("Email: ${email ?? 'Не указан'}"),
        Text("Возраст: ${age?.toString() ?? 'Не указан'}"),
      ],
    );
  }
}
```
