# Лекция: Dart. Обработка ошибок

Привет, будущий Flutter-разработчик! Сегодня мы поговорим о **обработке ошибок** в языке Dart — одной из ключевых тем, которую нужно хорошо понимать для разработки стабильных и надежных мобильных приложений.

Понимание того, как правильно обрабатывать ошибки, — это не просто полезный навык, а **необходимое условие** для создания качественного кода. Особенно если ты работаешь с асинхронными операциями или взаимодействуешь с внешними API.

---

## 🔹 1. Отличие Exception и Error

В Dart есть два основных типа исключений: **Exception** и **Error**.

### 📌 Exception

**Exception** — это класс, который используется для обработки **ожидаемых** или **предсказуемых** ошибок. Например:

- Неправильный формат данных
- Ошибка ввода пользователя
- Попытка доступа к несуществующему файлу

Примеры `Exception`:
```dart
throw FormatException("Неверный формат даты");
```

### 📌 Error

**Error** — это более серьезная ошибка, которая обычно указывает на **проблему в самой системе**, например:

- Переполнение стека (`StackOverflowError`)
- Ошибка времени выполнения (`OutOfMemoryError`)
- Непредвиденные ошибки, которые могут привести к крашу приложения

Примеры `Error`:
```dart
throw OutOfMemoryError("Недостаточно памяти");
```

> Важно: **Все `Exception` — это `Object`, но не все `Error` являются `Exception`**.

### 🧠 Какой тип использовать?

| Тип       | Пример использования                            |
|-----------|-------------------------------------------------|
| `Exception` | Когда ты ожидаем, что что-то может пойти не так, например, неверный ввод от пользователя |
| `Error`     | Когда происходит критическая ошибка, которую трудно предсказать, например, сбой в памяти |

## 🔹 2. Try-catch-finally

### 🧱 Синтаксис:

```dart
try {
  // Блок кода, где может произойти ошибка
} catch (e) {
  // Обработка ошибки
} finally {
  // Этот блок выполняется всегда, независимо от того, была ли ошибка
}
```

### 🧪 Пример с Dart:

```dart
void main() {
  try {
    int result = 10 ~/ 0; // Ошибка: деление на ноль
    print("Результат: $result");
  } catch (e) {
    print("Произошла ошибка: $e");
  } finally {
    print("Этот блок выполнится всегда");
  }
}
```

### 🧠 Как работает `catch`?

В Dart можно ловить несколько типов исключений:

```dart
try {
  // ...
} catch (e, stackTrace) {
  if (e is FormatException) {
    print("Ошибка формата данных");
  } else if (e is IOException) {
    print("Ошибка ввода-вывода");
  } else {
    print("Неизвестная ошибка: $e");
  }
}
```

> Обрати внимание: `stackTrace` — это необязательный параметр, который показывает стек вызовов при возникновении ошибки.

## 🔹 3. Обработка ошибок в асинхронных функциях

### 🧠 Что такое асинхронная функция?

Функции в Dart могут быть **асинхронными**, если они выполняются не сразу, а в будущем (например, при работе с сетью или файлами).

Пример асинхронной функции:

```dart
Future<String> fetchUserData() async {
  // Симулируем асинхронную операцию
  await Future.delayed(Duration(seconds: 2));
  return "Данные пользователя";
}
```

### 🧠 Обработка ошибок в `Future`:

Есть два способа обработки ошибок в `Future`:

#### ✅ Способ 1: `.catchError()`

```dart
fetchUserData().then((value) {
  print(value);
}).catchError((error) {
  print("Ошибка при получении данных: $error");
});
```

#### ✅ Способ 2: `try-catch` внутри `async/await`

```dart
void main() async {
  try {
    String data = await fetchUserData();
    print(data);
  } catch (e) {
    print("Ошибка: $e");
  }
}
```

> ⚠️ Обрати внимание: если ты используешь `async/await`, то **внутри `try-catch`** можно обрабатывать ошибки так же, как и в синхронном коде.

### 🧪 Пример с реальной ошибкой:

```dart
Future<String> fetchUserDataFromAPI(String userId) async {
  if (userId.isEmpty) {
    throw FormatException("ID пользователя не может быть пустым");
  }

  // Симуляция сетевого запроса
  await Future.delayed(Duration(seconds: 1));
  
  if (userId == "invalid") {
    throw SocketException("Нет подключения к интернету");
  }

  return "Данные пользователя с ID: $userId";
}

void main() async {
  try {
    String data = await fetchUserDataFromAPI("");
  } catch (e) {
    print("Ошибка: $e");
  }
}
```

## 🔹 4. Примеры в Flutter

В Flutter мы часто работаем с асинхронными функциями — например, при загрузке данных из API.

```dart
class UserService {
  static Future<Map<String, dynamic>> fetchUser(int userId) async {
    try {
      final response = await http.get(Uri.parse('https://api.example.com/user/$userId'));
      
      if (response.statusCode == 200) {
        return json.decode(response.body);
      } else {
        throw HttpException("Ошибка HTTP: ${response.statusCode}");
      }
    } catch (e) {
      print("Ошибка при загрузке пользователя: $e");
      rethrow; // Переброс ошибки, если нужно передать её выше
    }
  }
}
```

Использование в `Widget`:

```dart
class UserScreen extends StatefulWidget {
  @override
  _UserScreenState createState() => _UserScreenState();
}

class _UserScreenState extends State<UserScreen> {
  Future<Map<String, dynamic>>? _userDataFuture;

  void _loadUserData(int userId) {
    setState(() {
      _userDataFuture = UserService.fetchUser(userId);
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text("Пользователь")),
      body: FutureBuilder<Map<String, dynamic>>(
        future: _userDataFuture,
        builder: (context, snapshot) {
          if (snapshot.connectionState == ConnectionState.waiting) {
            return Center(child: CircularProgressIndicator());
          } else if (snapshot.hasError) {
            return Center(child: Text("Ошибка: ${snapshot.error}"));
          } else if (snapshot.hasData) {
            return Text(snapshot.data!['name']);
          } else {
            return Center(child: Text("Данные отсутствуют"));
          }
        },
      ),
    );
  }
}
```

## 🧠 Важные моменты при обработке ошибок:

1. **Не игнорируй ошибки** — даже если они кажутся незначительными.
2. **Используй `try-catch` в асинхронном коде**, особенно при работе с API.
3. **Передавай ошибки дальше**, если это необходимо (например, `rethrow`).
4. **Всегда проверяй типы исключений** — это делает код более надежным.
