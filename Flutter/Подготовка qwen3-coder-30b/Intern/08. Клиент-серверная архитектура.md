# Лекция: Клиент-серверная архитектура

## Введение

Клиент-серверная архитектура — одна из самых распространённых и фундаментальных моделей взаимодействия в современных информационных системах, особенно в мобильной разработке. Эта модель лежит в основе большинства приложений, которые мы используем: от социальных сетей до банковских сервисов.

В данной лекции вы узнаете:

- Что такое клиент и сервер
- Как они взаимодействуют друг с другом
- Примеры таких взаимодействий в контексте Flutter и Dart
- Основные принципы работы с API

---

## 1. Основные понятия: Клиент и Сервер

### Что такое клиент?

Клиент — это программа или устройство, которое **запрашивает** данные или услуги у сервера. В мире мобильной разработки клиентом обычно является **мобильное приложение**, например, приложение на Flutter.

Пример:  
Если вы используете приложение «Погода», чтобы узнать температуру в Москве, ваш телефон — это клиент. Он отправляет запрос к серверу (например, OpenWeather API), который отвечает вам данными о погоде.

### Что такое сервер?

Сервер — это программа или устройство, которое **предоставляет** данные или услуги клиенту. Сервер слушает запросы от клиентов и обрабатывает их, возвращая ответ.

Пример:  
Когда ваше Flutter-приложение запрашивает информацию о погоде, сервер (например, API OpenWeather) принимает запрос, обращается к базе данных или другим источникам, формирует ответ и отправляет его обратно клиенту.

### Взаимодействие между клиентом и сервером

Клиент и сервер взаимодействуют по определённым протоколам, чаще всего — это HTTP/HTTPS. Клиент отправляет **запрос**, а сервер возвращает **ответ**.

Пример запроса:
```
GET /api/weather?city=Moscow
```

Пример ответа:
```json
{
  "temperature": 15,
  "humidity": 60,
  "wind_speed": 3.2
}
```

## 2. Роли клиента и сервера в мобильной разработке

В мобильных приложениях клиент — это само приложение (Flutter), а сервер — это внешний API или backend-сервис, например:

- REST API
- GraphQL API
- Firebase
- Бэкенд на Node.js, Django, Spring Boot и т.д.

### Пример: Работа с REST API в Flutter

Допустим, вы хотите реализовать функционал загрузки списка пользователей через REST API.

#### 1. Определение модели данных:

```dart
class User {
  final int id;
  final String name;
  final String email;

  User({required this.id, required this.name, required this.email});

  factory User.fromJson(Map<String, dynamic> json) {
    return User(
      id: json['id'],
      name: json['name'],
      email: json['email'],
    );
  }
}
```

#### 2. Создание сервиса для работы с API:

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

class UserService {
  static const String baseUrl = 'https://jsonplaceholder.typicode.com';

  static Future<List<User>> fetchUsers() async {
    final response = await http.get(Uri.parse('$baseUrl/users'));

    if (response.statusCode == 200) {
      List<dynamic> data = json.decode(response.body);
      return data.map((json) => User.fromJson(json)).toList();
    } else {
      throw Exception('Failed to load users');
    }
  }
}
```

#### 3. Использование сервиса в Flutter-приложении:

```dart
class UsersPage extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text("Пользователи")),
      body: FutureBuilder<List<User>>(
        future: UserService.fetchUsers(),
        builder: (context, snapshot) {
          if (snapshot.hasData) {
            return ListView.builder(
              itemCount: snapshot.data!.length,
              itemBuilder: (context, index) {
                final user = snapshot.data![index];
                return ListTile(
                  title: Text(user.name),
                  subtitle: Text(user.email),
                );
              },
            );
          } else if (snapshot.hasError) {
            return Center(child: Text("Ошибка: ${snapshot.error}"));
          } else {
            return Center(child: CircularProgressIndicator());
          }
        },
      ),
    );
  }
}
```

## 3. Примеры взаимодействия клиента и сервера

### Пример 1: Запрос данных с сервера (GET)

Клиент запрашивает данные (например, список постов):

```dart
final response = await http.get(Uri.parse('https://jsonplaceholder.typicode.com/posts'));
```

Сервер отвечает JSON-данными:

```json
[
  {
    "id": 1,
    "title": "Post title",
    "body": "Post body"
  }
]
```

### Пример 2: Отправка данных на сервер (POST)

Клиент создаёт новый пост:

```dart
final response = await http.post(
  Uri.parse('https://jsonplaceholder.typicode.com/posts'),
  headers: {'Content-Type': 'application/json'},
  body: jsonEncode({
    'title': 'New Post',
    'body': 'Post content',
    'userId': 1,
  }),
);
```

Сервер обрабатывает и возвращает созданный объект:

```json
{
  "id": 101,
  "title": "New Post",
  "body": "Post content",
  "userId": 1
}
```

### Пример 3: Использование Firebase как серверной части

Если вы используете Firebase, то:

- Клиент — это Flutter-приложение
- Сервер — это Firebase (Firestore, Realtime Database, Auth и т.д.)

Пример получения данных из Firestore:

```dart
import 'package:cloud_firestore/cloud_firestore.dart';

final db = FirebaseFirestore.instance;

Future<void> fetchPosts() async {
  final snapshot = await db.collection('posts').get();
  for (var doc in snapshot.docs) {
    print(doc.data());
  }
}
```

## 4. Протоколы взаимодействия

### HTTP/HTTPS

- Самый распространённый способ взаимодействия между клиентом и сервером.
- Клиент отправляет запрос (GET, POST, PUT, DELETE), сервер отвечает кодом состояния и данными.

Пример:  
Клиент делает GET-запрос к `/api/products`, сервер возвращает список товаров.

### WebSocket

Используется для **реального времени** взаимодействия, например, чаты, игры, уведомления.

Пример с `web_socket_channel`:

```dart
import 'package:web_socket_channel/web_socket_channel.dart';

final channel = WebSocketChannel.connect(
  Uri.parse('ws://localhost:8080'),
);

channel.stream.listen((message) {
  print(message);
});
```

### 1. Браузерный клиент

Используется в веб-приложениях, но в Flutter мы чаще работаем с мобильными клиентами.

### 2. Мобильный клиент (Flutter)

Это наше основное внимание: Flutter-приложение взаимодействует с сервером через API.

### 3. Desktop клиент

Также может быть частью архитектуры, например, приложение на Flutter Desktop.

## 6. Какие данные передаются между клиентом и сервером?

- **Запрос**: содержит метод (GET, POST), URL, заголовки, тело запроса.
- **Ответ**: код состояния HTTP, заголовки, тело ответа (обычно JSON).
