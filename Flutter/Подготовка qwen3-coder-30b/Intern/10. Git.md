# Лекция по Git для Flutter разработчика уровня Intern

## Введение в Git

Git — это распределённая система контроля версий, которая позволяет отслеживать изменения в файлах и координировать работу над проектом между несколькими разработчиками. В мире мобильной разработки, особенно в Flutter, Git играет ключевую роль, так как он помогает управлять кодом, вести историю изменений, решать конфликты и организовать командную работу.

Для Flutter-разработчика знание Git — это не просто плюс, а необходимость. При разработке мобильных приложений вы будете работать с проектами, которые могут содержать сотни файлов, включая код Dart, ресурсы, манифесты и конфигурационные файлы. Git помогает управлять этими изменениями и делает процесс разработки более стабильным и предсказуемым.

---

## 1. Ветви (Branches)

### Что такое ветвь?

Ветвь (branch) — это отдельная линия разработки в Git. Каждая ветвь содержит историю изменений, которая может отличаться от других ветвей. Это позволяет разработчикам работать над разными функциями или исправлениями одновременно, не мешая друг другу.

Важно понимать, что ветви — это не просто "копии" проекта. Они представляют собой ссылки на определённые коммиты (commit), и каждая ветвь может развиваться независимо.

### Как создать новую ветвь?

В командной строке:

```bash
git branch <имя-ветки>
```

Пример:
```bash
git branch feature-login-screen
```

Эта команда создаёт новую ветвь `feature-login-screen`, но не переключает вас на неё.

Чтобы сразу переключиться на новую ветку:

```bash
git checkout -b <имя-ветки>
```

Пример:
```bash
git checkout -b feature-login-screen
```

В Flutter-проекте это может быть полезно, например, если вы работаете над экраном авторизации. Создавая отдельную ветку, вы изолируете изменения, которые могут быть неприемлемы до завершения разработки.

### Как посмотреть список ветвей?

```bash
git branch -a
```

Эта команда покажет все локальные и удалённые ветви.

Пример вывода:
```
* main
  feature-login-screen
  develop
```

Здесь `main` — это текущая ветвь (отмечена звёздочкой).

### Переключение между ветвями

Для переключения между ветвями используется команда:

```bash
git checkout <имя-ветки>
```

Пример:
```bash
git checkout main
```

Также можно использовать команду `switch` (доступна с Git 2.23):

```bash
git switch main
```

Важно: перед переключением убедитесь, что все изменения в текущей ветке сохранены или закоммичены. Если есть незакоммиченные изменения, Git не даст вам переключиться на другую ветку.

## 2. Commit

### Что такое коммит?

Коммит (commit) — это фиксация изменений в Git. При каждом коммите вы создаёте точку в истории проекта, где содержатся все изменения, внесённые с момента последнего коммита.

Каждый коммит имеет уникальный идентификатор (хэш), автора, дату и сообщение (commit message), которое описывает, что было изменено.

### Как сделать коммит?

1. Сначала добавьте файлы в индекс:

```bash
git add .
```

или конкретные файлы:

```bash
git add lib/main.dart
```

2. Затем создайте коммит:

```bash
git commit -m "Добавлен экран авторизации"
```

Коммиты должны быть осмысленными и описательными. Лучше использовать глаголы в настоящем времени, например: `Добавить`, `Исправить`, `Удалить`, `Обновить`.

### Пример коммита для Flutter-проекта:

```bash
git add lib/screens/login_screen.dart
git commit -m "Создан экран авторизации с полями ввода и кнопкой входа"
```

Важно: перед каждым коммитом убедитесь, что ваш код работает корректно и не содержит ошибок.

## 3. Push

### Что такое Push?

Push — это отправка ваших локальных коммитов на удалённый репозиторий (например, GitHub или GitLab). После push, ваши изменения становятся доступны другим разработчикам.

### Как сделать push?

```bash
git push origin <имя-ветки>
```

Пример:
```bash
git push origin feature-login-screen
```

Если это первая попытка отправить ветку, и она не существует на удалённом репозитории:

```bash
git push -u origin feature-login-screen
```

Флаг `-u` устанавливает связь между локальной и удалённой веткой, чтобы в дальнейшем можно было просто использовать `git push`.

### Важно:
- Убедитесь, что у вас есть права на запись в репозиторий.
- Если кто-то уже обновил удалённую ветку, вы можете столкнуться с конфликтом. В таком случае нужно выполнить `git pull` перед `push`.

## 4. Pull и Fetch

### Что такое Pull?

Pull — это комбинация команд `fetch` и `merge`. Она получает изменения из удалённого репозитория и автоматически объединяет их с текущей локальной веткой.

Пример:

```bash
git pull origin main
```

Эта команда получает последние изменения из ветки `main` на удалённом репозитории и объединяет их с вашей локальной веткой `main`.

### Что такое Fetch?

Fetch — это команда, которая загружает изменения из удалённого репозитория, но **не объединяет** их с вашей локальной веткой. Это позволяет вам увидеть, что было изменено, без автоматического слияния.

Пример:

```bash
git fetch origin
```

После этого можно посмотреть, какие изменения были сделаны:

```bash
git log --oneline --graph --all
```

Или просто посмотреть, какие ветки обновились:

```bash
git branch -r
```

### Когда использовать Pull, а когда Fetch?

- Используйте `git pull`, если вы уверены, что ваши локальные изменения не конфликтуют с изменениями из удалённого репозитория.
- Используйте `git fetch`, если хотите увидеть изменения, но не сразу объединять их. Это полезно для анализа и принятия решения о том, как правильно объединить код.

## Практическое задание

Вам нужно создать Flutter-проект (или использовать уже существующий), а затем выполнить следующие шаги:

1. Создайте новую ветку `feature-user-profile`.
2. Добавьте новый экран `UserProfileScreen` в проект.
3. Сделайте коммит с сообщением "Добавлен экран профиля пользователя".
4. Отправьте изменения на удалённый репозиторий.
5. Переключитесь на ветку `main`, выполните `git pull`, чтобы получить последние изменения.
6. Вернитесь к ветке `feature-user-profile` и убедитесь, что вы не потеряли свои изменения.
