## 1. Основные концепции реляционных БД

### Что такое реляционная база данных?

Реляционная база данных (RDBMS — Relational Database Management System) — это способ хранения и управления данными, основанный на таблицах. Вся информация представлена в виде строк и столбцов, как в обычной таблице Excel.

Пример:
| ID | Имя     | Возраст |
|----|---------|---------|
| 1  | Иван    | 25      |
| 2  | Мария   | 30      |

В такой таблице:
- Каждая строка — это **запись** (или **tuple**).
- Каждый столбец — это **поле** (или **атрибут**).

### Основные свойства реляционных БД:

1. Данные хранятся в виде таблиц.
2. Каждая таблица имеет **уникальное имя**.
3. Столбцы имеют определённый тип данных (строка, число, дата и т.д.).
4. Таблицы связаны между собой через **ключи**.

## 2. Понятие нормализации

### Что такое нормализация?

Нормализация — это процесс структурирования данных в БД с целью минимизации дублирования и улучшения целостности.

Цель нормализации:
- Уменьшить повторяющиеся данные.
- Обеспечить целостность данных.
- Сделать БД более гибкой при изменении данных.

### Пример:

Представим, что у нас есть таблица "Заказы":

| ЗаказID | Имя клиента | Город     | Телефон   |
|---------|-------------|-----------|-----------|
| 1       | Иван        | Москва    | +7123...  |
| 2       | Иван        | Москва    | +7123...  |
| 3       | Мария       | Санкт-Петербург | +7456... |

Видно, что данные о клиенте дублируются. Это плохо. Нужно нормализовать:

#### Таблица "Клиенты":

| ClientID | Имя     | Город             |
|----------|---------|-------------------|
| 1        | Иван    | Москва            |
| 2        | Мария   | Санкт-Петербург   |

#### Таблица "Заказы":

| OrderID | ClientID | Product |
|---------|----------|---------|
| 1       | 1        | Ноутбук |
| 2       | 1        | Мышка   |
| 3       | 2        | Клавиатура |

Теперь данные не дублируются, и если нужно изменить телефон клиента, мы меняем только одну запись.

## 3. Primary Key

### Что такое Primary Key?

**Primary Key (PK)** — уникальный идентификатор записи в таблице. Он должен быть:
- **Уникальным** (никакие две записи не могут иметь одинаковый PK)
- **Не NULL** (всегда должен быть заполнен)

Пример:

| ID | Имя     |
|----|---------|
| 1  | Иван    |
| 2  | Мария   |

Здесь `ID` — Primary Key.

В Flutter приложениях часто используется `int` или `String` как PK, например:

```dart
class User {
  final int id;
  final String name;

  User({required this.id, required this.name});
}
```

## 4. SQL: SELECT, INSERT, UPDATE, DELETE

SQL — это язык запросов к БД. Давай рассмотрим основные операции.

### SELECT (чтение)

Чтобы получить данные из таблицы:

```sql
SELECT * FROM users;
```

Получим все строки и столбцы из таблицы `users`.

```sql
SELECT name, age FROM users WHERE age > 20;
```

Только поля `name` и `age`, где возраст больше 20.

### INSERT (вставка)

Добавить новую запись:

```sql
INSERT INTO users (name, age) VALUES ('Анна', 28);
```

### UPDATE (обновление)

Изменить данные:

```sql
UPDATE users SET age = 29 WHERE name = 'Анна';
```

### DELETE (удаление)

Удалить запись:

```sql
DELETE FROM users WHERE name = 'Анна';
```

## 5. SQL: CREATE TABLE, DROP TABLE, ALTER TABLE

### CREATE TABLE

Создание таблицы:

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    age INTEGER
);
```

Здесь:
- `id` — первичный ключ, автоматически увеличивается (`AUTOINCREMENT`)
- `name` — текстовое поле, обязательное (`NOT NULL`)
- `age` — целое число

### DROP TABLE

Удаление таблицы:

```sql
DROP TABLE users;
```

> ⚠️ Будь осторожен! Это удалит всё содержимое таблицы.

### ALTER TABLE

Добавить или изменить структуру таблицы:

```sql
ALTER TABLE users ADD COLUMN email TEXT;
```

Добавит новый столбец `email`.

## 6. JOIN-запросы (LEFT, RIGHT, INNER)

JOIN — это способ объединить данные из двух или более таблиц на основе общего поля.

### INNER JOIN

Возвращает только строки, которые есть в обеих таблицах:

```sql
SELECT users.name, orders.product
FROM users
INNER JOIN orders ON users.id = orders.user_id;
```

### LEFT JOIN

Возвращает все строки из левой таблицы и совпадающие из правой:

```sql
SELECT users.name, orders.product
FROM users
LEFT JOIN orders ON users.id = orders.user_id;
```

### RIGHT JOIN

Возвращает все строки из правой таблицы и совпадающие из левой (редко используется).

## 7. ERD (Entity Relationship Diagram) — Диаграммы отношений

### Что такое ERD?

**ERD** — это визуальное представление структуры базы данных: сущностей, их атрибутов и связей между ними.

### Пример:

У нас есть две таблицы:
- `Users` (пользователи)
- `Orders` (заказы)

Связь: один пользователь может сделать много заказов → **один ко многим**.

В ERD это выглядит так:

```
[Users] 1 ——< [Orders]
```

То есть, у одной записи в `Users` может быть много записей в `Orders`.

### Почему нужны ERD?

- Помогают планировать структуру БД.
- Упрощают понимание связей между таблицами.
- Используются при проектировании приложений.

## Примеры на Flutter и SQLite

В Flutter для работы с локальной БД часто используется пакет [sqflite](https://pub.dev/packages/sqflite).

### Создание таблицы:

```dart
import 'package:sqflite/sqflite.dart';
import 'package:path/path.dart';

Future<Database> initDB() async {
  final dbPath = await getDatabasesPath();
  final path = join(dbPath, 'users.db');

  return await openDatabase(
    path,
    version: 1,
    onCreate: (db, version) async {
      await db.execute('''
        CREATE TABLE users (
          id INTEGER PRIMARY KEY AUTOINCREMENT,
          name TEXT NOT NULL,
          age INTEGER
        )
      ''');
    },
  );
}
```

### Вставка данных:

```dart
Future<void> insertUser(Database db, String name, int age) async {
  await db.insert('users', {
    'name': name,
    'age': age,
  });
}
```

### Выборка данных:

```dart
Future<List<Map<String, dynamic>>> getUsers() async {
  final db = await initDB();
  return await db.query('users');
}
```
