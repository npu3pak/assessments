# Принцип DRY в Flutter разработке

## Введение

Добро пожаловать в лекцию по одному из фундаментальных принципов программирования — **DRY (Don't Repeat Yourself)**. Этот принцип не только важен для мобильной разработки, но и является основой хорошего кода в любой области программирования.

В этой лекции мы подробно рассмотрим:

- Что такое DRY
- Почему этот принцип так важен
- Как его применять на практике в Flutter-проектах
- Когда и почему не стоит следовать DRY
- Практические примеры на Dart/Flutter

---

## Что такое DRY (Don't Repeat Yourself)?

**DRY — это аббревиатура от "Don't Repeat Yourself"**, что переводится как **«Не повторяйся»**. Это один из ключевых принципов программирования, который гласит:

> **Если вы повторяете один и тот же код в нескольких местах, это может быть признаком плохого дизайна.**

Принцип DRY подразумевает, что каждый фрагмент знаний должен иметь единственное, точное и авторитетное представление в системе.

### Цель DRY

Цель этого принципа — уменьшить дублирование кода, чтобы:

1. Упростить поддержку и изменение
2. Снизить риск ошибок
3. Повысить читаемость
4. Сделать код более модульным

---

## Почему принцип DRY важен?

### 1. **Упрощает поддержку**

Если вы обнаруживаете баг в одном месте, то его нужно исправлять только в одном месте — там, где он определён.

Пример: представьте, что вы используете один и тот же стиль для кнопок во всём приложении. Если вы захотите изменить цвет фона кнопки, вам нужно будет обновить только одно место.

### 2. **Уменьшает риск ошибок**

Если у вас много дублирующегося кода, и вы забудете обновить его во всех местах, возникнут непредсказуемые ошибки.

### 3. **Повышает читаемость и понятность**

Когда логика вынесена в отдельные функции или классы, код становится легче воспринимать.

### 4. **Создаёт более модульную архитектуру**

Если вы повторяете одни и те же действия — это сигнал к тому, что нужно вынести их в отдельные компоненты.

## Как применять DRY в Flutter?

В Flutter есть множество способов использовать DRY:

### 1. **Использование виджетов-компонентов**

Один из самых распространённых способов — создавать пользовательские виджеты, которые можно переиспользовать.

```dart
// Плохо: дублирование кода
class MyHomePage extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Page 1')),
      body: Column(
        children: [
          Text('Hello'),
          ElevatedButton(
            onPressed: () {},
            child: Text('Click me'),
          ),
        ],
      ),
    );
  }
}

class AnotherPage extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Page 2')),
      body: Column(
        children: [
          Text('Hello'),
          ElevatedButton(
            onPressed: () {},
            child: Text('Click me'),
          ),
        ],
      ),
    );
  }
}
```

**Хорошее решение — вынести общий виджет в отдельный компонент:**

```dart
class CommonWidget extends StatelessWidget {
  final String title;
  final VoidCallback onPressed;

  const CommonWidget({
    Key? key,
    required this.title,
    required this.onPressed,
  }) : super(key: key);

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Text(title),
        ElevatedButton(
          onPressed: onPressed,
          child: Text('Click me'),
        ),
      ],
    );
  }
}

class MyHomePage extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Page 1')),
      body: CommonWidget(
        title: 'Hello',
        onPressed: () {},
      ),
    );
  }
}
```

### 2. **Вынесение логики в отдельные классы или функции**

Если у вас есть повторяющаяся логика работы с данными, выносите её в отдельные методы.

```dart
// Плохо
class HomeScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Column(
        children: [
          Text('User Name: ${getUserData().name}'),
          Text('User Age: ${getUserData().age}'),
          Text('User Email: ${getUserData().email}'),
        ],
      ),
    );
  }
}

// Хорошо
class HomeScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    final user = getUserData();
    return Scaffold(
      body: Column(
        children: [
          Text('User Name: ${user.name}'),
          Text('User Age: ${user.age}'),
          Text('User Email: ${user.email}'),
        ],
      ),
    );
  }
}
```

### 3. **Использование стилей и тем**

Если вы используете одни и те же стили для текста или кнопок — вынесите их в `ThemeData` или создайте отдельный класс со стилями.

```dart
class AppStyles {
  static const TextStyle titleStyle = TextStyle(
    fontSize: 24,
    fontWeight: FontWeight.bold,
  );

  static const TextStyle bodyStyle = TextStyle(
    fontSize: 16,
  );
}

// Использование:
Text('Hello', style: AppStyles.titleStyle)
```

## Когда DRY не следует применять?

Хотя принцип DRY — отличный ориентир, он **не всегда должен быть соблюдён в 100% случаев**.

### 1. **Когда повторение упрощает код и повышает ясность**

Иногда дублирование может быть полезным для читаемости, особенно если два фрагмента кода выполняют разные задачи.

```dart
// Это не обязательно нужно выносить в функцию, если они используются в разных местах и отличаются смыслом:
Text('Welcome to the app');
Text('Please login');

// Эти строки имеют разный смысл, поэтому не стоит их объединять.
```

### 2. **Повторение из-за различий в реализации**

Иногда похожие части кода настолько разные, что их выносить в общую функцию — не улучшает код, а усложняет.

```dart
// Пример: два разных метода с похожими названиями, но разными логиками

void saveUser(User user) {
  // Логика сохранения пользователя
}

void saveProduct(Product product) {
  // Логика сохранения продукта
}
```

### 3. **Повторение ради тестирования**

Иногда при тестировании можно использовать повторяющийся код, чтобы проверить разные сценарии.

## Дополнительные практики DRY в Flutter

### 1. **Использование `const` для статических значений**

Если вы используете один и тот же цвет или размер в разных местах — лучше объявить их как `const`.

```dart
class AppColors {
  static const Color primaryColor = Color(0xFF4CAF50);
  static const Color secondaryColor = Color(0xFF2196F3);
}
```

### 2. **Использование `StatefulWidget` и `StatelessWidget` по назначению**

Не создавайте лишние виджеты, если они не нужны. Используйте `StatelessWidget`, если состояние не меняется.

### 3. **Модульная структура проекта**

Разбивайте проект на модули: `widgets`, `models`, `services`, `utils`. Это помогает избежать дублирования и упрощает поддержку.

## Практическое задание

### Задание:

Создайте простое приложение Flutter с тремя экранами:

1. Главный экран (`HomeScreen`) — отображает список пользователей
2. Экран профиля (`ProfileScreen`) — отображает информацию о пользователе
3. Экран настроек (`SettingsScreen`) — отображает настройки

На всех экранах должен быть один и тот же **заголовок** и **навигационная панель (BottomNavigationBar)**.

### Требования:

- Используйте принцип DRY: вынесите общие части в отдельные виджеты или классы
- Создайте виджет `CustomAppBar` для заголовка
- Создайте виджет `CustomBottomNavBar`
- Виджеты должны принимать параметры через `const` и `required`
