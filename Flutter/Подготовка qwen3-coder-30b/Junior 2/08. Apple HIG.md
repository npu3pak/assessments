## 1. Назначение Human Interface Guidelines (HIG)

**Human Interface Guidelines (HIG)** — это официальная документация от Apple, которая описывает, как создавать интуитивно понятные, эстетичные и доступные интерфейсы для iOS, iPadOS и macOS. HIG не является просто техническим стандартом, а представляет собой философию взаимодействия пользователя с приложением.

### Зачем нужны HIG?

- **Универсальность**: Пользователь уже знает, как работают интерфейсы на iOS. Использование HIG делает ваше приложение "знакомым", что снижает порог вхождения.
- **Доступность**: HIG учитывает потребности людей с ограниченными возможностями (например, использование VoiceOver).
- **Повышение качества UX/UI**: Следование HIG помогает избежать распространенных ошибок и делает интерфейс более привлекательным.
- **Упрощение разработки**: Если вы следуете стандартам, вам легче проектировать, тестировать и поддерживать приложение.

### Важно:
Flutter позволяет создавать приложения, которые выглядят как native iOS или Android. Однако, если вы разрабатываете под **iOS**, важно использовать компоненты, соответствующие HIG, чтобы ваше приложение не казалось "не по-другому" или непривычным.

## 2. Принципы HIG, применимые к iOS

### 1. **Соответствие системе**

iOS имеет строгую иерархию взаимодействия, которая должна соблюдаться при разработке. Это включает:

- Стили, шрифты, цвета
- Навигацию (например, NavigationView, TabBar)
- Взаимодействие с жестами (например, свайпы)

#### Пример (Dart + Flutter):
```dart
class MyHomePage extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: Text('My App'),
      ),
      body: Center(
        child: Text('Hello, iOS!'),
      ),
    );
  }
}
```

В этом примере мы используем стандартный `AppBar`, который соответствует HIG. Он имеет правильную высоту, стиль и поведение.

---

### 2. **Ясность**

Интерфейс должен быть простым и понятным. Пользователь должен сразу понимать, что делает каждая кнопка или элемент управления.

#### Пример:
```dart
ElevatedButton(
  onPressed: () {
    // действие
  },
  child: Text('Подтвердить'),
)
```

Такой элемент говорит пользователю, что при нажатии произойдет какое-то действие. Это соответствует принципу "ясности".

---

### 3. **Глубина**

Интерфейс должен предоставлять возможность доступа к более глубоким уровням информации без перегрузки пользователя. Используйте навигацию, вкладки и карточки.

#### Пример:
```dart
BottomNavigationBar(
  items: [
    BottomNavigationBarItem(icon: Icon(Icons.home), label: 'Главная'),
    BottomNavigationBarItem(icon: Icon(Icons.settings), label: 'Настройки'),
  ],
)
```

---

### 4. **Соответствие ожиданиям**

Пользователь ожидает, что интерфейс будет вести себя так же, как и другие приложения на iOS. Например:

- Стандартные кнопки (например, `ElevatedButton`) должны использовать цвета и стили по умолчанию.
- Всплывающие окна (`AlertDialog`) должны иметь стандартный стиль.

---

### 5. **Доступность**

Все элементы должны быть доступны с помощью VoiceOver, увеличения масштаба и других средств.

#### Пример:
```dart
Text(
  'Заголовок',
  semanticsLabel: 'Заголовок приложения',
)
```

## 3. Принципы HIG, применимые к iPadOS

iPadOS имеет больше возможностей по сравнению с iOS — например, поддержка многозадачности, расширенная навигация и более мощные интерфейсы.

### 1. **Удобство для больших экранов**

iPadOS позволяет использовать больше пространства. Например:

- `SplitView` (для отображения двух экранов одновременно)
- `SlideOver` (появление всплывающего окна)
- Использование `NavigationSplitView`

#### Пример:
```dart
NavigationSplitView(
  column: NavigationRail(
    destinations: [
      NavigationDestination(icon: Icon(Icons.home), label: Text('Главная')),
    ],
  ),
  detail: Text('Детальная информация'),
)
```

---

### 2. **Совместимость с клавиатурой и мышью**

iPadOS поддерживает внешние устройства, поэтому важно:

- Добавлять поддержку `Keyboard` (например, обработка Enter, Tab)
- Использовать `FocusNode` для управления фокусом
- Поддерживать навигацию с помощью стрелок

---

### 3. **Многофункциональность**

iPadOS может работать как полноценный компьютер, поэтому интерфейс должен быть адаптирован под:

- Повторное использование (например, `Share` и `Action` в меню)
- Многозадачность
- Использование док-станции

## 4. Стандартные UI-компоненты, их возможности и решения задач

Вот список стандартных UI-компонентов, которые вы должны использовать в Flutter для создания соответствующего интерфейса под iOS.

### 1. **AppBar**

Создает стандартную шапку экрана.

#### Пример:
```dart
AppBar(
  title: Text('Мой экран'),
  actions: [
    IconButton(icon: Icon(Icons.search), onPressed: () {}),
  ],
)
```

---

### 2. **BottomNavigationBar**

Используется для переключения между основными разделами приложения.

#### Пример:
```dart
BottomNavigationBar(
  items: [
    BottomNavigationBarItem(icon: Icon(Icons.home), label: 'Главная'),
    BottomNavigationBarItem(icon: Icon(Icons.person), label: 'Профиль'),
  ],
)
```

---

### 3. **AlertDialog**

Используется для отображения сообщений и запросов.

#### Пример:
```dart
showDialog(
  context: context,
  builder: (context) => AlertDialog(
    title: Text('Подтвердите действие'),
    content: Text('Вы уверены?'),
    actions: [
      TextButton(onPressed: () => Navigator.of(context).pop(), child: Text('Отмена')),
      TextButton(onPressed: () => Navigator.of(context).pop(), child: Text('OK')),
    ],
  ),
);
```

---

### 4. **TextField**

Используется для ввода данных. Важно использовать `TextInputType` и `keyboardType`.

#### Пример:
```dart
TextField(
  keyboardType: TextInputType.emailAddress,
  decoration: InputDecoration(
    labelText: 'Email',
    prefixIcon: Icon(Icons.email),
  ),
)
```

---

### 5. **ListView**

Используется для отображения списков данных.

#### Пример:
```dart
ListView.builder(
  itemCount: items.length,
  itemBuilder: (context, index) {
    return ListTile(
      title: Text(items[index]),
    );
  },
)
```

---

### 6. **NavigationRail / NavigationSplitView**

Используются для навигации в больших интерфейсах, особенно на iPadOS.

#### Пример:
```dart
NavigationRail(
  destinations: [
    NavigationDestination(icon: Icon(Icons.home), label: Text('Главная')),
    NavigationDestination(icon: Icon(Icons.settings), label: Text('Настройки')),
  ],
)
```
