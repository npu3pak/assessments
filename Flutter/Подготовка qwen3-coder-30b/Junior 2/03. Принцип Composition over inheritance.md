# Лекция: **Принцип Composition over Inheritance**

## Введение

В мире программирования есть два основных способа создания сложных объектов и расширения их функциональности: **наследование (inheritance)** и **композиция (composition)**. Наследование — это когда один класс наследует свойства и методы другого, а композиция — это когда мы строим сложные объекты из более простых, используя их как "строительные блоки".

Сегодня мы рассмотрим **принцип Composition over Inheritance**, который является ключевым элементом современной разработки программного обеспечения. Особенно актуален он в контексте Flutter-разработки, где часто требуется гибкая архитектура и повторное использование кода.

---

## Что такое Composition?

**Композиция** — это подход к созданию объектов путем объединения более простых компонентов. Вместо того чтобы создавать иерархию классов через наследование, вы строите сложные структуры, используя другие объекты как части.

### Пример:

Представим, что у нас есть класс `Car`, который должен иметь возможность ездить, звук, а также иметь двигатель.

Вместо того чтобы наследоваться от `Vehicle` и потом `Engine`, мы можем использовать композицию:

```dart
class Engine {
  void start() => print("Двигатель запущен");
}

class Car {
  final Engine engine;

  Car(this.engine);

  void drive() {
    engine.start();
    print("Машина едет");
  }
}
```

Такой подход позволяет нам легко менять поведение `Car`, просто заменяя `Engine` на другой компонент.

---

## Что такое Inheritance?

**Наследование** — это механизм, при котором один класс получает свойства и методы другого класса. Это позволяет повторно использовать код, но также может привести к жёсткой связи между классами и усложнению системы.

### Пример наследования:

```dart
class Vehicle {
  void start() => print("Транспорт запущен");
}

class Car extends Vehicle {
  void drive() => print("Машина едет");
}
```

Наследование удобно, но имеет свои недостатки — особенно при сложных иерархиях.

---

## Почему Composition лучше?

### 1. **Гибкость**

С композицией вы можете легко менять поведение объекта, заменяя его части:

```dart
class ElectricEngine {
  void start() => print("Электродвигатель запущен");
}

class HybridCar {
  final Engine engine;

  HybridCar(this.engine);

  void drive() {
    engine.start();
    print("Гибридная машина едет");
  }
}
```

Мы можем легко изменить `Engine` на `ElectricEngine`, и всё будет работать без изменения других частей кода.

### 2. **Уменьшение связанности**

Используя композицию, вы уменьшаете зависимость между классами. В отличие от наследования, где вы ограничены одной цепочкой, композиция позволяет вам собирать объекты из разных частей.

### 3. **Проще тестировать**

Компоненты, используемые в композиции, можно тестировать независимо друг от друга.

### 4. **Легче поддерживать и масштабировать**

В больших проектах наследование может привести к сложным иерархиям, которые трудно изменять. Композиция позволяет легко добавлять новые функции без изменения существующих классов.

---

## Недостатки Composition over Inheritance

Хотя композиция имеет множество преимуществ, у неё есть и недостатки:

### 1. **Больше кода**

Композиция может требовать больше строк кода, особенно если вы хотите передавать методы из одной части в другую.

### 2. **Сложнее понять структуру**

В некоторых случаях композиция может быть менее очевидной для новичков, так как не всегда ясно, как объекты взаимодействуют между собой.

---

## Mixins в Dart

**Mixin** — это способ повторного использования кода в Dart, который позволяет добавлять функциональность в классы без использования наследования. Это мощный инструмент для реализации композиции в Dart и Flutter.

### Что такое Mixin?

Mixin — это класс, который не предназначен для самостоятельного использования, а используется как "строительный блок" для других классов.

```dart
mixin Flyable {
  void fly() => print("Я летаю!");
}

class Bird with Flyable {
  void sing() => print("Чирик-чирик");
}
```

Теперь `Bird` имеет и метод `fly()`, и метод `sing()`.

### Почему Mixin полезен?

1. **Повторное использование кода** — вы можете использовать один mixin в нескольких классах.
2. **Избегает проблем наследования** — например, множественного наследования, которое не поддерживается в Dart.
3. **Позволяет строить сложные объекты из простых частей**.

### Пример с несколькими mixins:

```dart
mixin Flyable {
  void fly() => print("Я летаю!");
}

mixin Swimmable {
  void swim() => print("Я плаваю!");
}

class Duck with Flyable, Swimmable {
  void quack() => print("Кря-кря");
}
```

Теперь `Duck` может и летать, и плавать, и квакать.

### Ограничения Mixin:

1. **Mixin не могут иметь конструкторов**.
2. **Mixin не могут быть абстрактными**, но вы можете использовать абстрактные методы внутри них (создавая контракт).
3. **Mixin не могут быть инстанцированы напрямую**.

### Абстрактный mixin:

```dart
mixin Flyable {
  void fly();

  void takeOff() => print("Взлетаем!");
}

class Eagle with Flyable {
  @override
  void fly() => print("Орёл летит высоко");
}
```

## Сравнение: Composition vs Inheritance

| Особенность         | Composition                  | Inheritance                   |
|---------------------|------------------------------|-------------------------------|
| Повторное использование кода | Да (через композицию)       | Да (через наследование)       |
| Гибкость            | Высокая                      | Низкая                        |
| Сложность           | Более сложная концепция     | Проще для понимания          |
| Поддержка тестирования | Легче                     | Труднее (если иерархия сложна)|
| Изменения в коде    | Не требуют изменения классов | Могут потребовать изменений  |

---

## Когда использовать Composition?

- Когда вы хотите **повторно использовать поведение** без жёсткой связи.
- Когда **необходима гибкость** и **легкость масштабирования**.
- Когда **нужно избежать сложных иерархий наследования**.

---

## Когда использовать Inheritance?

- Когда вы строите **логически связанную иерархию**, например, `Animal` → `Dog`, `Cat`.
- Когда вы уверены, что **наследование не будет меняться** в будущем.
- Когда **нужно использовать полиморфизм** с общими методами.

---

## Заключение

Принцип **Composition over Inheritance** — это фундаментальный принцип в современном программировании. В Flutter он особенно важен, потому что позволяет создавать гибкие и масштабируемые UI-компоненты, которые легко тестировать и поддерживать.

Использование **mixins** в Dart — отличный способ реализовать композицию, особенно если вы хотите повторно использовать код между различными классами без наследования.
