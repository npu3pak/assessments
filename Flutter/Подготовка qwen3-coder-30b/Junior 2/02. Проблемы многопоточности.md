# Лекция: Проблемы многопоточности

## Введение

В мире мобильной разработки, особенно при использовании Flutter, важно понимать, как работают потоки выполнения. Flutter использует Dart, который по умолчанию работает в одном потоке (single-threaded), но при работе с асинхронными операциями и взаимодействии с внешними системами могут возникать проблемы многопоточности.

В этой лекции мы рассмотрим основные проблемы, связанные с многопоточностью, которые могут возникнуть при разработке мобильных приложений на Flutter. Понимание этих проблем позволит создавать более стабильные и надежные приложения.

---

## 1. Гонки (Race Conditions)

### Что такое гонка?

Гонка (race condition) — это состояние в программе, когда результат выполнения зависит от порядка, в котором выполняются независимые потоки или задачи. Это приводит к неопределенному поведению программы.

В Flutter, особенно при работе с асинхронными операциями, гонки могут возникать при одновременном доступе к общему ресурсу (например, переменной) из нескольких потоков или задач.

### Пример:

```dart
import 'dart:async';

class Counter {
  int _count = 0;

  Future<void> increment() async {
    await Future.delayed(Duration(milliseconds: 100)); // Симуляция асинхронной работы
    _count++; // Это может привести к гонке, если несколько вызовов происходят одновременно
  }

  int get count => _count;
}

void main() async {
  final counter = Counter();
  
  // Запускаем несколько асинхронных задач
  await Future.wait([
    counter.increment(),
    counter.increment(),
    counter.increment(),
  ]);

  print(counter.count); // Ожидаемое значение: 3, но на практике может быть меньше
}
```

В этом примере три вызова `increment()` могут выполняться одновременно. Если обе задачи читают `_count` до того, как одна из них изменит его, они будут записывать одно и то же значение, и счетчик увеличится только на 1 вместо 3.

### Решение:

Для решения проблемы гонок используются механизмы синхронизации, такие как `synchronized` или `Mutex`.

## 2. Dead/Live Lock

### Что такое Deadlock?

Deadlock — это состояние, при котором два или более потока блокируются навсегда, ожидая ресурсы, которые удерживают друг друга.

Пример:

```dart
import 'dart:async';

class BankAccount {
  int balance = 1000;
  final _lock = Lock(); // Предполагаемый мьютекс

  Future<void> transfer(BankAccount other, int amount) async {
    await _lock.acquire();
    if (balance >= amount) {
      balance -= amount;
      print('Переведено: $amount');
    }
    await _lock.release();

    // Потенциальная Deadlock, если другие потоки также пытаются получить блокировку
    await other._lock.acquire(); // Если другой поток уже удерживает эту блокировку
    other.balance += amount;
    await other._lock.release();
  }
}
```

### Что такое Live Lock?

Live Lock — это состояние, при котором потоки не блокируются, но не могут продвинуться вперед, потому что они постоянно реагируют на действия друг друга, не выполняя полезной работы.

### Решение:

Использование стратегии ожидания (например, `tryLock`) или упорядоченного захвата ресурсов помогает избежать deadlock и live lock.

## 3. Инверсия приоритетов

### Что такое инверсия приоритетов?

Инверсия приоритетов — это ситуация, когда поток с более низким приоритетом выполняется раньше потока с более высоким приоритетом. Это может происходить в системах с приоритетами и блокировками.

В Dart/Flutter это не так очевидно, но в сложных системах управления ресурсами может быть важно учитывать приоритеты потоков.

Пример:

Представим, что есть несколько потоков: высокоприоритетный (например, обновление UI) и низкоприоритетный (обработка данных). Если низкоприоритетный поток захватывает ресурс, который нужен высокоприоритетному, то последний может блокироваться.

### Решение:

Оптимизация приоритетов, использование планировщика задач, а также предотвращение длительного удержания ресурсов.

## 4. Throttle и Debounce

### Что такое Throttle?

Throttle — это техника ограничения частоты выполнения функции в течение определенного времени. Например, при скроллинге или поиске ввода, чтобы не вызывать обработку слишком часто.

Пример:

```dart
import 'dart:async';

class Throttler {
  Timer? _timer;
  final Duration duration;

  Throttler(this.duration);

  void throttle(Function() callback) {
    if (_timer?.isActive ?? false) return;

    _timer = Timer(duration, callback);
  }
}

void main() {
  final throttler = Throttler(Duration(milliseconds: 500));

  void handleInput(String input) {
    print('Обработан ввод: $input');
  }

  // Имитация частых вызовов
  for (int i = 0; i < 10; i++) {
    throttler.throttle(() => handleInput('input_$i'));
  }
}
```

### Что такое Debounce?

Debounce — это техника, которая откладывает выполнение функции до тех пор, пока не пройдет определенное время без вызовов. Полезно при поиске или вводе текста.

Пример:

```dart
class Debouncer {
  Timer? _timer;
  final Duration duration;

  Debouncer(this.duration);

  void debounce(Function() callback) {
    _timer?.cancel();
    _timer = Timer(duration, callback);
  }
}

void main() {
  final debouncer = Debouncer(Duration(milliseconds: 500));

  void handleSearch(String query) {
    print('Поиск по запросу: $query');
  }

  // Имитация ввода
  for (int i = 0; i < 10; i++) {
    debouncer.debounce(() => handleSearch('query_$i'));
  }
}
```

## 5. Пакет `synchronized`

Пакет `synchronized` — это удобный способ синхронизации в Dart/Flutter.

Установка:

```yaml
dependencies:
  synchronized: ^3.0.1
```

Пример использования:

```dart
import 'package:synchronized/synchronized.dart';

class SyncExample {
  final _lock = Lock();
  int count = 0;

  Future<void> increment() async {
    await _lock.synchronized(() async {
      // Только один поток может выполнить этот блок
      await Future.delayed(Duration(milliseconds: 100));
      count++;
    });
  }
}

void main() async {
  final example = SyncExample();
  await Future.wait([
    example.increment(),
    example.increment(),
    example.increment(),
  ]);
  print(example.count); // Всегда будет 3
}
```
