# Лекция: MVC Архитектурный паттерн для Flutter разработки

## Введение в MVC

MVC (Model-View-Controller) — это один из самых распространённых архитектурных шаблонов, используемых в мобильной и веб-разработке. Он помогает структурировать код, делая его более поддерживаемым, тестируемым и расширяемым.

В Flutter MVC реализуется с помощью следующих компонентов:
- **Model** — отвечает за данные и логику бизнес-логики.
- **View** — отвечает за отображение данных пользователю.
- **Controller** — связывает Model и View, обрабатывает события и управляет потоком данных.

---

## 1. Слой Model

### Что такое Model?

**Model** — это слой, который отвечает за **данные и бизнес-логику приложения**. Он не зависит от интерфейса пользователя и не знает, как данные будут отображаться. В Flutter модели обычно представляют собой классы, которые описывают структуру данных (например, `User`, `Product`, `Post`), а также методы для работы с ними.

### Особенности Model:

- Содержит данные и методы для их обработки.
- Не зависит от UI.
- Может работать с базами данных, API или внутренними хранилищами.

### Пример модели в Dart:

```dart
class User {
  final String id;
  final String name;
  final String email;

  User({
    required this.id,
    required this.name,
    required this.email,
  });

  // Метод для создания объекта из JSON (например, при получении данных с API)
  factory User.fromJson(Map<String, dynamic> json) {
    return User(
      id: json['id'],
      name: json['name'],
      email: json['email'],
    );
  }

  // Метод для преобразования объекта в JSON
  Map<String, dynamic> toJson() {
    return {
      'id': id,
      'name': name,
      'email': email,
    };
  }
}
```

### Использование модели:

```dart
void main() {
  final user = User(
    id: '1',
    name: 'Иван Петров',
    email: 'ivan@example.com',
  );

  print(user.toJson());
}
```

> **Примечание:** В реальных приложениях модель может взаимодействовать с `http` клиентом или `shared_preferences`, чтобы получать/сохранять данные.

## 2. Слой View

### Что такое View?

**View** — это **представление данных пользователю**, то есть UI (интерфейс). В Flutter это обычно набор виджетов, которые отображают информацию на экране. View не содержит логики, он просто "показывает" данные, полученные от Controller.

### Особенности View:

- Отвечает за отображение данных.
- Не содержит бизнес-логики.
- Может получать данные от Controller.

### Пример View в Flutter:

```dart
class UserView extends StatelessWidget {
  final User user;

  const UserView({Key? key, required this.user}) : super(key: key);

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Профиль пользователя')),
      body: Padding(
        padding: EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text('Имя: ${user.name}'),
            Text('Email: ${user.email}'),
          ],
        ),
      ),
    );
  }
}
```

> **Важно:** View не должен знать, откуда берутся данные. Он просто отображает то, что ему передают.

## 3. Слой Controller

### Что такое Controller?

**Controller** — это связующее звено между **Model** и **View**. Он получает данные из Model, обрабатывает их и передаёт View для отображения. Также Controller может обрабатывать пользовательские действия (например, нажатие кнопки) и управлять потоком данных.

### Особенности Controller:

- Обеспечивает связь между Model и View.
- Обрабатывает события пользователя.
- Может вызывать методы Model для получения/изменения данных.

### Пример Controller:

```dart
class UserController {
  User? _currentUser;

  // Получить данные пользователя (например, из API)
  Future<void> fetchUser(String userId) async {
    // Здесь можно сделать http-запрос
    final userData = await fetchUserDataFromAPI(userId);
    _currentUser = User.fromJson(userData);
  }

  // Метод для получения текущего пользователя
  User? get currentUser => _currentUser;

  // Пример метода для обновления данных
  Future<void> updateUser(User updatedUser) async {
    // Здесь можно отправить данные обратно на сервер
    await updateUserDataOnAPI(updatedUser);
    _currentUser = updatedUser;
  }
}
```

### Как Controller взаимодействует с View:

```dart
class UserScreen extends StatefulWidget {
  @override
  _UserScreenState createState() => _UserScreenState();
}

class _UserScreenState extends State<UserScreen> {
  final UserController controller = UserController();

  @override
  void initState() {
    super.initState();
    controller.fetchUser('1');
  }

  @override
  Widget build(BuildContext context) {
    return FutureBuilder<User?>(
      future: controller.fetchUser('1'),
      builder: (context, snapshot) {
        if (snapshot.connectionState == ConnectionState.waiting) {
          return CircularProgressIndicator();
        }
        final user = controller.currentUser;
        if (user == null) {
          return Text('Пользователь не найден');
        }
        return UserView(user: user);
      },
    );
  }
}
```

> **Примечание:** В более сложных приложениях Controller может быть реализован как `ChangeNotifier` или использовать `Bloc`, `Riverpod` и другие паттерны.

## 4. Особенности MVVM

### Что такое MVVM?

**MVVM (Model-View-ViewModel)** — это улучшенная версия MVC, где вместо Controller используется **ViewModel**. ViewModel содержит логику отображения данных и обработки пользовательских действий, но не знает о View напрямую.

### Различие между MVC и MVVM:

| Особенность | MVC | MVVM |
|-------------|-----|------|
| Связь с View | Controller | ViewModel |
| Ответственность | Controller управляет View | ViewModel упрощает View |
| Уровень абстракции | Низкий | Высокий |

### Пример ViewModel в Flutter:

```dart
class UserViewModel with ChangeNotifier {
  User? _user;
  bool _isLoading = false;

  User? get user => _user;
  bool get isLoading => _isLoading;

  Future<void> loadUser(String userId) async {
    _isLoading = true;
    notifyListeners();

    try {
      final userData = await fetchUserDataFromAPI(userId);
      _user = User.fromJson(userData);
    } catch (e) {
      print('Ошибка загрузки данных: $e');
    } finally {
      _isLoading = false;
      notifyListeners();
    }
  }
}
```

### Использование ViewModel в View:

```dart
class UserScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    final viewModel = Provider.of<UserViewModel>(context);

    return Scaffold(
      appBar: AppBar(title: Text('Пользователь')),
      body: Center(
        child: viewModel.isLoading
            ? CircularProgressIndicator()
            : Text(viewModel.user?.name ?? 'Нет данных'),
      ),
    );
  }
}
```

> **Примечание:** MVVM лучше всего работает с `Provider`, `Riverpod`, или другими инструментами, которые обеспечивают реактивность.

## Заключение

MVC — это мощный паттерн, который помогает структурировать Flutter-приложения. Он разделяет ответственность между слоями:
- **Model** отвечает за данные.
- **View** отображает их.
- **Controller** управляет потоком данных и взаимодействием.

MVVM — это более современный подход, где ViewModel берёт на себя больше работы по управлению состоянием и связыванию данных с View.
