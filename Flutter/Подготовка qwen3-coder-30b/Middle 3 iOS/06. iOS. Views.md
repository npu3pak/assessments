# Лекция: iOS Views – Создание наследников UIView и верстка в Xib-файлах

## Введение

В этом разделе мы рассмотрим, как создавать пользовательские представления (Views) в iOS-приложениях. Мы сосредоточимся на двух ключевых аспектах:  
1. **Создание наследников `UIView`**  
2. **Верстка `UIView` в Xib-файлах**

Эти темы являются фундаментальными для разработки мобильных приложений под iOS, особенно если вы стремитесь к уровню Middle 3 iOS-разработчика. После изучения этой лекции вы сможете самостоятельно создавать собственные View-компоненты и верстать их в Xib-файлах, что значительно ускорит процесс разработки и повысит переиспользуемость кода.

---

## 1. Создание наследников UIView

### Что такое `UIView`?

`UIView` — это базовый класс для всех видимых элементов интерфейса в iOS. Он отвечает за отображение содержимого, обработку событий и управление структурой представлений (View Hierarchy). Вся графика интерфейса на iOS строится на основе `UIView` и его наследников: `UIButton`, `UILabel`, `UIImageView`, `UITableView`, `UICollectionView` и т.д.

### Почему создавать собственные `UIView`?

Иногда стандартные компоненты не подходят под задачу, и вам нужно создать кастомный View с уникальным поведением или внешним видом. Например:

- Кастомная кнопка с анимацией
- Специальный элемент для отображения данных
- Компонент с собственной логикой взаимодействия

В этом случае вы наследуете `UIView`, чтобы создать свою собственную реализацию.

---

### Как создать собственный UIView?

Создание наследника `UIView` — это простая задача, но требует понимания жизненного цикла View и способа рендеринга.

#### Пример: Создание кастомного View

```swift
import UIKit

class CustomView: UIView {
    
    // MARK: - Инициализация
    
    override init(frame: CGRect) {
        super.init(frame: frame)
        setupView()
    }
    
    required init?(coder: NSCoder) {
        super.init(coder: coder)
        setupView()
    }
    
    private func setupView() {
        backgroundColor = .systemBlue
        layer.cornerRadius = 10
        clipsToBounds = true
    }
    
    // MARK: - Перерисовка
    
    override func draw(_ rect: CGRect) {
        let context = UIGraphicsGetCurrentContext()
        context?.setFillColor(UIColor.white.cgColor)
        context?.fill(rect)
        
        // Пример рисования текста
        let text = "Custom View"
        let attributes: [NSAttributedString.Key: Any] = [
            .font: UIFont.systemFont(ofSize: 16),
            .foregroundColor: UIColor.white
        ]
        
        let textSize = text.boundingRect(with: rect.size,
                                         options: .usesLineFragmentOrigin,
                                         attributes: attributes,
                                         context: nil).size
        
        let textRect = CGRect(x: (rect.width - textSize.width) / 2,
                              y: (rect.height - textSize.height) / 2,
                              width: textSize.width,
                              height: textSize.height)
        
        text.draw(in: textRect, withAttributes: attributes)
    }
}
```

#### Объяснение:

- `override init(frame:)` — инициализация с заданной рамкой
- `required init?(coder:)` — для использования из Interface Builder (Xib или Storyboard)
- `setupView()` — общая функция настройки (цвет, скругления и т.п.)
- `override func draw(_ rect:)` — метод рисования на CGContext. Используется для кастомной графики.

---

### Важные моменты:

1. **Конструкторы:**
   - `init(frame:)` — используется при программном создании.
   - `init?(coder:)` — используется при загрузке из Xib или Storyboard.

2. **Перерисовка (`draw`) vs Auto Layout:**
   - Метод `draw(_:)` используется для низкоуровневой графики.
   - Для простых изменений (цвета, размеры) лучше использовать Auto Layout и свойства `backgroundColor`, `layer.cornerRadius`.

3. **Создание через Interface Builder:**
   - Чтобы использовать ваш кастомный View в Xib или Storyboard, нужно указать его тип в "Custom Class" в Inspector.

## 2. Верстка UIView в Xib-файлах

### Что такое Xib?

Xib — это файл интерфейса в формате XML, который описывает пользовательский интерфейс. Он используется для создания UI визуально через Interface Builder (в Xcode). Вместо того чтобы программно создавать View, вы можете создать их визуально и связать с кодом.

### Как создать Xib-файл?

1. В Xcode выберите: **File → New → File**
2. Выберите **User Interface → View**
3. Назовите файл, например `CustomView.xib`
4. Откроется редактор с пустым View

---

### Связывание Xib-файла с кодом

Чтобы использовать Xib в коде, нужно:

#### 1. Создать класс, соответствующий Xib:

```swift
class CustomView: UIView {
    
    @IBOutlet weak var titleLabel: UILabel!
    @IBOutlet weak var button: UIButton!
    
    override init(frame: CGRect) {
        super.init(frame: frame)
        loadFromNib()
    }
    
    required init?(coder: NSCoder) {
        super.init(coder: coder)
        loadFromNib()
    }
    
    private func loadFromNib() {
        let bundle = Bundle(for: type(of: self))
        let nib = UINib(nibName: "CustomView", bundle: bundle)
        let view = nib.instantiate(withOwner: self, options: nil).first as! UIView
        
        addSubview(view)
        view.translatesAutoresizingMaskIntoConstraints = false
        NSLayoutConstraint.activate([
            view.topAnchor.constraint(equalTo: topAnchor),
            view.leadingAnchor.constraint(equalTo: leadingAnchor),
            view.trailingAnchor.constraint(equalTo: trailingAnchor),
            view.bottomAnchor.constraint(equalTo: bottomAnchor)
        ])
    }
}
```

#### 2. Подключить элементы в Xib:

В Interface Builder вы можете перетащить элементы в класс и использовать `@IBOutlet` и `@IBAction`.

---

### Плюсы использования Xib:

- **Быстрая верстка** без программного кода
- **Работа визуально** — легко экспериментировать с макетом
- **Легко поддерживать UI** при изменении макета

### Минусы:

- Сложнее тестировать и автоматизировать
- Повышается связность между UI и бизнес-логикой
