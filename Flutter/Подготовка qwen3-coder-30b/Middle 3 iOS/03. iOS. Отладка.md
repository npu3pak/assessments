### Лекция: Отладка в iOS разработке (Flutter)

#### Введение

Отладка — это один из ключевых навыков, который необходим каждому мобильному разработчику. Особенно это важно при работе с Flutter, где вы можете использовать как Dart, так и Swift/ObjC код под iOS. Отладка помогает выявлять ошибки, понимать поведение программы в реальном времени и оптимизировать производительность.

В этой лекции мы рассмотрим:

1. **Настройку break points** — точек остановки, которые позволяют приостановить выполнение кода для анализа состояния.
2. **Остановка приложения при возникновении ошибок** — как настроить автоматическую остановку при исключениях.
3. **Выполнение команд `p` и `po`** — встроенные команды отладчика, которые позволяют просматривать значения переменных.

---

## 1. Настройка Break Points

### Что такое break point?

Break point (точка остановки) — это указание в коде, где выполнение программы будет приостановлено. Это позволяет вам:

- Вручную анализировать состояние переменных.
- Изучать стек вызовов.
- Протрассировать выполнение программы шаг за шагом.

### Как добавить break point в Xcode?

В Xcode (который используется для сборки Flutter-приложений под iOS):

1. Откройте файл `.dart` или `.swift`.
2. Нажмите слева на номер строки (или кликните на саму строку).
3. Появится красная точка — break point.
4. Можно также дважды кликнуть на строке, чтобы добавить точку остановки.

> **Примечание**: Если вы работаете с Flutter-проектом, то в Xcode вы будете видеть файлы `.swift`, которые генерируются автоматически при сборке. Однако большинство логики находится в Dart-файлах, и отладка в них происходит через отладчик Dart.

### Break point в Flutter/Dart

При использовании **Dart DevTools** или **VS Code / Android Studio**, вы можете ставить break points прямо в `.dart` файлах.

Пример:

```dart
class MyHomePage extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    int value = 10; // Установите break point здесь
    return Scaffold(
      appBar: AppBar(title: Text('Debug Example')),
      body: Center(
        child: Text('$value'),
      ),
    );
  }
}
```

При запуске приложения в режиме отладки, когда выполнение достигнет строки с `int value = 10;`, оно остановится. Вы сможете посмотреть значение `value`.

### Типы break points:

- **Standard** — обычный break point.
- **Exception breakpoint** — останавливает выполнение при возникновении исключения (например, `NullPointer` или `AssertionError`).
- **Conditional breakpoint** — останавливается только при выполнении условия.

#### Пример: Условный break point

В Xcode:

1. Добавьте break point.
2. Кликните правой кнопкой мыши по нему → **Edit Breakpoint**.
3. В поле "Condition" введите условие, например:
   ```
   value == 5
   ```

Тогда остановка произойдет только если `value` равен 5.

## 2. Остановка при возникновении ошибок

### Exception Breakpoint

Чтобы автоматически останавливать выполнение при возникновении ошибки:

1. В **Debug Navigator** слева (или в боковой панели) откройте вкладку **Breakpoints**.
2. Нажмите на "+" и выберите **Add Exception Breakpoint**.
3. Выберите тип исключения:
   - **All Exceptions**: остановка при любом исключении.
   - **Caught Exceptions**: только при перехваченных исключениях.
   - **Uncaught Exceptions**: только при необработанных исключениях.

> Это очень полезно при отладке Flutter-приложений, где ошибки могут быть скрыты или возникнуть в асинхронном коде.

### Пример ошибки и остановка

Предположим, у нас есть такой код:

```dart
void processValue(int? value) {
  if (value == null) {
    throw Exception("Value cannot be null");
  }
  print(value * 2);
}
```

Если мы вызовем `processValue(null)` и у нас установлен **Exception Breakpoint**, выполнение остановится на строке с `throw`.

## 3. Выполнение команд `p` и `po`

### Что такое `p` и `po`?

Это команды отладчика, используемые в **LLDB (Low-Level Debugger)**, который используется в Xcode.

- `p <expression>` — выводит значение выражения.
- `po <expression>` — выводит значение выражения с форматированием объектов (например, `print` вместо `toString()`).

### Как использовать команды?

1. Запустите приложение в режиме отладки.
2. Когда выполнение остановлено на break point:
   - Введите команду в **Debug Console** (внизу Xcode).
   - Например:
     ```
     p value
     po myObject
     ```

### Пример:

```dart
void main() {
  List<String> names = ['Alice', 'Bob', 'Charlie'];
  Map<String, int> ages = {'Alice': 25, 'Bob': 30};

  runApp(MyApp());
}
```

При остановке на строке `Map<String, int> ages = {...}` в консоли можно выполнить:

```bash
p names
po ages
```

Результат:
```bash
(names) $R0 = size=3 { "Alice" "Bob" "Charlie" }
(ages) $R1 = {
  "Alice" = 25
  "Bob" = 30
}
```

> **Примечание**: `po` полезнее для вывода объектов, поскольку он вызывает `toString()` или специализированные методы.

## Полезные советы

### 1. Используйте отладочные логи

```dart
debugPrint('Значение: $value');
```

Их можно включить/отключить через флаг `--dart-define`.

### 2. Отладка асинхронного кода

Flutter использует асинхронность (Future, Stream). Для отладки таких частей:

1. Установите break point внутри `async` функции.
2. Используйте `await` и `print()` для понимания потока.

Пример:

```dart
Future<void> fetchData() async {
  print('Начинаем запрос');
  final response = await http.get(Uri.parse('https://api.example.com'));
  print('Ответ получен: $response');
}
```

### 3. Используйте **Dart DevTools**

Для более продвинутой отладки:

- **Flutter Inspector** — просмотр дерева виджетов.
- **Timeline** — анализ производительности.
- **Debugger** — отладка в IDE (VS Code, Android Studio).
