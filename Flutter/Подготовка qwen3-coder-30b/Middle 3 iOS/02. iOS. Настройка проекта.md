# Лекция 02: iOS. Настройка проекта

Привет, разработчик! Сегодня мы поговорим о **настройке проекта в iOS-среде** для Flutter-приложения. Это важная часть подготовки к разработке, особенно если ты хочешь создать качественное и производительное приложение под iOS.

Мы рассмотрим такие понятия, как:

1. **Targets**
2. **Build Configurations**
3. **Build Schemes**
4. **Info.plist**
5. **Capabilities**
6. **Build Phases**
7. **Управление локализацией**

Все это поможет тебе разобраться в том, как устроена структура проекта и как правильно его настраивать для нужд Flutter-приложения.

---

## 1. Targets

### Что такое Target?

**Target (Цель)** — это конфигурация сборки проекта, которая описывает, что нужно собрать, какие файлы использовать, какие фреймворки подключать и т.д.

В Flutter-проекте ты обычно имеешь два основных target:

- **Runner** — основной target для приложения.
- **RunnerTests** — target для тестов (если используются).

Когда ты создаешь Flutter-проект, Xcode автоматически создает эти два target'а. Но ты можешь добавлять и свои.

### Как настроить Target?

1. Открой проект в Xcode.
2. В левой панели выбери корневую папку проекта (не `Runner`).
3. Выбери `Runner` из списка Targets.
4. Вкладка `General` позволяет:
   - Изменить имя приложения
   - Установить Bundle Identifier
   - Выбрать версию iOS
   - Установить ресурсы (иконки, splash screen)

### Пример: Добавление нового Target

Если ты хочешь создать отдельный target для тестирования или для разных билдов:

1. В Xcode: `File → New → Target`
2. Выбери `iOS → Application → App`
3. Задай имя (например, `MyApp-Test`)
4. Убедись, что используется тот же язык (`Swift` или `Objective-C`) и та же версия iOS.

## 2. Build Configurations

### Что такое Build Configuration?

**Build Configuration** — это набор настроек, которые влияют на сборку проекта: отладка (Debug), релиз (Release) и другие пользовательские конфигурации.

В Flutter-проекте обычно есть:

- **Debug**
- **Release**

Каждая конфигурация может иметь свои переменные, флаги, оптимизации и т.д.

### Как управлять Build Configurations?

1. В Xcode выбери проект.
2. Перейди на вкладку `Info`.
3. Убедись, что ты видишь список конфигураций.
4. Ты можешь добавлять свои, например, `Staging`.

### Пример: Добавление своей Build Configuration

1. В Xcode выбери `Project Settings`.
2. Перейди на вкладку `Info`.
3. Нажми `+` рядом с `Configurations`.
4. Выбери `Duplicate "Debug"` и назови `Staging`.

Теперь ты можешь использовать `Staging` для специфичных настроек, например, для тестового API-эндпоинта.

## 3. Build Schemes

### Что такое Build Scheme?

**Build Scheme** — это набор правил, которые определяют, **как и когда** собирать проект: какие target'ы использовать, какую конфигурацию применять, запускать ли тесты и т.д.

Каждый `Target` может быть связан с несколькими схемами.

### Как настроить Build Scheme?

1. В Xcode выбери `Product → Scheme → Manage Schemes`.
2. Выбери нужную схему или создай новую.
3. В настройках можно указать:
   - Target
   - Конфигурацию (Debug/Release)
   - Тесты
   - Run / Profile / Analyze

### Пример: Создание отдельной схемы для Staging

1. `Manage Schemes`
2. Нажми `+` → `New Scheme`
3. Назови его `Runner-Staging`
4. Установи конфигурацию `Staging`

Теперь ты можешь собирать приложение как в Debug, так и в Staging-режиме.

## 4. Info.plist

### Что такое Info.plist?

**Info.plist** — это файл настроек проекта, который содержит информацию о приложении: версия, имя, иконка, разрешения, URL-схемы и т.д.

В Flutter-проекте этот файл находится по пути:

```
ios/Runner/Info.plist
```

### Как использовать Info.plist?

Пример содержимого `Info.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>CFBundleDevelopmentRegion</key>
    <string>$(DEVELOPMENT_LANGUAGE)</string>
    <key>CFBundleDisplayName</key>
    <string>MyApp</string>
    <key>CFBundleExecutable</key>
    <string>$(EXECUTABLE_NAME)</string>
    <key>CFBundleIdentifier</key>
    <string>com.example.myapp</string>
    <key>CFBundleInfoDictionaryVersion</key>
    <string>6.0</string>
    <key>CFBundleName</key>
    <string>myapp</string>
    <key>CFBundlePackageType</key>
    <string>APPL</string>
    <key>CFBundleShortVersionString</key>
    <string>$(FLUTTER_BUILD_NAME)</string>
    <key>CFBundleSignature</key>
    <string>????</string>
    <key>CFBundleVersion</key>
    <string>$(FLUTTER_BUILD_NUMBER)</string>
    <key>LSRequiresIPhoneOS</key>
    <true/>
    <key>UILaunchStoryboardName</key>
    <string>LaunchScreen</string>
    <key>UIMainStoryboardFile</key>
    <string>Main</string>
    <key>UISupportedInterfaceOrientations</key>
    <array>
        <string>UIInterfaceOrientationPortrait</string>
        <string>UIInterfaceOrientationLandscapeLeft</string>
        <string>UIInterfaceOrientationLandscapeRight</string>
    </array>
    <key>UISupportedInterfaceOrientations~ipad</key>
    <array>
        <string>UIInterfaceOrientationPortrait</string>
        <string>UIInterfaceOrientationPortraitUpsideDown</string>
        <string>UIInterfaceOrientationLandscapeLeft</string>
        <string>UIInterfaceOrientationLandscapeRight</string>
    </array>
    <key>UIViewControllerBasedStatusBarAppearance</key>
    <false/>
</dict>
</plist>
```

### Почему важно?

- Это основной способ задания настроек, которые влияют на поведение приложения.
- Здесь можно указать `URL Schemes`, `Permissions`, `Custom Entitlements`.

## 5. Capabilities

### Что такое Capabilities?

**Capabilities** — это функции, которые ты включаешь в приложение, например:

- Push Notifications
- App Groups
- iCloud
- HealthKit
- и другие.

Это позволяет использовать системные возможности iOS.

### Как управлять Capabilities?

1. В Xcode выбери проект.
2. Перейди на вкладку `Signing & Capabilities`.
3. Нажми `+ Capability` и выбери нужную функцию.

### Пример: Включение Push Notifications

1. Добавь Capability `Push Notifications`
2. Убедись, что у тебя есть сертификат для Push (в Apple Developer Portal)
3. Сгенерируй `.p8` файл и загрузи его в Xcode

## 6. Build Phases

### Что такое Build Phases?

**Build Phases** — это шаги, которые выполняются при сборке проекта.

Основные фазы:

- **Compile Sources** — компиляция исходных файлов
- **Link Binary With Libraries** — связывание с библиотеками
- **Copy Bundle Resources** — копирование ресурсов (иконки, строки, изображения)
- **Run Script** — выполнение скриптов перед сборкой

### Как использовать Build Phases?

1. В Xcode выбери проект.
2. Перейди на вкладку `Build Phases`.
3. Добавь нужные фазы.

#### Пример: Добавление скрипта перед сборкой

Добавь `Run Script`:

```bash
echo "Building for ${CONFIGURATION}"
```

Или например, запуск `flutter pub get` перед сборкой:

```bash
cd ..
flutter pub get
```

## 7. Управление локализацией

### Что такое локализация?

**Локализация (Localization)** — это адаптация приложения под разные языки и регионы.

Flutter использует `intl` пакет для локализации.

### Как настроить локализацию в Flutter?

1. Добавь `intl` в `pubspec.yaml`:

```yaml
dependencies:
  flutter:
    sdk: flutter
  intl: ^0.18.0

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^2.0.0
  build_runner: ^2.3.0
```

2. Создай файлы локализации, например:

```bash
lib/l10n/app_en.arb
lib/l10n/app_ru.arb
```

Пример `app_en.arb`:

```json
{
  "hello": "Hello"
}
```

Пример `app_ru.arb`:

```json
{
  "hello": "Привет"
}
```

3. Сгенерируй локализацию:

```bash
flutter pub run build_runner build
```

4. Используй в коде:

```dart
import 'package:flutter/material.dart';
import 'package:intl/intl.dart';

void main() {
  runApp(MyApp());
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      localizationsDelegates: [
        S.delegate,
        GlobalMaterialLocalizations.delegate,
        GlobalWidgetsLocalizations.delegate,
        GlobalCupertinoLocalizations.delegate,
      ],
      supportedLocales: [
        Locale('en'),
        Locale('ru'),
      ],
      home: Scaffold(
        appBar: AppBar(title: Text(S.of(context).hello)),
      ),
    );
  }
}
```

## Практическое задание

1. Создай новый Flutter-проект.
2. Открой его в Xcode.
3. Настрой `Runner` target:
   - Измени Bundle Identifier на `com.yourcompany.myapp`
   - Добавь новую Build Configuration `Staging`
   - Создай новую Build Scheme `Runner-Staging`
4. Добавь в `Info.plist` URL scheme.
5. Включи Capability Push Notifications.
6. Добавь скрипт в Build Phases, который выводит сообщение о сборке.
7. Настрой локализацию на английский и русский.
