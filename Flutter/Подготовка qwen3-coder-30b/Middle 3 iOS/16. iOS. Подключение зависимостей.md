# Лекция: iOS. Подключение зависимостей

## Введение

В мобильной разработке подключение внешних библиотек — это один из ключевых аспектов, который позволяет ускорить процесс разработки и использовать уже готовые решения для решения типовых задач. На iOS платформе существуют различные инструменты для управления зависимостями: **SPM (Swift Package Manager)**, **CocoaPods**, а также вспомогательные технологии, такие как **XCFramework**. В данной лекции мы подробно рассмотрим все эти инструменты и их применение в контексте Flutter-разработки.

## 1. Статические и динамические библиотеки, XCFramework

### Что такое статическая и динамическая библиотека?

**Библиотека** — это набор функций или классов, которые можно использовать в других проектах.

#### Статическая библиотека (.a файл)

- Содержит скомпилированный код, который **встраивается напрямую в исполняемый файл** при сборке.
- Пример: `libMyLibrary.a`
- Преимущества:
  - Быстрее загрузка, т.к. всё встроено.
  - Нет зависимости от внешних ресурсов во время выполнения.
- Недостатки:
  - Увеличивает размер финального приложения.
  - Невозможно использовать одну и ту же библиотеку в нескольких приложениях без повторной компиляции.

#### Динамическая библиотека (.dylib файл)

- Библиотека загружается **во время выполнения** и может использоваться разными приложениями.
- Пример: `libMyLibrary.dylib`
- Преимущества:
  - Экономия памяти (одна копия библиотеки используется несколькими приложениями).
  - Возможность обновления без пересборки приложения.
- Недостатки:
  - Сложнее управление версиями и зависимостями.

### XCFramework

**XCFramework** — это новый формат распространения библиотек в iOS, разработанный Apple для замены устаревших .framework и .a файлов. Он позволяет:

- Поддерживать несколько архитектур (например, x86_64, arm64) внутри одной структуры.
- Работать с различными платформами (iOS, macOS, Catalyst).
- Упрощает подключение библиотек в проектах, особенно если они содержат Swift-код.

> Важно: XCFramework — это **новый стандарт**, и его использование предпочтительнее по сравнению со старыми способами, особенно при использовании Swift-библиотек.

Пример подключения XCFramework в Xcode:
1. Перетащите `.xcframework` в проект.
2. Убедитесь, что он добавлен в раздел **Frameworks, Libraries and Embedded Content**.
3. При необходимости установите флаг `Embed & Sign`.

## 2. Подключение и использование библиотек

Подключение библиотек в iOS проектах — это процесс интеграции сторонних компонентов в ваше приложение. Рассмотрим подробнее, как это делается.

### Пример: использование библиотеки через CocoaPods

Допустим, вы хотите использовать библиотеку `Alamofire` для работы с HTTP-запросами:

1. Добавьте в `Podfile` строку:
   ```ruby
   pod 'Alamofire'
   ```

2. Запустите команду:
   ```bash
   pod install
   ```

3. Откройте `.xcworkspace`, а не `.xcodeproj`.

4. Импортируйте библиотеку в коде:
   ```swift
   import Alamofire
   ```

### Как использовать в Flutter?

Flutter использует **iOS-часть проекта** (внутри `ios/`) для подключения зависимостей. Для этого:

1. Откройте папку `ios` в вашем Flutter-проекте.
2. Отредактируйте `Podfile`, добавив зависимости.
3. Запустите `pod install`.
4. В коде Flutter используйте `MethodChannel` или `Platform Channels`, чтобы взаимодействовать с native-библиотеками.

## 3. SPM (Swift Package Manager). Подключение зависимостей

**SPM** — это встроенный в Xcode менеджер пакетов, который поддерживает Swift и C/C++ проекты.

### Как использовать SPM?

#### В Xcode:

1. Откройте ваш проект.
2. Перейдите в **File > Add Package Dependencies...**
3. Введите URL-адрес репозитория Swift-пакета, например:
   ```
   https://github.com/Alamofire/Alamofire.git
   ```

4. Выберите версию или указав ветку (`main`, `develop` и т.д.)

5. Укажите, к какому проекту добавить пакет (ваше приложение).

#### В Flutter:

Flutter поддерживает SPM напрямую. Если ваша библиотека написана на Swift и использует SPM, вы можете просто указать её в `pubspec.yaml` через `flutter pub add`, если она уже опубликована как Dart-пакет.

Если же вы используете **native-код**, то:
1. Добавьте Swift-пакет в `ios/Podfile` или напрямую в Xcode.
2. Синхронизируйте проект через `pod install`.

## 4. CocoaPods. Установка

**CocoaPods** — это система управления зависимостями для Objective-C и Swift проектов.

### Установка CocoaPods:

```bash
sudo gem install cocoapods
```

> Убедитесь, что у вас установлен Ruby и Xcode CLI.

После установки можно проверить версию:
```bash
pod --version
```

## 5. CocoaPods. Файлы Podfile и Podfile.lock

### Podfile

Это конфигурационный файл, описывающий зависимости проекта. Пример:

```ruby
platform :ios, '12.0'

target 'MyApp' do
  use_frameworks!
  
  pod 'Alamofire', '~> 5.6'
  pod 'Kingfisher', '~> 7.0'
end
```

- `platform :ios, '12.0'` — минимальная версия iOS.
- `use_frameworks!` — используется при подключении Swift-библиотек.
- `pod 'Name', '~> 5.6'` — указывает библиотеку и её версию.

### Podfile.lock

Файл, в котором хранится точная версия всех установленных зависимостей и их рекурсивных зависимостей.

Пример содержимого:

```ruby
PODS:
  - Alamofire (5.6.4)
  - Kingfisher (7.3.0)

DEPENDENCIES:
  - Alamofire (~> 5.6)
  - Kingfisher (~> 7.0)

SPEC CHECKSUMS:
  Alamofire: 1234567890abcdef...
  Kingfisher: abcdef1234567890...

PODFILE CHECKSUM: 1234567890abcdef...
```

Этот файл **не должен изменяться вручную**, он обновляется автоматически при вызове `pod install`.

## 6. CocoaPods. Команды pod install и pod update

### pod install

Команда устанавливает зависимости, указанные в `Podfile`. Если `Podfile.lock` уже существует — она использует его для установки точно тех же версий.

Пример:
```bash
pod install
```

### pod update

Обновляет все зависимости до последней доступной версии (по правилам, указанным в `Podfile`). Если вы хотите обновить конкретную зависимость:

```bash
pod update Alamofire
```

> Обратите внимание: `pod update` может привести к несовместимостям, поэтому лучше использовать `pod install`, если вы работаете с фиксированными версиями.

## Практическое задание

### Задача:

1. Создайте новый Flutter-проект:
   ```bash
   flutter create my_flutter_app
   cd my_flutter_app
   ```

2. Откройте проект в Xcode (или используйте `open ios/Runner.xcworkspace`).

3. Добавьте в `Podfile` следующие зависимости:
   - Alamofire (`pod 'Alamofire', '~> 5.6'`)
   - Kingfisher (`pod 'Kingfisher', '~> 7.0'`)

4. Выполните команду:
   ```bash
   cd ios && pod install
   ```

5. В Flutter-коде реализуйте функционал, который:
   - Использует `Alamofire` для отправки GET-запроса на тестовый API.
   - Использует `Kingfisher` для загрузки изображения по URL и отображения его в приложении.

6. Запустите приложение и убедитесь, что всё работает корректно.
