# Лекция: Многопоточность в iOS (GCD)  
**Уровень подготовки: Middle 3 iOS**

---

## Введение

В современной разработке мобильных приложений важно понимать, как эффективно использовать многопоточность для обеспечения высокой производительности, отзывчивости интерфейса и правильной работы с ресурсами. В этом курсе мы рассмотрим **Grand Central Dispatch (GCD)** — это мощная система в iOS/macOS, позволяющая управлять выполнением задач в многопоточной среде.

GCD предоставляет удобный способ планирования и выполнения операций в фоновых потоках, чтобы избежать блокировки основного потока (main thread) приложения. Это особенно важно для Flutter-разработчиков, которые работают с нативными компонентами и могут столкнуться с необходимостью использовать GCD напрямую.

---

## 1. Serial и Concurrent очереди. Глобальные очереди, QoS

### Что такое очередь (Queue)?
Очередь в GCD — это структура данных, которая содержит задачи (blocks), которые будут выполнены по одному или одновременно, в зависимости от типа очереди.

### Типы очередей:

#### 1.1 Serial Queue (Сериальная очередь)
- Выполняет только одну задачу за раз.
- Задачи выполняются последовательно — одна за другой.
- Используется для обеспечения синхронизации и предотвращения гонок данных (race conditions).

Пример:

```swift
let serialQueue = DispatchQueue(label: "com.myapp.serialQueue")

serialQueue.async {
    print("Задача 1")
}

serialQueue.async {
    print("Задача 2")
}
```

Вывод:
```
Задача 1
Задача 2
```

> Задачи выполняются по порядку, потому что очередь сериальная.

#### 1.2 Concurrent Queue (Конкурентная очередь)
- Может выполнять несколько задач одновременно.
- Порядок выполнения не гарантируется.
- Используется для параллельных операций, где нет зависимости между задачами.

Пример:

```swift
let concurrentQueue = DispatchQueue(label: "com.myapp.concurrent", qos: .background, attributes: .concurrent)

concurrentQueue.async {
    print("Задача 1")
}

concurrentQueue.async {
    print("Задача 2")
}
```

Вывод:
```
Задача 1
Задача 2
```

или

```
Задача 2
Задача 1
```

> Порядок может меняться — задачи выполняются параллельно.

#### 1.3 Глобальные очереди (Global Queues)
- Предоставляются системой и доступны по умолчанию.
- Используются для выполнения задач в фоне.
- Существует три уровня: `userInteractive`, `userInitiated`, `default`, `utility`, `background`.
- Каждый уровень имеет разный приоритет и используется в зависимости от характера задачи.

Пример:

```swift
DispatchQueue.global(qos: .background).async {
    // Долгая операция, например, загрузка данных из сети
    print("Задача выполняется в фоне")
}
```

#### 1.4 QoS (Quality of Service)
Определяет приоритет задачи и влияет на то, как система распределяет ресурсы.

| QoS             | Описание |
|------------------|----------|
| `.userInteractive` | Высокий приоритет, используется для UI-задач |
| `.userInitiated`   | Средний приоритет, задачи, инициированные пользователем |
| `.default`         | По умолчанию, средний приоритет |
| `.utility`         | Низкий приоритет, фоновые операции |
| `.background`      | Самый низкий приоритет, например, загрузка файлов |

## 2. Синхронное и асинхронное выполнение заданий

### Асинхронное выполнение (`async`)
- Задача выполняется в фоне.
- Основной поток не блокируется.
- Используется для долгих операций.

```swift
DispatchQueue.global().async {
    // Выполняется в фоне
    print("Фоновая задача")
}

print("Эта строка выведется сразу")
```

### Синхронное выполнение (`sync`)
- Задача выполняется синхронно — основной поток блокируется до завершения.
- Может привести к deadlock, если вызывается из того же потока.

```swift
DispatchQueue.global().sync {
    print("Синхронная задача")
}

print("Эта строка выведется после завершения задачи")
```

> ⚠️ Не используйте `sync` в основном потоке, это может вызвать **deadlock**.

## 3. DispatchGroup

`DispatchGroup` используется для отслеживания группы задач и выполнения действия после их завершения.

### Пример:

```swift
let group = DispatchGroup()

group.enter()
DispatchQueue.global().async {
    // Долгая задача
    Thread.sleep(forTimeInterval: 2)
    print("Задача 1 завершена")
    group.leave()
}

group.enter()
DispatchQueue.global().async {
    Thread.sleep(forTimeInterval: 1)
    print("Задача 2 завершена")
    group.leave()
}

group.notify(queue: .main) {
    print("Все задачи завершены")
}
```

### Как работает:
- `enter()` — увеличивает счетчик.
- `leave()` — уменьшает.
- `notify` — выполняется после того, как все задачи завершены.

## 4. Проблема Race Condition

Race condition возникает, когда несколько потоков одновременно обращаются к одной и той же переменной или ресурсу, что может привести к неопределенному поведению.

### Пример проблемы:

```swift
var counter = 0

for _ in 0..<1000 {
    DispatchQueue.global().async {
        counter += 1 // Это потенциальная race condition!
    }
}
```

Результат может быть любым — от 0 до 1000, в зависимости от того, как потоки будут синхронизированы.

### Решение с помощью `DispatchQueue`:

```swift
let queue = DispatchQueue(label: "counter.queue", attributes: .concurrent)
var counter = 0

for _ in 0..<1000 {
    queue.async(flags: .barrier) {
        counter += 1 //_barrier гарантирует, что только один поток изменяет данные за раз
    }
}
```

Или использовать `NSLock`:

```swift
let lock = NSLock()
var counter = 0

for _ in 0..<1000 {
    DispatchQueue.global().async {
        lock.lock()
        counter += 1
        lock.unlock()
    }
}
```

## 5. Проблема Deadlock

Deadlock — это состояние, когда два или более потоков ждут друг друга, и приложение блокируется.

### Пример deadlock:

```swift
let queue1 = DispatchQueue(label: "queue1")
let queue2 = DispatchQueue(label: "queue2")

queue1.async {
    print("queue1 начал выполнение")
    queue2.sync {
        print("queue2 внутри queue1")
    }
}

queue2.async {
    print("queue2 начал выполнение")
    queue1.sync {
        print("queue1 внутри queue2")
    }
}
```

Вывод:
```
queue1 начал выполнение
queue2 начал выполнение
```

Но дальше программа **зависнет** — это deadlock.

### Решение:
- Избегать `sync` вызовов из основного потока.
- Следить за порядком блокировки ресурсов.
- Использовать `DispatchGroup` или асинхронные методы вместо синхронных.
