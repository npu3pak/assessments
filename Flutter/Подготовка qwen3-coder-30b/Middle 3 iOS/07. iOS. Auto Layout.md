# Лекция: iOS Auto Layout для Flutter-разработчика (Middle 3 iOS)

## Введение

В этой лекции мы рассмотрим **Auto Layout** — фундаментальную систему в iOS разработке, которая позволяет создавать адаптивные интерфейсы. Несмотря на то, что Flutter использует свой собственный способ компоновки (LayoutBuilder, SizedBox и т.п.), понимание Auto Layout важно для мобильных разработчиков, которые работают с iOS напрямую или взаимодействуют с UIKit.

## Оглавление:

1. Управление расположением элементов
2. Работа с Constraints (ограничения)
3. Hugging Priority и Compression Resistance
4. Size Classes

---

## 1. Управление расположением элементов

### Что такое Auto Layout?

Auto Layout — это система ограничений (constraints), которая определяет, как элементы интерфейса должны быть размещены и изменять размер при изменении ориентации устройства или размера экрана.

Когда вы создаете UI в Storyboard или программно с помощью кода, вы указываете **ограничения** (constraints), которые определяют:
- Расстояние от края контейнера до элемента,
- Отношения размеров между элементами,
- Позиционирование по центру или краям.

### Как это работает в Flutter?

В Flutter вы не управляете Auto Layout напрямую, но вы используете **Layout Widgets**, которые работают с аналогичными принципами:
- `Container`, `SizedBox`, `Row`, `Column`, `Stack` и др. — все эти виджеты используют внутреннюю систему компоновки.
- Вы задаете размеры, отступы, позиционирование через свойства `width`, `height`, `padding`, `margin`, `alignment`, `crossAxisAlignment`.

Пример:
```dart
Container(
  width: 100,
  height: 50,
  margin: EdgeInsets.all(16),
  child: Text("Hello"),
)
```

Этот контейнер будет иметь фиксированный размер и отступы, но при изменении ориентации экрана он не будет адаптироваться автоматически. Для этого нужно использовать `LayoutBuilder`, `ConstrainedBox`, `SizedBox` и т.д.

### Зачем нужно понимать Auto Layout?

Даже если вы работаете в Flutter, понимание Auto Layout помогает:
- Понять, как работают `LayoutBuilder` и `MediaQuery`.
- Лучше понимать взаимодействие между виджетами.
- Работать с UIKit напрямую (например, при использовании Objective-C/Swift или SwiftUI).

## 2. Работа с Constraints

### Что такое Constraints?

Ограничения (constraints) — это правила, которые определяют:
- Где находится элемент,
- Какой у него размер,
- Как он должен реагировать на изменения экрана.

В iOS вы создаёте ограничения через:
- **Storyboard** (через Interface Builder),
- **Программно**, используя `NSLayoutConstraint`.

Пример программного создания ограничений:

```swift
let label = UILabel()
label.text = "Hello"

view.addSubview(label)

label.translatesAutoresizingMaskIntoConstraints = false

NSLayoutConstraint.activate([
    label.centerXAnchor.constraint(equalTo: view.centerXAnchor),
    label.centerYAnchor.constraint(equalTo: view.centerYAnchor),
    label.widthAnchor.constraint(equalToConstant: 100),
    label.heightAnchor.constraint(equalToConstant: 50)
])
```

### Как это работает в Flutter?

В Flutter вы **не пишете ограничения вручную**, но вы **управляете поведением виджетов** через их свойства, которые подразумевают наличие ограничений.

Например:
```dart
Row(
  children: [
    Container(width: 50, height: 50, color: Colors.red),
    Expanded(child: Text("This expands")),
  ],
)
```

Здесь `Expanded` указывает, что дочерний элемент должен занять всё доступное место по горизонтали.

### Основные типы ограничений:

1. **Positional constraints** — позиционирование:
   - `top`, `bottom`, `leading`, `trailing`
2. **Size constraints** — размер:
   - `width`, `height`, `minWidth`, `maxWidth`
3. **Aspect Ratio** — соотношение сторон
4. **Centering constraints** — центрирование

### Пример: Сложная компоновка в Flutter

```dart
Container(
  padding: EdgeInsets.all(16),
  child: Column(
    mainAxisAlignment: MainAxisAlignment.center,
    children: [
      Text("Title"),
      SizedBox(height: 10),
      Container(
        width: 100,
        height: 100,
        color: Colors.blue,
      ),
      SizedBox(height: 10),
      Text("Some text"),
    ],
  ),
)
```

Этот пример показывает, как вы можете использовать `Column` и `SizedBox`, чтобы задать интервалы между элементами.

## 3. Hugging Priority и Compression Resistance

### Что такое Hugging Priority?

**Hugging priority** — это приоритет элемента "прижиматься" к своему содержимому.

Например:
- Если вы создали `UILabel` с текстом "Hello World", и вы установили высокую `huggingPriority`, то этот лейбл будет стремиться быть таким же маленьким, как его контент.
- Если `huggingPriority` низкая — он будет стремиться занять больше места.

### Что такое Compression Resistance?

**Compression resistance** — это приоритет элемента сопротивляться уменьшению размера.

Если вы установите высокую `compressionResistance`, то элемент не будет сжиматься, даже если его контейнер меньше.

### Пример использования в UIKit:

```swift
let label = UILabel()
label.text = "Hello World"

// Установка приоритетов
label.setContentHuggingPriority(.defaultHigh, for: .horizontal)
label.setContentCompressionResistancePriority(.defaultLow, for: .horizontal)
```

### Как это работает в Flutter?

В Flutter нет прямого аналога `huggingPriority` и `compressionResistance`, но эти концепции реализуются через:
- Использование `Expanded` или `Flexible`,
- Применение `BoxConstraints`,
- Установку свойств `mainAxisSize`, `crossAxisAlignment`, `mainAxisAlignment`.

Пример:

```dart
Row(
  children: [
    Container(width: 50, height: 50, color: Colors.red),
    Expanded(
      child: Container(color: Colors.blue),
    ),
  ],
)
```

Здесь `Expanded` позволяет второму элементу занять всё доступное пространство.

## 4. Size Classes

### Что такое Size Classes?

**Size Classes** — это механизм в iOS, который позволяет адаптировать интерфейс под разные размеры экранов:
- **Width**: Compact (узкий) / Regular (широкий)
- **Height**: Compact (низкий) / Regular (высокий)

Например:
- iPhone в портретном режиме: `wCompact hCompact`
- iPad в ландшафтном режиме: `wRegular hRegular`

### Как это влияет на разработку?

Вы можете использовать Size Classes для:
- Изменения структуры layout,
- Отображения разных элементов,
- Применения разных размеров и отступов.

### Пример использования в UIKit:

```swift
override func traitCollectionDidChange(_ previousTraitCollection: UITraitCollection?) {
    if traitCollection.horizontalSizeClass == .regular {
        // Широкий экран, можно использовать более сложную компоновку
    } else {
        // Узкий экран, упрощенная версия
    }
}
```

### Как это работает в Flutter?

Flutter не использует Size Classes напрямую, но вы можете определить размер экрана с помощью `MediaQuery`:

```dart
final size = MediaQuery.of(context).size;
if (size.width > 600) {
  // Широкий экран (например, iPad)
} else {
  // Узкий экран (например, iPhone)
}
```

Также можно использовать `LayoutBuilder`, чтобы адаптировать UI под разные размеры:

```dart
LayoutBuilder(
  builder: (context, constraints) {
    if (constraints.maxWidth > 600) {
      return Row(children: [/* широкий layout */]);
    } else {
      return Column(children: [/* узкий layout */]);
    }
  },
)
```
