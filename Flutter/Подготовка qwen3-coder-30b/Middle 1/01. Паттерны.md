# Лекция: Паттерны проектирования для Flutter разработчика уровня Middle

## Введение

Паттерны проектирования — это готовые решения часто встречающихся задач в программировании. Они обеспечивают гибкость, масштабируемость и читаемость кода. В мире Flutter особенно важно уметь применять паттерны, чтобы создавать чистый, поддерживаемый и расширяемый код. На этом занятии мы рассмотрим 6 ключевых паттернов проектирования: **Builder**, **Factory**, **Delegate**, **Wrapper**, **Observer**, и **Composite**.

---

## 1. Builder (Строитель)

### Описание
Паттерн Builder используется для построения сложных объектов пошагово, разделяя создание объекта на этапы. Он полезен, когда объект требует много параметров, и конструктор становится неудобным.

### Когда использовать:
- Когда объект имеет множество параметров
- Когда нужно обеспечить гибкость в построении объекта
- Когда один и тот же процесс создания должен создавать разные представления

### Пример на Dart (Flutter):

```dart
class User {
  final String name;
  final int age;
  final String email;

  User({
    required this.name,
    required this.age,
    required this.email,
  });

  @override
  String toString() => 'User(name: $name, age: $age, email: $email)';
}

class UserBuilder {
  String? _name;
  int? _age;
  String? _email;

  UserBuilder setName(String name) {
    _name = name;
    return this;
  }

  UserBuilder setAge(int age) {
    _age = age;
    return this;
  }

  UserBuilder setEmail(String email) {
    _email = email;
    return this;
  }

  User build() {
    return User(
      name: _name ?? '',
      age: _age ?? 0,
      email: _email ?? '',
    );
  }
}

void main() {
  final user = UserBuilder()
    .setName('Иван')
    .setAge(30)
    .setEmail('ivan@example.com')
    .build();

  print(user); // User(name: Иван, age: 30, email: ivan@example.com)
}
```

### Плюсы:
- Читаемость и гибкость
- Упрощение создания сложных объектов

### Минусы:
- Дополнительный уровень абстракции может быть избыточным для простых случаев

## 2. Factory (Фабрика), Фабричный метод, Абстрактная фабрика

### Описание
Фабричные паттерны позволяют создавать объекты без указания конкретных классов. Они помогают снизить связность между клиентом и создаваемыми объектами.

#### 2.1. Factory Method (Фабричный метод)
Определяет интерфейс для создания объекта, но позволяет подклассам изменять тип создаваемого объекта.

#### 2.2. Abstract Factory (Абстрактная фабрика)
Предоставляет интерфейс для создания семейств связанных или зависимых объектов без указания их конкретных классов.

### Пример на Dart:

```dart
abstract class Button {
  void render();
}

class WindowsButton implements Button {
  @override
  void render() => print('Render Windows Button');
}

class MacButton implements Button {
  @override
  void render() => print('Render Mac Button');
}

// Фабричный метод
abstract class GUIFactory {
  Button createButton();
}

class WindowsFactory extends GUIFactory {
  @override
  Button createButton() => WindowsButton();
}

class MacFactory extends GUIFactory {
  @override
  Button createButton() => MacButton();
}

void main() {
  final factory = WindowsFactory(); // или MacFactory()
  final button = factory.createButton();
  button.render(); // Render Windows Button
}
```

### Плюсы:
- Снижает связность
- Упрощает добавление новых типов объектов

### Минусы:
- Может усложнить структуру проекта при неправильном применении

## 3. Delegate (Делегат)

### Описание
Паттерн делегирования используется, когда один объект передаёт часть своей работы другому объекту. Это позволяет упростить логику и повысить переиспользуемость.

### Когда использовать:
- Когда класс должен делегировать часть своих обязанностей другим объектам
- Для реализации поведения без наследования

### Пример на Dart:

```dart
class Database {
  void save(String data) => print('Saving $data to DB');
}

class Logger {
  void log(String message) => print('Logging: $message');
}

class DataManager {
  final Database _database = Database();
  final Logger _logger = Logger();

  void saveData(String data) {
    _logger.log('Saving data...');
    _database.save(data);
  }
}
```

### Плюсы:
- Упрощает код
- Повышает модульность

### Минусы:
- Может привести к усложнению взаимодействия между объектами

## 4. Wrapper (Обёртка)

### Описание
Wrapper — это паттерн, при котором объект оборачивает другой объект, добавляя ему новую функциональность. Обычно используется для расширения функционала без изменения исходного класса.

### Когда использовать:
- Когда нужно добавить функционал к уже существующему объекту
- Для создания адаптеров или оберток вокруг сторонних библиотек

### Пример на Dart:

```dart
class TextProcessor {
  String process(String text) => text.toUpperCase();
}

class CapitalizeWrapper {
  final TextProcessor _processor;

  CapitalizeWrapper(this._processor);

  String process(String text) => _processor.process(text).replaceAllMapped(
    RegExp(r'\b\w'),
    (match) => match.group(0)?.toUpperCase() ?? '',
  );
}
```

### Плюсы:
- Удобно расширять функционал
- Не нарушает принцип открытости/закрытости

### Минусы:
- Может усложнить структуру, если много обёрток

## 5. Observer (Наблюдатель)

### Описание
Паттерн Observer позволяет объектам уведомлять другие объекты о своих изменениях. Он часто используется в реактивных системах и UI-фреймворках.

### Когда использовать:
- Для реализации событийной архитектуры
- Когда один объект должен реагировать на изменения другого

### Пример на Dart:

```dart
class Subject {
  final List<Observer> _observers = [];

  void attach(Observer observer) => _observers.add(observer);

  void notify(String message) {
    for (var observer in _observers) {
      observer.update(message);
    }
  }
}

abstract class Observer {
  void update(String message);
}

class ConcreteObserver implements Observer {
  @override
  void update(String message) {
    print('Received: $message');
  }
}

void main() {
  final subject = Subject();
  final observer = ConcreteObserver();

  subject.attach(observer);
  subject.notify('Hello, World!');
}
```

### Плюсы:
- Упрощает взаимодействие между объектами
- Поддерживает слабую связанность

### Минусы:
- Может быть сложно отладить при большом количестве подписчиков

## 6. Composite (Компоновщик)

### Описание
Паттерн Composite используется для построения древовидных структур, где элементы могут быть как листьями, так и узлами. Он позволяет работать с отдельными объектами и их группами одинаково.

### Когда использовать:
- Для работы с древовидной структурой данных
- Когда нужно выполнять операции над коллекцией и её элементами

### Пример на Dart:

```dart
abstract class Component {
  void operation();
}

class Leaf extends Component {
  @override
  void operation() => print('Leaf operation');
}

class Composite extends Component {
  final List<Component> _children = [];

  void add(Component component) => _children.add(component);

  @override
  void operation() {
    for (var child in _children) {
      child.operation();
    }
  }
}

void main() {
  final leaf1 = Leaf();
  final leaf2 = Leaf();
  final composite = Composite();

  composite.add(leaf1);
  composite.add(leaf2);

  composite.operation(); // Leaf operation, Leaf operation
}
```

### Плюсы:
- Упрощает работу с древовидными структурами
- Позволяет одинаково работать с элементами и группами

### Минусы:
- Может усложнить код при неправильном применении

## Практическое задание

Создайте Flutter-приложение, которое демонстрирует использование следующих паттернов:

1. **Builder** — для построения сложного UI-элемента (например, формы с полями)
2. **Factory** — для создания различных типов виджетов (в зависимости от параметра)
3. **Observer** — для обработки изменений состояния приложения
4. **Composite** — для построения дерева элементов меню
5. **Wrapper** — для расширения функционала существующего класса (например, логирования или валидации)
