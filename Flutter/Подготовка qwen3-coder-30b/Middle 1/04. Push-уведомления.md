# Лекция: Push-уведомления в Flutter

## Введение

Push-уведомления — это механизм, позволяющий отправлять сообщения на мобильные устройства пользователя, даже когда приложение не активно. Это мощный инструмент для взаимодействия с пользователем, уведомления о событиях, рекламных акциях и т.д.

В мире мобильной разработки push-уведомления играют ключевую роль в повышении вовлеченности пользователей и эффективности приложений. В данном руководстве мы рассмотрим:

1. Концепцию push-уведомлений
2. Системы push-уведомлений (Firebase, OneSignal и другие)
3. Отличия сигнальных и обычных push-уведомлений
4. Управление разрешениями на Android
5. Работа с Push Token'ами
6. Настройка приложения под Firebase
7. Особенности приема push в foreground и background
8. Отправка push через Firebase Console
9. Отправка push через gorush

## 1. Объяснение концепции

Push-уведомление — это сообщение, которое отправляется с сервера на мобильное устройство пользователя, даже если приложение не запущено. Это достигается за счет использования специализированных сервисов, таких как Firebase Cloud Messaging (FCM), Apple Push Notification Service (APNs) для iOS и Google Cloud Messaging для Android.

### Принцип работы:

1. Приложение регистрируется в push-сервисе и получает уникальный **Push Token**.
2. Сервер отправляет сообщение через API сервиса, указывая токен получателя.
3. Сервис доставляет уведомление на устройство.
4. На устройстве отображается уведомление или запускается приложение (в зависимости от настроек).

### Пример: Что происходит при получении push-уведомления

```dart
// Внутри flutter-приложения мы можем прослушивать push-уведомления
Future<void> _handleBackgroundMessage(RemoteMessage message) async {
  print('Получено фоновое сообщение: ${message.notification?.title}');
}
```

## 2. Какие есть сервисы Push-уведомлений и чем они отличаются

В мобильной разработке существует несколько популярных платформ для push-уведомлений:

### Firebase Cloud Messaging (FCM)

**Описание:**  
Сервис от Google, используемый для отправки уведомлений и данных на Android, iOS и Web. Поддерживает как **notification messages**, так и **data messages**.

**Преимущества:**
- Интеграция с другими сервисами Firebase
- Удобная панель управления через Firebase Console
- Поддержка аудиторий (segments)
- Простота настройки

**Недостатки:**
- Зависимость от Google Play Services (на Android)

### OneSignal

**Описание:**  
Кроссплатформенный сервис, который поддерживает Android, iOS, Web и другие платформы. Позволяет отправлять push-уведомления через API.

**Преимущества:**
- Хорошо работает без Google Play Services
- Поддержка разных языков и регионов
- Отличная документация

**Недостатки:**
- Не все функции доступны бесплатно (например, сегментация)
- Меньше интеграций с другими сервисами Google

### Amazon SNS (Simple Notification Service)

**Описание:**  
Сервис от AWS, предназначенный для доставки сообщений по различным каналам: push-уведомления, SMS, email.

**Преимущества:**
- Интеграция с другими сервисами AWS
- Масштабируемость

**Недостатки:**
- Сложнее настройки для новичков
- Нужно иметь учетную запись AWS

### APNs (Apple Push Notification Service)

**Описание:**  
Сервис от Apple, предназначенный исключительно для iOS.

**Преимущества:**
- Официальная поддержка от Apple
- Отличная интеграция с iOS

**Недостатки:**
- Работает только на iOS устройствах

## 3. Отличие сигнальных Push и Push-уведомлений без деталей реализации

### Сигнальные Push-уведомления (Notification Messages)

Это уведомления, которые **автоматически отображаются** в системе уведомлений устройства. Они не требуют обработки внутри приложения и показываются даже если приложение закрыто.

**Пример:**
```json
{
  "notification": {
    "title": "Новое сообщение",
    "body": "У вас новое уведомление!"
  },
  "data": {
    "custom_key": "value"
  }
}
```

### Push-уведомления без деталей (Data Messages)

Это **данные**, которые отправляются в приложение, но не отображаются как уведомление. Эти данные нужно обрабатывать программно внутри приложения.

**Пример:**
```json
{
  "data": {
    "event_type": "message_received",
    "message_id": "12345"
  }
}
```

> **Важно:** Если в сообщении есть поле `notification`, то оно будет отображено как уведомление. Если только `data` — тогда приложение должно обработать данные самостоятельно.

## 4. Запрос разрешений. Особенности на Android

Перед тем как получать push-уведомления, необходимо получить **разрешение пользователя**. В Android это делается через системное окно.

### Объяснение:

- На Android 6+ (API level 23+) нужно запрашивать разрешение `POST_NOTIFICATIONS`.
- На Android 13+ (API 33) требуется отдельное разрешение на уведомления.
- В Flutter можно использовать пакет [flutter_local_notifications](https://pub.dev/packages/flutter_local_notifications).

### Пример запроса разрешений:

```dart
import 'package:flutter_local_notifications/flutter_local_notifications.dart';

final flutterLocalNotificationsPlugin = FlutterLocalNotificationsPlugin();

Future<void> requestNotificationPermission() async {
  const AndroidInitializationSettings initializationSettingsAndroid =
      AndroidInitializationSettings('@mipmap/ic_launcher');

  final InitializationSettings initializationSettings =
      InitializationSettings(android: initializationSettingsAndroid);

  await flutterLocalNotificationsPlugin.initialize(initializationSettings);

  // Запрос разрешения
  final NotificationAppLaunchDetails? notificationAppLaunchDetails =
      await flutterLocalNotificationsPlugin.getNotificationAppLaunchDetails();

  if (notificationAppLaunchDetails?.didNotificationLaunchApp ?? false) {
    // Приложение было запущено через уведомление
  }
}
```

### Особенности на Android:

- Для Android 13+ нужно использовать `PermissionManager` и запросить `Permission.notification`.
- Если разрешение не получено, push-уведомления не будут отображаться.
- Некоторые устройства (например, Xiaomi) могут блокировать уведомления по умолчанию — проверяйте настройки пользователя.

## 5. Работа с Push Token

Push Token — это уникальный идентификатор устройства, который получает приложение при регистрации в FCM. Он используется сервером для отправки push-уведомлений конкретному устройству.

### Как получить Token:

```dart
import 'package:firebase_messaging/firebase_messaging.dart';

Future<void> _getPushToken() async {
  final token = await FirebaseMessaging.getToken();
  print('Push Token: $token');

  // Отправка токена на ваш сервер
  await sendTokenToServer(token);
}
```

### Обработка изменения токена:

```dart
FirebaseMessaging.onTokenRefresh.listen((newToken) {
  print('Обновленный Token: $newToken');
  sendTokenToServer(newToken);
});
```

> **Важно:** Токен может измениться, например, при обновлении приложения или сбросе настроек. Поэтому необходимо слушать `onTokenRefresh`.

## 6. Настройка приложения для получения Push-уведомлений Firebase

### Шаг 1: Подключение Firebase к проекту

1. Создайте проект в [Firebase Console](https://console.firebase.google.com/)
2. Скачайте файл `google-services.json` и положите его в `android/app/`
3. Добавьте зависимости в `pubspec.yaml`:

```yaml
dependencies:
  firebase_core: ^2.15.0
  firebase_messaging: ^14.7.0
```

### Шаг 2: Инициализация Firebase

```dart
import 'package:firebase_core/firebase_core.dart';
import 'package:flutter/material.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp();
  runApp(MyApp());
}
```

### Шаг 3: Обработка push-сообщений

```dart
Future<void> _handleBackgroundMessage(RemoteMessage message) async {
  print('Получено фоновое сообщение: ${message.notification?.title}');
}

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp();

  FirebaseMessaging.onMessage.listen((RemoteMessage message) {
    print('Получено уведомление в foreground: ${message.notification?.title}');
  });

  FirebaseMessaging.onBackgroundMessage(_handleBackgroundMessage);

  runApp(MyApp());
}
```

## 7. Отличие приема Push в Foreground и Background

### Foreground (приложение активно)

- Уведомления обрабатываются через `onMessage`.
- Можно показать уведомление внутри приложения.
- Пример:

```dart
FirebaseMessaging.onMessage.listen((RemoteMessage message) {
  print('Уведомление в foreground: ${message.notification?.title}');
});
```

### Background (приложение свернуто или закрыто)

- Уведомления обрабатываются через `onBackgroundMessage`.
- Система запускает приложение в фоне, если нужно.
- Нужно реализовать обработку данных и уведомлений.

```dart
Future<void> _handleBackgroundMessage(RemoteMessage message) async {
  print('Фоновое сообщение: ${message.notification?.title}');
}
```

## 8. Отправка Push-уведомлений через консоль Firebase

### Шаги:

1. Перейдите в [Firebase Console](https://console.firebase.google.com/)
2. Выберите проект → Cloud Messaging
3. Нажмите "Создать сообщение"
4. Укажите:
   - Заголовок и текст уведомления
   - Целевую аудиторию (все устройства или конкретный токен)
   - Дополнительные данные, если нужно

> **Важно:** Для отправки через консоль нужно знать Push Token устройства.

## 9. Отправка Push-уведомлений через gorush при наличии json-файла с ключом

Gorush — это open-source сервер для отправки push-уведомлений (в основном для Android и iOS).

### Установка:

1. Скачайте [gorush](https://github.com/zhenghaoz/gorush)
2. Настройте файл `config.toml` или используйте JSON
3. Используйте API для отправки push

### Пример запроса через curl:

```bash
curl -X POST http://localhost:8080/api/push \
  -H "Content-Type: application/json" \
  -d '{
    "tokens": ["token1", "token2"],
    "message": "Hello from gorush!",
    "platform": "android"
  }'
```
