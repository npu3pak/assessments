## 1. Linter — Что такое, как подключить и настроить

### Что такое Linter?

**Linter** — это инструмент, который анализирует исходный код на наличие ошибок, несоответствий стилю и потенциальных проблем. Он помогает улучшить качество кода, предотвратить распространённые ошибки и поддерживать единообразие в проекте.

В Dart для этого используется **`dart analyze`**, который основан на наборе правил из **[Effective Dart](https://dart.dev/effective-dart)**.

### Как подключить Linter?

В Flutter проектах Linter уже встроен и активен по умолчанию. Однако можно его дополнительно настроить.

#### 1.1 Файл `analysis_options.yaml`

Это главный конфигурационный файл для анализа кода. Он находится в корне проекта:

```yaml
# analysis_options.yaml

linter:
  rules:
    # Правила, которые вы хотите включить или отключить
    prefer_final_locals: true
    avoid_print: true
    prefer_single_quotes: true
    unnecessary_new: true
    unnecessary_const: true
    use_key_in_widget_constructors: true
    must_be_immutable: true
    public_member_api_docs: true # Рекомендация к документации
```

#### 1.2 Что можно настроить?

| Правило                          | Описание                                                                 |
|----------------------------------|--------------------------------------------------------------------------|
| `prefer_final_locals`            | Использовать `final` вместо `var`, если значение не изменяется          |
| `avoid_print`                    | Запрет на использование `print()` в продакшене                           |
| `prefer_single_quotes`           | Использовать одинарные кавычки для строк                                 |
| `use_key_in_widget_constructors` | Обязательное использование `key` при создании виджетов                   |
| `public_member_api_docs`         | Обязательное наличие документации для публичных членов класса           |

#### 1.3 Как запустить анализ?

В командной строке:

```bash
flutter analyze
```

Или через IDE (например, VS Code или Android Studio), где автоматически показываются ошибки и предупреждения.

> ⚠️ Важно: Linter не заменяет тестирование и ручную проверку кода, но он помогает избежать многих типичных ошибок и улучшить качество.

## 2. Стиль кода (Style Guide)

### Что такое Style Guide?

**Style Guide** — это набор правил по написанию кода, который делает его более читаемым, согласованным и поддерживаемым. В Dart используется официальный стиль, описанный в [Effective Dart](https://dart.dev/effective-dart).

### Основные рекомендации:

#### 2.1 Именование

- Переменные и функции: `camelCase`
- Классы и типы: `PascalCase`
- Константы: `UPPER_SNAKE_CASE`

```dart
class UserProfile {
  final String name;
  final int age;

  UserProfile({
    required this.name,
    required this.age,
  });

  static const String DEFAULT_NAME = 'Anonymous';
}
```

#### 2.2 Отступы и форматирование

Используйте **Flutter Doctor** или **Dart extension в VS Code** для автоматического форматирования:

```bash
dart format .
```

Пример кода до и после форматирования:

```dart
class Calculator{
  int add(int a, int b){return a+b;}
}
```

После форматирования:

```dart
class Calculator {
  int add(int a, int b) {
    return a + b;
  }
}
```

#### 2.3 Комментарии

Используйте комментарии для объяснения **зачем** что-то делается, а не **что** делается:

```dart
// ❌ Плохо
int calculateTotal(int price, int quantity) {
  return price * quantity; // Умножаем цену на количество
}

// ✅ Хорошо
/// Вычисляет общую сумму по цене и количеству.
int calculateTotal(int price, int quantity) {
  return price * quantity;
}
```

#### 2.4 Порядок полей

Поля класса должны быть расположены в следующем порядке:

1. Константы (`const`)
2. Статические поля
3. Поля экземпляра
4. Конструкторы
5. Методы

```dart
class User {
  static const String DEFAULT_ROLE = 'user';

  final String name;
  final int age;

  User({required this.name, required this.age});

  void greet() {
    print('Hello, $name');
  }
}
```

## 3. Документирование (Documentation Guide)

### Зачем документировать?

Документация делает код понятнее для других разработчиков, а также упрощает его поддержку и тестирование.

### Как документировать в Dart?

Используйте **DartDoc**, который позволяет создавать комментарии с метаданными:

```dart
/// Класс для представления пользователя.
///
/// Пример использования:
/// ```dart
/// final user = User(name: 'John', age: 30);
/// ```
class User {
  /// Имя пользователя
  final String name;

  /// Возраст пользователя
  final int age;

  /// Создаёт нового пользователя.
  ///
  /// [name] — имя пользователя.
  /// [age] — возраст пользователя (должен быть положительным).
  User({
    required this.name,
    required this.age,
  });
}
```

### Как сгенерировать документацию?

```bash
dart doc .
```

Это создаст HTML-документацию по проекту.

> 📌 **Совет:** Обязательно документируйте публичные API, такие как классы, методы и константы.

## 4. Использование конструкций языка (Usage Guide)

### 4.1 Используйте `final` и `const`

Предпочтительнее использовать `final` вместо `var`, если значение не изменится:

```dart
// ❌ Не очень
var name = 'John';

// ✅ Лучше
final String name = 'John';
```

Используйте `const`, когда значение известно во время компиляции:

```dart
const int MAX_USERS = 100;
const List<String> SUPPORTED_LANGUAGES = ['en', 'ru'];
```

### 4.2 Используйте `required` в конструкторах

Если параметр обязателен, используйте ключевое слово `required`:

```dart
class User {
  final String name;
  final int age;

  User({
    required this.name,
    required this.age,
  });
}
```

### 4.3 Используйте `late` только тогда, когда действительно нужно

Ключевое слово `late` позволяет объявить переменную без инициализации, но его использование может быть опасным:

```dart
class MyWidget extends StatelessWidget {
  late final String title; // Плохо, если не уверен, что будет инициализировано

  @override
  Widget build(BuildContext context) {
    return Text(title);
  }
}
```

> ✅ Лучше всегда инициализировать поля при создании объекта.

### 4.4 Не используйте `dynamic`, если не нужно

Если тип известен, используйте его явно:

```dart
// ❌ Не очень
dynamic result = someFunction();

// ✅ Лучше
String result = someFunction();
```

## 5. Проектирование (Design Guide)

### 5.1 SOLID принципы

Соблюдайте основные принципы проектирования:

#### Single Responsibility Principle (SRP)
Каждый класс должен иметь одну ответственность.

```dart
// ❌ Нарушение SRP
class User {
  String name;
  void saveToDatabase() { /* ... */ }
  void sendEmail() { /* ... */ }
}

// ✅ Хорошо
class UserRepository {
  void save(User user) { /* ... */ }
}

class EmailService {
  void send(User user) { /* ... */ }
}
```

#### Open/Closed Principle (OCP)
Программные сущности должны быть открыты для расширения, но закрыты для модификации.

```dart
abstract class Shape {
  double calculateArea();
}

class Rectangle extends Shape {
  @override
  double calculateArea() => width * height;
}
```

#### Dependency Inversion Principle (DIP)
Зависите от абстракций, а не от конкретных реализаций.

```dart
abstract class UserRepository {
  Future<User> getUser(int id);
}

class DatabaseUserRepository implements UserRepository {
  @override
  Future<User> getUser(int id) async {
    // ...
  }
}
```

### 5.2 Используйте паттерны проектирования

#### Singleton

```dart
class DatabaseManager {
  static final DatabaseManager _instance = DatabaseManager._internal();
  factory DatabaseManager() => _instance;
  DatabaseManager._internal();

  // ...
}
```

#### Builder Pattern

```dart
class UserBuilder {
  String? name;
  int? age;

  UserBuilder setName(String name) {
    this.name = name;
    return this;
  }

  UserBuilder setAge(int age) {
    this.age = age;
    return this;
  }

  User build() => User(name: name!, age: age!);
}
```

## Практическое задание

Создайте Flutter-приложение с простым интерфейсом, где реализованы следующие практики:

1. Используйте `analysis_options.yaml` с несколькими правилами.
2. Реализуйте класс `User`, документируйте его через DartDoc.
3. Примените паттерн Builder для создания объекта `User`.
4. Все поля должны быть `final`, если они не изменяются.
5. Используйте `required` параметры в конструкторе.
6. Подключите Linter и убедитесь, что анализ проходит без ошибок.
