# Лекция: Android Gradle для Flutter разработчика уровня Middle 3

## Введение

Добро пожаловать в лекцию по **Android Gradle** — ключевому инструменту для сборки, настройки и управления проектами на Android. Хотя вы работаете с Flutter, знание Gradle важно, потому что Flutter использует Android Gradle Plugin (AGP) для сборки приложений под Android.

Эта лекция поможет вам понять, как управлять сборкой вашего Flutter-приложения под Android, какие параметры и настройки влияют на процесс, и как правильно работать с зависимостями, версиями, архитектурами и билд-вариантами.

## 1. Назначение Gradle

**Gradle** — это мощная система автоматизации сборки для проектов Java, Kotlin и Android. Он позволяет:

- Управлять зависимостями проекта (библиотеки, фреймворки и т.д.)
- Определять конфигурации сборки
- Создавать разные версии приложения (например, debug и release)
- Автоматизировать процессы: компиляция, тестирование, упаковка
- Интегрироваться с IDE и CI/CD

В Flutter проектах Gradle работает на уровне Android-части. Когда вы запускаете `flutter build apk`, Flutter вызывает Gradle для сборки `.apk` или `.aab`.

### Пример: Как Gradle используется в Flutter

Внутри Flutter-проекта структура Android-части выглядит так:

```
android/
├── app/
│   ├── build.gradle
│   └── src/main/...
├── build.gradle
└── gradle.properties
```

Когда вы выполняете `flutter build apk`, Gradle читает `build.gradle` файлы и собирает проект.

## 2. Настройка версии приложения

Версия приложения — это важная часть, особенно для публикации в Google Play. В Android используются два параметра:

- **versionCode** — целое число, используется для отслеживания версий (увеличивается с каждой новой сборкой)
- **versionName** — строка, отображается пользователю (например, "1.0.2")

### Файл: `android/app/build.gradle`

```gradle
android {
    compileSdkVersion 34

    defaultConfig {
        applicationId "com.example.myapp"
        minSdkVersion 21
        targetSdkVersion 34
        versionCode 1
        versionName "1.0.0"
    }
}
```

#### Как это работает:

- `versionCode` — увеличивается при каждой публикации в Play Store (например, 1 → 2 → 3)
- `versionName` — может быть любым, например, “1.0.0”, “2.1.0-beta” и т.д.

#### Практический совет:

Используйте автоматическую генерацию версий при помощи скриптов или CI/CD (например, GitHub Actions), чтобы не забывать обновлять `versionCode`.

## 3. Добавление источника для скачивания сторонних библиотек

Gradle использует **репозитории** для поиска и загрузки зависимостей. По умолчанию, Flutter-проекты используют:

```gradle
repositories {
    google()
    mavenCentral()
}
```

### Файл: `android/build.gradle`

```gradle
allprojects {
    repositories {
        google()
        mavenCentral()
    }
}
```

#### Что такое репозитории?

- **google()** — загружает зависимости из Google (например, AndroidX, Firebase)
- **mavenCentral()** — загружает зависимости из Maven Central (стандартный репозиторий)

#### Пример: Добавление библиотеки

В `android/app/build.gradle`:

```gradle
dependencies {
    implementation 'com.google.firebase:firebase-analytics:21.3.0'
}
```

Gradle автоматически скачает и подключит эту библиотеку, если она доступна в репозиториях.

## 4. Свойство `ndk.abiFilters`

**NDK (Native Development Kit)** — позволяет использовать C/C++ код в Android-приложениях. Свойство `abiFilters` определяет, под какие архитектуры будет собираться native-код.

### Пример:

```gradle
android {
    defaultConfig {
        ndk {
            abiFilters 'arm64-v8a', 'armeabi-v7a'
        }
    }
}
```

#### Что такое ABI?

ABI (Application Binary Interface) — это набор архитектур, под которые может быть собрано приложение:

- `arm64-v8a` — 64-битные ARM процессоры (современные устройства)
- `armeabi-v7a` — 32-битные ARM
- `x86_64` — для эмуляторов и некоторых устройств

#### Почему важно?

Если вы не указываете `abiFilters`, Gradle соберёт всё (что увеличит размер APK), но если вы укажете только нужные архитектуры, размер APK сократится.

## 5. Объявление Build Variants

**Build Variant** — это комбинация Build Type и Product Flavor. Позволяет создавать разные версии приложения: debug, release, staging и т.д.

### Пример:

```gradle
android {
    buildTypes {
        debug {
            // Настройки для debug-версии
        }
        release {
            minifyEnabled true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
        }
    }

    flavorDimensions "version"
    productFlavors {
        free {
            dimension "version"
        }
        paid {
            dimension "version"
        }
    }
}
```

#### Что такое Build Types?

- **debug** — используется при разработке, содержит отладочную информацию
- **release** — финальная версия для публикации

#### Что такое Product Flavors?

Используются для создания разных версий приложения:

- `free` — бесплатная версия с рекламой
- `paid` — платная версия без рекламы

### Результат:

Gradle создаст 4 варианта сборки: `freeDebug`, `freeRelease`, `paidDebug`, `paidRelease`.

## 6. Добавление зависимостей

В Gradle зависимости указываются в файле `build.gradle` внутри модуля (например, `android/app/build.gradle`).

### Пример:

```gradle
dependencies {
    implementation 'androidx.appcompat:appcompat:1.6.1'
    implementation 'com.google.android.material:material:1.9.0'
    implementation 'androidx.constraintlayout:constraintlayout:2.1.4'
    testImplementation 'junit:junit:4.13.2'
    androidTestImplementation 'androidx.test.ext:junit:1.1.5'
}
```

#### Типы зависимостей:

- `implementation` — подключает библиотеку в сборку
- `testImplementation` — используется только для тестов
- `androidTestImplementation` — используется для Android-тестов

### Важно:

В Flutter проектах зависимости указываются в `pubspec.yaml`, а Gradle получает их через `android/app/build.gradle`.

## Практическое задание

1. Создайте новый Flutter-проект.
2. Откройте файл `android/app/build.gradle`.
3. Измените `versionCode` и `versionName`.
4. Добавьте в зависимости библиотеку `firebase-analytics`.
5. Укажите `abiFilters` для `arm64-v8a` и `armeabi-v7a`.
6. Создайте build variant `staging` и `production`.
7. Проверьте, что Gradle корректно собирает проект (`flutter build apk`).
