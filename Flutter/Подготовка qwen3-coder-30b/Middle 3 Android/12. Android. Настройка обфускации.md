**Уровень:** Middle 3 Android  
**Цель:** Ознакомление с концепцией обфускации, настройкой правил, работой с эмулятором и ускорением процесса сборки через HAXM.

---

## 📌 Введение

Обфускация — это процесс изменения исходного кода или бинарных файлов таким образом, чтобы он стал труднее для понимания человеком, но при этом сохранял свою функциональность. Обфускация особенно важна при выпуске мобильных приложений, поскольку:
- Защищает исходный код от копирования.
- Уменьшает размер APK.
- Скрывает внутреннюю логику работы приложения.

В Android-разработке для обфускации используется **ProGuard** или его более современная версия — **R8**, которая используется по умолчанию в Gradle (включая Flutter).  
В Flutter, даже если вы не пишете нативный Kotlin/Java код, обфускация всё равно может быть полезна при сборке APK или AAB для продакшена.

## 1. Назначение обфускации

### 🔍 Что такое обфускация?

Обфускация — это процесс **сокрытия информации** в коде с целью:
- Уменьшения размера APK (удаление неиспользуемого кода).
- Затруднения анализа кода третьими лицами.
- Предотвращения копирования или взлома приложения.

### 🛡️ Как работает обфускация?

Обфускация изменяет:
- Имена классов, методов и полей на случайные (например, `a`, `b`, `c`).
- Удаляет ненужный код.
- Оптимизирует работу JVM/Android Runtime.

### 📦 Примеры эффектов:

**До обфускации:**
```java
public class UserAuthenticator {
    public boolean validateUser(String username, String password) {
        return true;
    }
}
```

**После обфускации (предположительно):**
```java
public class a {
    public boolean a(String var1, String var2) {
        return true;
    }
}
```

### 🧠 Важно:
- Обфускация работает только на **сборке Release**.
- Приложение должно быть полностью протестировано перед обфускацией — иначе могут возникнуть ошибки времени выполнения.

## 2. Подключение файла с правилами обфускации `proguard-rules.pro`

### 📁 Где находится файл?

Файл `proguard-rules.pro` обычно лежит в:
```
android/app/proguard-rules.pro
```

Если его нет — создайте его вручную.

### 🧩 Что делает этот файл?

Этот файл содержит **правила ProGuard**, которые указывают:
- Какие классы/методы **не нужно обфусцировать**.
- Какие классы должны быть **сохранены**.

### ✅ Пример содержимого:

```proguard
# Не обфусцировать классы из вашего приложения
-keep class com.yourcompany.yourapp.** { *; }

# Сохранить все классы, аннотированные @Keep
-keep @androidx.annotation.Keep class * { *; }

# Не обфусцировать Flutter-generated код
-keep class io.flutter.** { *; }

# Не трогать методы из MainActivity
-keepclassmembers class com.yourcompany.yourapp.MainActivity {
    public void *();
}

# Сохранить JSON-сериализацию (например, если используете json_serializable)
-keep class your_app.models.** { *; }
```

### 🔄 Как подключить?

В файле `android/app/build.gradle` убедитесь, что указано:

```gradle
buildTypes {
    release {
        minifyEnabled true
        proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
    }
}
```

> **Примечание:** `minifyEnabled true` — включает обфускацию.

## 3. Настройка исключений для обфускации

### 🚫 Что исключают из обфускации?

Некоторые классы и методы **должны остаться без изменений**, например:
- Классы, которые используются через reflection.
- Flutter-плагины.
- Классы, созданные с помощью `json_serializable`.
- Методы, вызываемые из native кода (JNI).
- Аннотации `@Keep`.

### 🧪 Пример исключений:

```proguard
# Не обфусцировать классы с аннотацией @Keep
-keep @androidx.annotation.Keep class * { *; }

# Не трогать Flutter-классы
-keep class io.flutter.** { *; }

# Не обфусцировать модели JSON
-keep class com.yourcompany.app.models.** { *; }

# Не трогать методы, вызываемые через reflection
-keepclassmembers class yourapp.** {
    public void *();
}

# Сохранить конструкторы для сериализации
-keepclassmembers class yourapp.models.** {
    <init>(...);
}
```

### 🔧 Совет:
Если вы получаете ошибки вроде `NoSuchMethodError`, `ClassNotFoundException` — это сигнал, что обфускация удалила нужный метод или класс.

## 4. Как добавить и настроить эмулятор Android

### 📱 Что такое эмулятор?

Эмулятор Android — это виртуальная среда, которая имитирует работу устройства Android. Используется для тестирования приложений без реального устройства.

### 🔧 Шаги создания эмулятора:

#### 1. Откройте **Android Studio**
#### 2. Перейдите в `Tools` → `AVD Manager`
#### 3. Нажмите **Create Virtual Device**
#### 4. Выберите устройство (например, Pixel 5)
#### 5. Выберите системный образ (например, Android 13 — API Level 33)
#### 6. Нажмите **Finish**

### 🧪 Запуск эмулятора:

1. В AVD Manager нажмите ▶️ (Run) рядом с нужным устройством.
2. Эмулятор запустится и будет готов к работе.

### 💡 Совет:
Для более быстрой работы используйте **x86-образы** вместо ARM (если ваш компьютер поддерживает x86).

## 5. Как работать с файловой системой эмулятора

### 🧰 Как получить доступ к файлам эмулятора?

1. В Android Studio откройте **Device File Explorer**:
   - `View` → `Tool Windows` → `Device File Explorer`
2. Выберите ваш эмулятор.
3. Навигация по `/data/data/com.yourcompany.app/files/`

### 🔍 Примеры:

- `/data/data/com.yourcompany.app/files/` — папка приложения.
- `/sdcard/` — внешняя память.
- `/data/local/tmp/` — временные файлы.

### 📁 Как копировать файлы?

Можно использовать команду через `adb`:
```bash
adb push local_file.txt /sdcard/
adb pull /sdcard/remote_file.txt .
```

### 🧪 Полезно для:
- Проверки сохранённых данных.
- Отладки файловых операций.

## 6. Ускорение с помощью HAXM. Описание. Поддерживаемые процессоры. Настройка

### ⚡ Что такое HAXM?

**Intel Hardware Accelerated Execution Manager (HAXM)** — это библиотека, которая позволяет эмулятору использовать **аппаратное ускорение** (Intel VT-x). Это значительно ускоряет работу эмулятора.

### ✅ Поддерживаемые процессоры:

- Intel Core i5/i7/i9
- Intel Xeon
- С поддержкой VT-x и VT-d

> **Важно:** HAXM не работает на процессорах AMD (используйте **Intel Hardware Accelerated Execution Manager** или **WSL2** на Windows).

### 🛠️ Установка HAXM:

1. Откройте **SDK Manager** в Android Studio.
2. Перейдите во вкладку **SDK Tools**.
3. Поставьте галочку напротив:
   - Intel x86 Emulator Accelerator (HAXM installer)
4. Нажмите Apply → OK

### 🧪 Проверка установки:

Запустите эмулятор и проверьте в логах:
```
HAX is working, and emulator runs in fast virt mode
```

Если видите это сообщение — всё работает.

## 🧠 Практическое задание

### 📌 Задание: Настройка обфускации и эмулятора в Flutter-проекте

1. Создайте новый Flutter проект.

3. Включите обфускацию в `build.gradle`.
4. Запустите сборку в режиме Release (`flutter build apk --release`).
5. Убедитесь, что приложение работает корректно.
6. Настройте эмулятор Android (используя AVD Manager).
7. Проверьте работу с файловой системой эмулятора через Device File Explorer.
8. Установите и настройте HAXM, если возможно.
