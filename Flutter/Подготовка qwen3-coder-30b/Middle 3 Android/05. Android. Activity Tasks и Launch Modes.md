# Лекция: Android Activity Tasks и Launch Modes

## Введение

При разработке мобильных приложений на Android важно понимать, как система управляет жизненным циклом Activity, особенно когда пользователь переходит между различными экранами. Понимание **Tasks** и **Launch Modes** позволяет создавать более стабильные и предсказуемые приложения.

В этой лекции мы рассмотрим:
1. Что такое **Tasks** и **Back Stack**
2. Параметр `launchMode` в AndroidManifest.xml
3. Какие существуют значения `launchMode`
4. Примеры работы с различными `launchMode` в Flutter приложениях (на Dart)

---

## 1. Tasks и Back Stack

### Что такое Task?

**Task** — это коллекция `Activity`, связанных между собой в одну логическую последовательность. Каждый раз, когда вы запускаете новое приложение или активность, система может создать новый task (если не указано иное) или добавить активность в существующий task.

Каждый task имеет:
- Один или несколько **Activity**
- Связанный **Back Stack** — стек, который хранит информацию о том, какие `Activity` были открыты и в каком порядке

### Что такое Back Stack?

**Back Stack** (или просто back stack) — это структура данных, реализующая принцип LIFO (Last In First Out), которая отслеживает активности, открытые пользователем в рамках одного task. Когда пользователь нажимает кнопку "Назад", система удаляет верхнюю активность из back stack и возвращает управление предыдущей активности.

Пример:
1. Открывается `MainActivity`
2. Переход в `ProfileActivity` — она добавляется в back stack
3. Переход в `SettingsActivity` — также добавляется в back stack

Теперь при нажатии "Назад":
- Сначала `SettingsActivity` удаляется из стека
- Затем `ProfileActivity`
- И наконец `MainActivity`

### Какие задачи могут существовать?

Существуют следующие типы tasks:
1. **Default task** — стандартный способ, когда каждая новая Activity добавляется в текущий task
2. **SingleTask** — активность создается только один раз в определенном task (если такая уже существует, то будет использована существующая)
3. **SingleInstance** — активность создается только один раз и находится в собственном task
4. **SingleTop** — если активность уже находится на вершине stack, то она не будет пересоздаваться

## 2. Параметр launchMode при запуске Activity

Параметр `launchMode` указывается в манифесте Android (`AndroidManifest.xml`) для определения того, как должна обрабатываться активность при запуске. Он влияет на то, как система управляет стеком задач и активностями.

### Значения launchMode

#### 1. `standard` (по умолчанию)

- Каждый раз, когда запускается Activity с этим mode, создается новый экземпляр.
- Новый экземпляр добавляется в текущий task.
- Используется по умолчанию для всех новых активностей.

**Пример:**

```xml
<activity
    android:name=".MainActivity"
    android:launchMode="standard" />
```

**Сценарий работы:**
1. Пользователь открывает `MainActivity`
2. Из нее открывается `SecondActivity`
3. Из `SecondActivity` снова открывается `SecondActivity` (новый экземпляр)
4. В back stack: `MainActivity` → `SecondActivity` → `SecondActivity`

#### 2. `singleTop`

- Если активность уже находится на вершине stack, новый экземпляр не создается.
- Если же она не находится на вершине — создается новый экземпляр и добавляется в стек.

**Пример:**

```xml
<activity
    android:name=".SecondActivity"
    android:launchMode="singleTop" />
```

**Сценарий:**
1. `MainActivity` → `SecondActivity`
2. Пользователь снова открывает `SecondActivity` через Intent
3. Новый экземпляр **не создается**, т.к. он уже на вершине stack
4. Если же мы открываем `ThirdActivity`, а затем `SecondActivity`, то новый экземпляр будет создан.

#### 3. `singleTask`

- Активность создается один раз и помещается в свой собственный task.
- Если активность уже существует в каком-то task, то этот task будет перемещен на передний план, а текущая активность не будет пересоздана.

**Пример:**

```xml
<activity
    android:name=".MainTaskActivity"
    android:launchMode="singleTask" />
```

**Сценарий работы:**
1. Пользователь запускает `MainTaskActivity`
2. Затем открывает `SecondActivity` (в другом task)
3. При повторном открытии `MainTaskActivity` — она не создается заново, а просто активируется из существующего task

#### 4. `singleInstance`

- Это самый строгий вариант: активность всегда находится в своем собственном task.
- Никогда не может быть частью другого task.
- Если вы запустите любую другую Activity в том же task, то она будет перенесена в новый task.

**Пример:**

```xml
<activity
    android:name=".UniqueActivity"
    android:launchMode="singleInstance" />
```

**Используется редко**, обычно для системных сервисов или специфичных случаев, например, экран блокировки.

## Практический пример использования launchMode в Flutter

В Flutter мы не можем напрямую изменить `launchMode`, потому что это свойство относится к AndroidManifest.xml. Однако можно использовать **Flutter Plugin** или управлять поведением через `Intent` или `PlatformChannel`.

Например, если вы хотите использовать `singleTop` для активности, вам нужно будет указать это в `AndroidManifest.xml`.

### Пример: Использование `singleTop`

Допустим, у вас есть экран профиля (`ProfileScreen`) и вы хотите, чтобы при повторном открытии он не пересоздавался.

1. В файле `android/app/src/main/AndroidManifest.xml` указываем:

```xml
<activity
    android:name=".MainActivity"
    android:launchMode="singleTop"
    android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.MAIN"/>
        <category android:name="android.intent.category.LAUNCHER"/>
    </intent-filter>
</activity>
```

2. При вызове экрана из другого места:

```dart
Navigator.push(
  context,
  MaterialPageRoute(builder: (context) => ProfileScreen()),
);
```

При этом, если `ProfileScreen` уже находится на вершине stack, то новый экземпляр не будет создан.

## Что происходит при использовании различных launchMode?

| Launch Mode       | Описание |
|-------------------|----------|
| `standard`        | Создается новая копия активности в текущем task. |
| `singleTop`       | Если активность уже на вершине stack, то она не пересоздается. |
| `singleTask`      | Активность создается только один раз и находится в собственном task. |
| `singleInstance`  | Активность всегда в отдельном task и никогда не может быть частью другого task. |

## Практическое задание

### Задача 1: Изучение поведения launchMode

Создайте простое Flutter-приложение с тремя экранами:

- `HomeScreen`
- `ProfileScreen`
- `SettingsScreen`

Используйте следующие настройки в `AndroidManifest.xml`:

```xml
<activity android:name=".HomeScreen" android:launchMode="standard"/>
<activity android:name=".ProfileScreen" android:launchMode="singleTop"/>
<activity android:name=".SettingsScreen" android:launchMode="singleTask"/>
```

Создайте навигацию между этими экранами и проверьте, как работает back stack при переходах.

После этого:
- Перейдите с `Home` → `Profile` → `Settings`
- Нажмите "Назад" несколько раз и проверьте, как работает стек.
- Попробуйте открыть `Profile` снова из `Settings`. Должна ли она пересоздаваться?
- Откройте `Settings` заново — должен ли новый task быть создан?

### Задача 2: Применение launchMode для улучшения UX

Создайте приложение с экраном авторизации (`LoginScreen`) и главным экраном (`MainScreen`). Используйте `singleTask` для `MainScreen`, чтобы при повторном входе пользователь не попадал в стек авторизации.
