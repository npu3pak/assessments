# Лекция: Android Logcat для Flutter разработчиков

## Введение

Logcat — это мощный инструмент отладки в экосистеме Android, который записывает и отображает системные сообщения и логи приложений. Для Flutter-разработчика, особенно на уровне Middle 3 Android, понимание работы с Logcat становится неотъемлемой частью процесса разработки, тестирования и устранения неполадок.

В этой лекции мы подробно рассмотрим назначение Logcat, способы фильтрации логов, уровни логирования и как их использовать в Flutter-приложениях. Мы также рассмотрим практические примеры на Dart/Flutter.

---

## 1. Назначение Logcat

### Что такое Logcat?

Logcat — это системный инструмент Android, который собирает и отображает логи, создаваемые приложениями и системными компонентами устройства. Эти логи содержат информацию о работе приложений, ошибках, предупреждениях, событиях и других сообщениях.

### Для чего используется Logcat?

Logcat применяется для:

- **Отладки приложений**: нахождение ошибок, которые не отображаются в интерфейсе.
- **Мониторинг состояния приложения**: отслеживание выполнения кода, логов, состояний потоков.
- **Анализа производительности**: выявление узких мест и проблем с производительностью.
- **Исследования поведения приложения**: в случаях, когда приложение работает не так, как ожидалось.
- **Сбор данных для отчетов**: когда нужно собрать информацию для разработчиков или тестировщиков.

### Как Logcat работает?

Logcat использует системный журнал (log buffer), в который записываются сообщения от различных источников:

- Системные компоненты Android
- Приложения, запущенные на устройстве
- Библиотеки и фреймворки

Каждое сообщение в Logcat имеет:
- **Уровень логирования** (verbose, debug, info, warning, error)
- **Тег** (уникальный идентификатор для группировки сообщений)
- **Приложение / процесс**, который отправил сообщение
- **Сообщение**

## 2. Фильтрация логов

### Зачем фильтровать логи?

Во время разработки может быть много информации в Logcat, поэтому фильтрация помогает сосредоточиться на нужных сообщениях и не терять время на шум.

### Какие типы фильтров существуют?

#### 1. По уровню логирования

Вы можете показывать только определённые уровни:

- **Verbose (V)** — самые подробные сообщения
- **Debug (D)** — отладочные сообщения
- **Info (I)** — информационные сообщения
- **Warning (W)** — предупреждения
- **Error (E)** — ошибки

#### 2. По тегу

Теги позволяют группировать сообщения по смыслу или модулю приложения.

#### 3. По имени процесса или приложения

Можно фильтровать логи конкретного приложения, например `com.example.myapp`.

#### 4. По тексту сообщения

Фильтрация по содержимому сообщения (например, `Network` или `API call`).

### Пример фильтрации в Android Studio

В Android Studio:

1. Откройте **Logcat** в нижней панели.
2. Нажмите на поле фильтра (рядом с иконкой лупы).
3. Выберите нужные фильтры:
   - По тегу: `Flutter` или `Dart`
   - По уровню: `Error`, `Warning`, `Debug`
   - По процессу: `com.example.myapp`

Пример:

```
Logcat Filter:
- Tag: Flutter
- Level: Debug
- Process: com.example.myapp
```

## 3. Уровни логирования

Logcat поддерживает следующие уровни логирования (в порядке возрастания важности):

| Уровень | Описание |
|--------|----------|
| **Verbose (V)** | Самый подробный уровень, используется для отладки |
| **Debug (D)** | Отладочные сообщения, помогают понять ход выполнения |
| **Info (I)** | Информационные сообщения, обычно используются для отслеживания важных событий |
| **Warning (W)** | Предупреждения, которые не являются критичными, но могут быть проблемой |
| **Error (E)** | Ошибки, которые нарушают работу приложения |

### Как использовать уровни в Flutter?

В Flutter-приложениях можно логировать сообщения с помощью `print()` или более продвинутых библиотек.

Пример:

```dart
import 'package:flutter/foundation.dart';

void main() {
  debugPrint('Debug message');
  print('Verbose message'); // по умолчанию это info в Logcat
}
```

Если вы используете `debugPrint`, то сообщения будут отображаться как **Debug**.

## 4. Логирование в Logcat

### Как логировать в Logcat из Flutter?

Flutter позволяет использовать:

- `print()` — по умолчанию выводит в консоль, но может быть перенаправлен в Logcat
- `debugPrint()` — более удобный способ для отладки, особенно если нужно подчеркнуть важность сообщения
- Специальные библиотеки: `logger`, `flutter_log` и т.д.

### Пример использования `print()` и `debugPrint()`

```dart
void main() {
  print("Это обычный print");
  debugPrint("Это debug сообщение");
}
```

В Logcat вы увидите:

```
I/flutter (12345): Это обычный print
D/flutter (12345): Это debug сообщение
```

Здесь:
- `I` — Info (по умолчанию)
- `D` — Debug

### Использование библиотеки `logger`

```yaml
dependencies:
  logger: ^1.4.0
```

```dart
import 'package:logger/logger.dart';

final logger = Logger();

void main() {
  logger.d('Debug message');
  logger.i('Info message');
  logger.w('Warning message');
  logger.e('Error message');
}
```

В Logcat:

```
D/Logger (12345): Debug message
I/Logger (12345): Info message
W/Logger (12345): Warning message
E/Logger (12345): Error message
```

## 5. Логирование с тегами

В Logcat можно использовать теги для группировки сообщений.

Пример с `logger`:

```dart
final logger = Logger(
  printer: PrettyPrinter(
    methodCount: 0,
    errorMethodCount: 8,
    lineLength: 120,
    colors: true,
    printEmojis: true,
  ),
);

void main() {
  logger.t('Network', 'Запрос к API');
}
```

В Logcat:

```
D/Network (12345): Запрос к API
```

## 6. Практическое применение Logcat в Flutter

Представим, что вы разрабатываете приложение с сетевыми вызовами.

### Пример: Логирование сетевых запросов

```dart
import 'package:http/http.dart' as http;
import 'package:logger/logger.dart';

final logger = Logger();

Future<void> fetchData() async {
  try {
    logger.i('Начинаю загрузку данных...');
    final response = await http.get(Uri.parse('https://api.example.com/data'));
    
    if (response.statusCode == 200) {
      logger.d('Данные получены успешно');
    } else {
      logger.w('Ошибка получения данных: ${response.statusCode}');
    }
  } catch (e) {
    logger.e('Ошибка при запросе: $e');
  }
}
```

При запуске приложения вы увидите в Logcat:

```
I/flutter (12345): Начинаю загрузку данных...
D/flutter (12345): Данные получены успешно
```

Если будет ошибка:

```
E/flutter (12345): Ошибка при запросе: SocketException: Connection failed
```
