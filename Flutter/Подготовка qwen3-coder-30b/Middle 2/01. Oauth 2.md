# Лекция: OAuth 2.0 — Полное руководство для Flutter-разработчика уровня Middle

---

## 📘 Общее описание OAuth 2.0

OAuth 2.0 — это открытый стандарт авторизации, который позволяет приложениям получать ограниченный доступ к ресурсам пользователя (например, данные профиля, файлы и т.п.) от сервиса (например, Google, Facebook или собственного сервера), без предоставления пароля. Это делает его идеальным для интеграции с системами аутентификации в мобильных приложениях.

**Принцип работы:**
1. Пользователь хочет получить доступ к ресурсам на стороннем сервисе.
2. Приложение направляет пользователя на сервер авторизации.
3. Пользователь авторизуется (вводит логин/пароль).
4. Сервер возвращает **access token**.
5. Приложение использует этот токен для доступа к защищённым ресурсам.

В Flutter это реализуется через сторонние библиотеки, такие как `oauth2` или `flutter_appauth`.

## 🔑 Access Token и подпись запросов

### Что такое Access Token?

Access token — это строка (обычно в формате JWT), которая действительна в течение определённого времени. Её можно использовать для доступа к ресурсам API.

Пример:

```dart
final accessToken = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...';
```

При каждом запросе к защищённому ресурсу нужно передавать этот токен в заголовке `Authorization`:

```dart
final response = await http.get(
  Uri.parse('https://api.example.com/user'),
  headers: {
    'Authorization': 'Bearer $accessToken',
  },
);
```

### Подпись запросов

Важно понимать, что access token не всегда содержит всю информацию о пользователе. Он просто указывает на то, что приложение имеет право получить доступ к определённым данным.

Если вы используете **OAuth 2.0 с JWT**, то токен может содержать полезную нагрузку (claims), содержащую ID пользователя или другие данные.

Пример запроса с JWT-токеном:

```dart
final token = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c';
final response = await http.get(
  Uri.parse('https://api.example.com/profile'),
  headers: {
    'Authorization': 'Bearer $token',
  },
);
```

### Безопасность

Access token должен быть передаваем только по HTTPS и никогда не сохраняться в незашифрованном виде. Также важно реализовать механизм обновления токена, чтобы избежать истечения срока действия.

## 🔄 Refresh Token и обновление access token

### Что такое Refresh Token?

Refresh token — это долгосрочный токен, который позволяет получить новый access token без повторной авторизации пользователя. Он выдаётся вместе с access token при первоначальной авторизации.

**Пример:**

```dart
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 3600,
  "refresh_token": "gfdhjklkjhgfdsdfghjklkjhgfdsdfghjkl",
  "token_type": "Bearer"
}
```

### Обновление access token

Когда токен истекает, приложение должно использовать refresh token для получения нового access token:

```dart
final response = await http.post(
  Uri.parse('https://oauth.example.com/token'),
  body: {
    'grant_type': 'refresh_token',
    'refresh_token': refreshToken,
    'client_id': 'your_client_id',
    'client_secret': 'your_client_secret',
  },
);
```

После успешного обновления, сервер возвращает новый `access_token`, возможно, новый `refresh_token`.

> ⚠️ Обратите внимание: refresh token может быть одноразовым или постоянным. Используйте его аккуратно.

## 🔐 СУДИР (Authorization Code Grant Flow)

### Что такое СУДИР?

СУДИР — это **Authorization Code Grant Flow**, один из четырёх способов OAuth 2.0, наиболее безопасный и часто используемый для мобильных приложений и серверов.

#### Принцип работы:

1. Приложение направляет пользователя на авторизационный сервер.
2. Пользователь авторизуется.
3. Сервер перенаправляет обратно с `code`.
4. Приложение обменивает `code` на `access_token` и `refresh_token`.

#### Сценарий:

```dart
// 1. Перенаправление пользователя на сервер авторизации
final url = Uri.parse(
  'https://accounts.google.com/o/oauth2/v2/auth?' +
      'client_id=your_client_id&' +
      'redirect_uri=com.yourapp.example.oauth2redirect&' +
      'response_type=code&' +
      'scope=email profile',
);

// Открываем URL в браузере (или через WebView)
launchUrl(url);

// 2. После авторизации сервер перенаправляет с кодом
// В нашем случае, это будет обработано через redirect URI

// 3. Обмениваем код на токены:
final response = await http.post(
  Uri.parse('https://oauth2.googleapis.com/token'),
  body: {
    'code': authorizationCode,
    'client_id': 'your_client_id',
    'client_secret': 'your_client_secret',
    'redirect_uri': 'com.yourapp.example.oauth2redirect',
    'grant_type': 'authorization_code',
  },
);
```

## 📱 СУДИР для мобильных приложений

### Особенности:

- В мобильных приложениях нет возможности скрыть `client_secret`, поэтому используются **PKCE (Proof Key for Code Exchange)** — механизм защиты от MITM-атак.
- PKCE добавляет дополнительный уровень безопасности.

#### Шаги для мобильного приложения:

1. Генерируем `code_verifier` и `code_challenge`.
2. Передаем `code_challenge` в URL авторизации.
3. После получения `authorization_code`, передаем `code_verifier` при обмене на токены.

#### Пример с flutter_appauth:

```dart
import 'package:flutter_appauth/flutter_appauth.dart';

final platform = FlutterAppAuth();
final result = await platform.authorizeAndExchangeCode(
  AuthorizationTokenRequest(
    'your_client_id',
    'https://accounts.google.com/o/oauth2/v2/auth',
    scopes: ['openid', 'profile'],
    redirectUrl: 'com.yourapp.example.oauth2redirect://oauth2callback',
    state: 'xyz123',
    additionalParameters: {
      'code_challenge': codeChallenge,
      'code_challenge_method': 'S256',
    },
  ),
);
```

> Важно: `code_verifier` должен быть сохранён, чтобы использовать его при обмене кода.

## 🌐 СУДИР для веб-приложений

### Основное отличие:

В веб-приложениях `client_secret` можно хранить на сервере, поэтому можно использовать более простой поток — **Authorization Code Grant без PKCE**.

#### Шаги:

1. Пользователь переходит по URL авторизации.
2. После авторизации сервер перенаправляет с `code`.
3. Сервер обменивает `code` на токены, используя `client_secret`.

```dart
final response = await http.post(
  Uri.parse('https://oauth2.example.com/token'),
  body: {
    'grant_type': 'authorization_code',
    'code': authorizationCode,
    'client_id': 'your_client_id',
    'client_secret': 'your_client_secret',
    'redirect_uri': 'http://localhost:3000/callback',
  },
);
```
