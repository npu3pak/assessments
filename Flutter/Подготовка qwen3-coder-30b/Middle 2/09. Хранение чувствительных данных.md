# Лекция 9: Хранение чувствительных данных в Flutter-приложениях

## Введение

В современном мире мобильной разработки вопросы безопасности и конфиденциальности данных становятся всё более актуальными. Особенно это касается хранения чувствительных данных, таких как:

- Токены доступа (access tokens)
- Логины и пароли
- API-ключи
- Персональные данные пользователей
- Ключи шифрования

Неправильное хранение этих данных может привести к серьёзным уязвимостям безопасности, утечке информации и даже взлому аккаунтов. В этой лекции мы рассмотрим, как безопасно хранить чувствительные данные в приложениях на Flutter.

---

## 1. Организация защищенного хранилища на iOS

### Что такое защищённое хранилище на iOS?

iOS предоставляет специальное хранилище под названием **Keychain Services**, которое используется для безопасного хранения конфиденциальных данных. Keychain — это система, обеспечивающая:

- Шифрование данных
- Защиту от копирования и извлечения из памяти
- Интеграцию с системой безопасности iOS (например, Touch ID / Face ID)

### Как работает Keychain в iOS?

Keychain использует криптографию на уровне операционной системы. Данные, записанные в Keychain, защищены:

- С помощью аппаратного шифрования
- Используя уникальные ключи для каждого приложения (если указано)
- Не подлежат резервному копированию без явного разрешения

Ключевые особенности Keychain:
- Данные хранятся в зашифрованном виде
- Доступ к данным возможен только через авторизованные вызовы
- Можно использовать для хранения паролей, токенов, сертификатов

### Пример использования Keychain через native код (iOS)

Если вы используете нативные методы, то данные можно сохранять и извлекать через `SecItemAdd` и `SecItemCopyMatching`. Но в Flutter рекомендуется использовать плагины.

## 2. Организация защищенного хранилища на Android

### Что такое защищённое хранилище на Android?

На Android защищённые данные хранятся с помощью механизма **Android Keystore** и **EncryptedSharedPreferences** (в зависимости от версии API).

### Android Keystore

Android Keystore — это система хранения ключей, которая позволяет:

- Генерировать и хранить криптографические ключи в защищённой среде
- Защитить их от извлечения через дампы памяти или внешние приложения
- Использовать для шифрования данных

Ключи, созданные в Keystore, связаны с конкретным устройством и не могут быть перенесены на другое.

### EncryptedSharedPreferences

Для хранения пар ключ-значение используется `EncryptedSharedPreferences`, который использует AES-256 шифрование и хранит данные в SharedPreferences.

### Пример использования EncryptedSharedPreferences (Java/Kotlin):

```java
// Kotlin
val masterKey = MasterKey.Builder(context, MasterKey.DEFAULT_MASTER_KEY_ALIAS)
    .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
    .build()

val sharedPreferences = EncryptedSharedPreferences.create(
    context,
    "secret_shared_prefs",
    masterKey,
    EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
    EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
)

val editor = sharedPreferences.edit()
editor.putString("token", "your_token_here")
editor.apply()
```

## 3. Плагин flutter_secure_storage

### Что такое flutter_secure_storage?

`flutter_secure_storage` — это популярный Flutter-плагин, который позволяет безопасно хранить данные на iOS и Android с использованием:

- **Keychain** на iOS
- **Keystore + EncryptedSharedPreferences** на Android

Этот плагин абстрагирует детали реализации и предоставляет простой интерфейс для работы с защищённым хранилищем.

### Установка

```yaml
dependencies:
  flutter_secure_storage: ^5.0.2
```

### Пример использования:

```dart
import 'package:flutter_secure_storage/flutter_secure_storage.dart';

final storage = FlutterSecureStorage();

// Сохранение данных
await storage.write(key: "token", value: "your_access_token");

// Чтение данных
String? token = await storage.read(key: "token");

// Удаление данных
await storage.delete(key: "token");
```

### Поддержка разных платформ

- **iOS**: Использует Keychain
- **Android**: Использует EncryptedSharedPreferences и Keystore

### Важные особенности:

- Данные не видны в обычных файлах или логах
- Не сохраняются в резервных копиях (если не указано)
- Поддерживает атрибуты для управления политиками хранения

## 4. Предотвращение резервного копирования для защищенного хранилища

### Почему это важно?

Резервные копии (например, iCloud или Google Drive) могут содержать данные, которые должны быть защищены. Если чувствительные данные попадают в резервную копию, они становятся уязвимыми.

### На iOS

На iOS можно указать, что данные не должны копироваться в iCloud:

```swift
// Swift
let keychainItem = [
    kSecClass: kSecClassGenericPassword,
    kSecAttrAccount: "token",
    kSecValueData: token.data(using: .utf8)!,
    kSecAttrAccessible: kSecAttrAccessibleWhenUnlockedThisDeviceOnly
] as [String : Any]

SecItemAdd(keychainItem as CFDictionary, nil)
```

В Flutter это делается автоматически через `flutter_secure_storage`, если не установлен флаг `accessible`.

### На Android

На Android можно указать `setEncryptionRequired(true)` и использовать `EncryptedSharedPreferences` с правильной конфигурацией.

### flutter_secure_storage

Плагин предоставляет параметр `accessible`:

```dart
await storage.write(
  key: "token",
  value: "your_token",
  accessible: KeychainAccessible.whenUnlockedThisDeviceOnly
);
```

Доступные значения:
- `whenUnlocked`
- `always`
- `whenUnlockedThisDeviceOnly`
- `alwaysThisDeviceOnly`

### Рекомендации:

Для хранения чувствительных данных (токенов, паролей) всегда используйте:

```dart
accessible: KeychainAccessible.whenUnlockedThisDeviceOnly
```

## 5. Передача чувствительных данных как параметров при сборке приложения

### Что такое передача данных на этапе сборки?

Иногда данные, такие как API-ключи или токены, не могут быть храниться в коде или файле конфигурации, особенно если приложение будет публичным. Для таких случаев используются:

- **Build-time secrets**
- **Environment variables**
- **Flutter build arguments**

### Способы передачи данных на этапе сборки

#### 1. Использование `--dart-define`

При сборке Flutter можно передавать переменные через `--dart-define`:

```bash
flutter build apk --dart-define=API_KEY=your_api_key_here
```

В коде:

```dart
String? apiKey = String.fromEnvironment('API_KEY');
```

#### 2. Использование `.env` файлов с помощью `dotenv`

Установите пакет:

```yaml
dependencies:
  dotenv: ^4.0.1
```

Создайте `.env` файл:

```env
API_KEY=your_api_key_here
```

Используйте в коде:

```dart
import 'package:dotenv/dotenv.dart';

final env = DotEnv().load();
String? apiKey = env['API_KEY'];
```

#### 3. Использование `build_runner` и генерации кода

Можно использовать генерацию кода для внедрения конфигураций на этапе сборки.

## Практическое задание

### Задача: Реализовать безопасное хранение токена доступа в Flutter-приложении

#### Цель:

Разработать простое приложение, которое:
1. Запрашивает у пользователя логин и пароль
2. После входа сохраняет access token в защищенное хранилище
3. При повторном запуске проверяет наличие токена
4. Отображает данные пользователя (если токен действителен)
5. Удаляет токен при выходе

#### Требования:

- Использовать `flutter_secure_storage`
- Не хранить чувствительные данные в обычных SharedPreferences или файлах
- Использовать `KeychainAccessible.whenUnlockedThisDeviceOnly`
- Предотвратить резервное копирование токена
- При выходе — удалять токен из хранилища

#### Пример структуры:

```dart
class AuthRepository {
  final FlutterSecureStorage storage = FlutterSecureStorage();

  Future<void> saveToken(String token) async {
    await storage.write(
      key: 'access_token',
      value: token,
      accessible: KeychainAccessible.whenUnlockedThisDeviceOnly,
    );
  }

  Future<String?> getToken() async {
    return await storage.read(key: 'access_token');
  }

  Future<void> removeToken() async {
    await storage.delete(key: 'access_token');
  }
}
```
