## Введение

**Crashlytics** — это мощный инструмент аналитики и мониторинга ошибок, разработанный компанией **Firebase**, который помогает разработчикам отслеживать сбои приложений, анализировать их причины и улучшать стабильность. Он особенно полезен в мобильной разработке (iOS и Android), где важно быстро реагировать на ошибки пользователей.

В рамках этой лекции мы рассмотрим:

- назначение Crashlytics,
- его настройку для Flutter на iOS и Android,
- как логировать ошибки и произвольную информацию,
- какие данные попадают в Crashlytics и как их фильтровать,
- как определить процент стабильных сессий,
- как отслеживать количество сбоев за последнее время,
- файлы DSYM для iOS,
- аналоги.

## 1. Назначение Crashlytics

**Crashlytics** — это инструмент, предназначенный для:

- **Отслеживания сбоев (crashes)** в приложениях на iOS и Android.
- **Анализа причин сбоев**, таких как стек вызовов, состояние устройства, версия ОС и т. д.
- **Получения отчетов о стабильности** приложения.
- **Мониторинга пользовательских сессий** и частоты возникновения ошибок.
- **Упрощения процесса исправления багов** через автоматическую группировку и фильтрацию данных.

### Основные преимущества:

- **Автоматическая сборка отчетов**: Crashlytics собирает данные о сбоях в реальном времени.
- **Интеграция с Firebase**: позволяет использовать все возможности Firebase в комплексе.
- **Поддержка Android и iOS**: универсальное решение для мобильных приложений.
- **Фильтрация и группировка**: можно фильтровать по версиям, устройствам, странам, стеку вызовов и т. д.

## 2. Настройка Crashlytics для Flutter на iOS и Android

Для начала нужно интегрировать Firebase в ваш Flutter-проект и активировать Crashlytics.

### Шаги:

#### 1. Создание проекта Firebase

1. Перейдите на [Firebase Console](https://console.firebase.google.com/)
2. Нажмите "Создать проект"
3. Введите имя проекта, включите Google Analytics (необязательно, но рекомендуется)
4. После создания проекта добавьте приложение для iOS и Android.

#### 2. Добавление Flutter-приложения в Firebase

1. В Firebase Console выберите ваш проект.
2. Нажмите на иконку Android или iOS (в зависимости от целевой платформы).
3. Следуйте инструкциям по добавлению приложения:
   - Для **Android**: укажите package name, загрузите `google-services.json`.
   - Для **iOS**: укажите bundle identifier, загрузите `GoogleService-Info.plist`.

#### 3. Установка зависимостей

В файле `pubspec.yaml` добавьте:

```yaml
dependencies:
  firebase_core: ^2.15.0
  firebase_crashlytics: ^3.4.1
```

#### 4. Инициализация Firebase в Flutter

В файле `main.dart`:

```dart
import 'package:firebase_core/firebase_core.dart';
import 'package:firebase_crashlytics/firebase_crashlytics.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp();

  // Обработка необработанных исключений
  FlutterError.onError = (errorDetails) {
    FirebaseCrashlytics.instance.recordFlutterError(errorDetails);
  };

  // Для ошибок в фоновых задачах
  PlatformDispatcher.instance.onUnhandledError = (Object error, StackTrace stack) {
    FirebaseCrashlytics.instance.recordError(error, stack);
  };

  runApp(MyApp());
}
```

#### 5. Настройка iOS

В файле `Runner/Info.plist` добавьте:

```xml
<key>FirebaseAppDelegateProxyEnabled</key>
<false/>
```

И в `Podfile` (если используете CocoaPods):

```ruby
target 'Runner' do
  use_frameworks!
  use_modular_headers!

  flutter_install_all_ios_pods File.dirname(File.realpath(__FILE__))
end

post_install do |installer|
  installer.pods_project.targets.each do |target|
    flutter_additional_ios_build_settings(target)
  end
end
```

#### 6. Настройка Android

В `android/app/src/main/AndroidManifest.xml` добавьте:

```xml
<meta-data
    android:name="firebase_crashlytics_collection_enabled"
    android:value="true" />
```

## 3. Логирование ошибок

### Важно: Crashlytics автоматически логирует необработанные исключения.

Однако можно вручную записывать данные, чтобы получить больше контекста:

```dart
try {
  // Некоторый код
  throw Exception('Произошла ошибка');
} catch (e, s) {
  FirebaseCrashlytics.instance.recordError(e, s);
}
```

### Запись произвольной информации

Если вы хотите отправить информацию о пользователе или контексте:

```dart
FirebaseCrashlytics.instance.setCustomKey('user_id', '12345');
FirebaseCrashlytics.instance.setCustomKey('session_id', 'abcde');
```

## 4. Логирование произвольной информации

Crashlytics позволяет записывать произвольные данные, которые могут помочь в анализе ошибки:

```dart
// Запись метаданных
FirebaseCrashlytics.instance.setCustomKey('screen', 'HomeScreen');
FirebaseCrashlytics.instance.setCustomKey('user_role', 'premium');

// Запись строки с логами
FirebaseCrashlytics.instance.log('Пользователь нажал кнопку "Оплатить"');
```

> Важно: данные сохраняются только в том случае, если произойдет сбой.

## 5. Какая информация попадает в Crashlytics. Как ее отфильтровать

### Что собирает Crashlytics:

- Стек вызовов (stack trace)
- Версия ОС
- Тип устройства
- Состояние памяти
- Имя приложения и версия
- Данные о пользователе (если установлены)
- Пользовательские метки (`setCustomKey`)

### Фильтрация:

В Firebase Console вы можете фильтровать данные по:

- Версии приложения
- ОС
- Устройству
- Статусу сессии
- Пользователям

## 6. Как определить процент стабильных сессий

**Стабильная сессия** — это сессия, в которой не произошло сбоев.

В Firebase Console:

1. Перейдите в раздел **Crashlytics**
2. Выберите вкладку **Sessions**
3. Там вы увидите:

   - **Total sessions**: общее количество сессий
   - **Crashed sessions**: количество сессий с ошибками
   - **Stable sessions**: стабильные сессии

**Формула:**

```
Процент стабильных сессий = (Stable Sessions / Total Sessions) * 100
```

## 8. Файлы DSYM для iOS

DSYM (Debug Symbol) файлы — это архивы с отладочной информацией, которые позволяют получить полный стек вызовов при сбое на iOS.

### Как они используются:

1. **Firebase Crashlytics** автоматически загружает DSYM-файлы, если они включены.
2. Вы можете вручную загрузить их через Firebase Console или с помощью Fastlane.

#### Настройка в Xcode:

В Build Settings укажите:

```
Debug Information Format = Dwarf with dSYM File
```
