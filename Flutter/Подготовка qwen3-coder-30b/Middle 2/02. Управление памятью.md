# Лекция: Управление памятью в Flutter (Dart)

## Введение

При разработке мобильных приложений, особенно на Flutter, важно понимать, как управляется память. Неправильное управление памятью может привести к утечкам, замедлению работы приложения, даже к его крашу. Особенно это актуально для мобильных устройств с ограниченными ресурсами.

В этой лекции мы рассмотрим:

1. Утечки памяти и их последствия.
2. ARC (Automatic Reference Counting) и его роль в управлении памятью.
3. GC (Garbage Collection) и его особенности.
4. Примеры на Dart и Flutter.

---

## 1. Утечки памяти. Причины и последствия

### Что такое утечка памяти?

Утечка памяти — это ситуация, при которой программа использует больше памяти, чем ей действительно нужно. Объекты, которые больше не используются, остаются в памяти, потому что на них по-прежнему есть ссылки.

### Причины утечек

1. **Циклические ссылки (Circular References)** — когда два или более объекта ссылаются друг на друга.
2. **Забытые слушатели событий** — например, подписка на `Stream` или `ChangeNotifier`, но отписка не происходит.
3. **Неправильное использование StatefulWidget** — если в `StatefulWidget` создаются объекты, которые не освобождаются при уничтожении виджета.
4. **Долгоживущие экземпляры** — например, глобальные или статические переменные, которые хранят данные и не обнуляются.

### Последствия

- Повышение потребления памяти.
- Снижение производительности.
- Падение приложения (OOM - Out of Memory).
- В iOS — Zombie Objects (объекты, которые уже были освобождены, но на них всё ещё идут ссылки).

### Zombie Objects в iOS

Zombie Objects — это объекты, которые были освобождены из памяти, но продолжают использоваться. Это может привести к падению приложения с ошибкой "EXC_BAD_ACCESS".

> В Flutter мы не работаем напрямую с Objective-C или Swift, но если вы используете native плагины, то понимание этих концепций важно.

## 2. ARC (Automatic Reference Counting)

### Что такое ARC?

ARC — это механизм автоматического управления памятью в языках, таких как Swift и Objective-C. Он отслеживает количество ссылок на объект и автоматически освобождает память, когда ссылок нет.

### Принцип работы

Каждый раз, когда вы создаете переменную или ссылку на объект, ARC увеличивает счетчик ссылок. Когда ссылка уничтожается, счетчик уменьшается. Если счетчик достигает нуля — объект удаляется.

### Преимущества

- Автоматическое управление памятью.
- Высокая производительность.
- Снижение рисков утечек.

### Недостатки

- Не подходит для всех случаев — например, циклические ссылки (в Swift можно использовать `weak` или `unowned`).
- Может быть неэффективным в некоторых сценариях работы с большими объемами данных.
  
> **В Dart ARC не используется. Dart использует GC.**

## 3. Garbage Collection (GC) в Dart

### Что такое Garbage Collection?

GC — это механизм автоматической очистки памяти, который освобождает объекты, на которые больше нет ссылок.

### Принцип работы

Dart использует **Generational Garbage Collector**. Это означает, что объекты разделяются на поколения:

- **New Space (молодое поколение)** — объекты, созданные недавно.
- **Old Space (старое поколение)** — объекты, которые выжили после нескольких сборок мусора.

GC запускается при достижении определенного порога использования памяти. Он проходит по объектам и удаляет те, на которые больше нет ссылок.

### Преимущества

- Упрощение разработки.
- Снижение рисков утечек.
- Не требует ручного управления памятью.

### Недостатки

- Может вызывать "паузы" в работе приложения (называемые "stop-the-world").
- Может быть менее эффективным, чем ручное управление (в некоторых случаях).

### Как работает GC в Flutter?

В Flutter GC запускается автоматически, но вы можете контролировать его поведение через настройки. Например, можно отключить GC при тестировании или изменить частоту сборки мусора.

Пример:

```dart
// Dart не позволяет напрямую управлять GC,
// но можно следить за потреблением памяти и обрабатывать большие объекты
void main() {
  runApp(MyApp());
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: MyHomePage(),
    );
  }
}

class MyHomePage extends StatefulWidget {
  @override
  _MyHomePageState createState() => _MyHomePageState();
}

class _MyHomePageState extends State<MyHomePage> {
  List<String> largeList = [];

  void addData() {
    for (int i = 0; i < 100000; i++) {
      largeList.add('Item $i');
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text("GC Demo")),
      body: Center(
        child: ElevatedButton(
          onPressed: addData,
          child: Text("Fill List"),
        ),
      ),
    );
  }
}
```

Если вы будете часто вызывать `addData()`, приложение начнет использовать больше памяти. GC в какой-то момент сработает и очистит старые объекты.

## Практическое задание

Создайте Flutter-приложение, которое демонстрирует:

1. Создание и утечку памяти через циклические ссылки (в Dart это не так очевидно, но можно использовать `WeakReference` или `ChangeNotifier`).
2. Использование `StreamController` и правильная отписка от потока.
3. Показать использование `Memory` и `Profiler` для анализа памяти (в Flutter DevTools).

### Пример утечки через ChangeNotifier:

```dart
class MyModel extends ChangeNotifier {
  String data = "Some data";

  void updateData(String newData) {
    data = newData;
    notifyListeners();
  }
}

class MyWidget extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return ChangeNotifierProvider(
      create: (_) => MyModel(),
      child: Consumer<MyModel>(
        builder: (_, model, __) {
          return Text(model.data);
        },
      ),
    );
  }
}
```

Если вы не вызываете `dispose()` у `ChangeNotifier`, или забудете отписаться от `Stream`, будет утечка памяти.
