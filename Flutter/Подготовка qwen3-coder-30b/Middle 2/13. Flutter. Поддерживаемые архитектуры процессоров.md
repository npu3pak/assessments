# Лекция: Flutter. Поддерживаемые архитектуры процессоров

## Введение

Прежде чем углубляться в тему поддерживаемых архитектур процессоров в контексте Flutter, важно понимать, что **Flutter** — это фреймворк для создания кроссплатформенных приложений, который позволяет разрабатывать как мобильные (iOS и Android), так и десктопные (Windows, macOS, Linux) и даже веб-приложения с помощью одного кода на языке Dart.

Однако, независимо от того, насколько универсальным является этот фреймворк, важно учитывать, какие **архитектуры процессоров** поддерживаются вашим приложением. Особенно это актуально при сборке Android-приложений, поскольку Android использует разные архитектуры процессоров (ARM, x86 и др.), и выбор поддерживаемых архитектур может влиять на размер APK, производительность и совместимость.

---

## 1. Что такое архитектура процессора?

**Архитектура процессора (или ISA — Instruction Set Architecture)** — это набор правил и инструкций, по которым работает микропроцессор. Она определяет:

- Какие команды может выполнять процессор.
- Какие регистры он имеет.
- Как организована память.
- Как происходит взаимодействие между CPU и другими компонентами системы.

Существует несколько основных архитектур процессоров:

| Тип архитектуры | Примеры | Описание |
|------------------|---------|----------|
| **ARM**          | ARMv7, ARM64 (AArch64) | Используется в большинстве смартфонов и планшетов на Android. Включает 32-битные (ARMv7) и 64-битные (ARM64) версии. |
| **x86**          | Intel x86, AMD x86 | Используется в компьютерах, эмуляторах Android и некоторых устройствах. |
| **MIPS**         | MIPS32, MIPS64 | Использовалась ранее в некоторых устройствах, но сейчас редко встречается. |
| **RISC-V**       | RISC-V 32/64-bit | Современная открытая архитектура, активно развивающаяся, но пока не распространена в мобильных устройствах. |

В контексте Flutter и Android-разработки **важно понимать**, какие из этих архитектур поддерживаются при сборке APK, и как это влияет на работу вашего приложения.

---

## 2. Какие архитектуры процессоров поддерживаются Flutter?

Flutter использует **нативную компиляцию** (на уровне Dart VM), которая позволяет генерировать исполняемые файлы под разные платформы и архитектуры. В Android-приложениях Flutter использует **AOT (Ahead-of-Time) компиляцию**, в результате которой из Dart-кода генерируется нативный код, который может быть выполнен на устройстве.

При сборке Flutter-приложений для Android используются **нативные библиотеки (native libraries)**, которые зависят от архитектуры процессора. Flutter поддерживает следующие архитектуры:

| Архитектура | Поддержка |
|-------------|-----------|
| **arm64-v8a** | ✅ Да (рекомендуется) |
| **armeabi-v7a** | ✅ Да (поддержка устаревшая, но всё ещё возможна) |
| **x86_64** | ✅ Да |
| **x86** | ✅ Да (редко используется) |

> 📌 Важно: Flutter не поддерживает архитектуры MIPS и RISC-V напрямую, но может использовать их через эмуляцию или специализированные сборки.

### Какие архитектуры используются в мобильных устройствах?

- **ARM64 (AArch64)** — стандарт для современных смартфонов.
- **ARMv7** — устаревшая, но всё ещё поддерживаемая архитектура для старых устройств.

Flutter генерирует **нативные библиотеки (libflutter.so)**, которые компилируются под определённые архитектуры. Эти библиотеки включаются в APK по умолчанию и могут быть использованы в зависимости от устройства.

## 3. Указание поддерживаемых архитектур при сборке Android-приложений

### Почему важно указывать поддерживаемые архитектуры?

При сборке Flutter-приложения для Android вы можете указать, **какие архитектуры процессоров** должен поддерживать ваше приложение. Это позволяет:

- Уменьшить размер APK.
- Улучшить производительность (если не включать ненужные библиотеки).
- Сократить время загрузки и установки.

### Как указать поддерживаемые архитектуры?

#### Способ 1: Через `android/app/build.gradle`

В файле `android/app/build.gradle` можно указать, какие архитектуры нужно включить в сборку:

```groovy
android {
    ...
    defaultConfig {
        ...
        ndk {
            abiFilters 'arm64-v8a', 'x86_64'
        }
    }
}
```

Это означает, что APK будет содержать только библиотеки для `arm64-v8a` и `x86_64`. Если вы не укажете `abiFilters`, то в APK будут включены **все архитектуры**, что увеличит размер.

#### Способ 2: Использование `flutter build apk --target-platform`

При сборке через командную строку можно указать платформы:

```bash
flutter build apk --target-platform=android-arm64,android-x64
```

Эта команда сгенерирует APK только для архитектур `arm64` и `x86_64`.

---

## 4. Пример: Как выглядит сборка с конкретными архитектурами

Допустим, мы хотим создать **APK** только для 64-битных устройств (ARM64), чтобы уменьшить размер.

1. Открываем `android/app/build.gradle`.
2. В секции `defaultConfig` добавляем:

```groovy
ndk {
    abiFilters 'arm64-v8a'
}
```

3. Запускаем сборку:

```bash
flutter build apk --target-platform=android-arm64
```

Теперь в APK будет только одна библиотека `libflutter.so` для ARM64, что уменьшает размер и ускоряет работу.

---

## 5. Что происходит при запуске на устройстве с другой архитектурой?

Если APK собрано только под одну архитектуру (например, `arm64-v8a`), а устройство использует другую (например, `x86_64), то:

- Приложение **не запустится**, если не будет включена эмуляция или не будет собрано под нужную архитектуру.
- Это может привести к ошибке:
  ```
  java.lang.UnsatisfiedLinkError: dlopen failed: library "libflutter.so" not found
  ```

---

## 6. Практические рекомендации

1. **Не включайте все архитектуры, если не нужно** — это увеличивает размер APK.
2. **Убедитесь, что вы тестируете на устройствах с нужной архитектурой**.
3. **Для старых устройств может потребоваться поддержка `armeabi-v7a`**, но это уже не рекомендуется.
4. **Если используете Firebase или другие зависимости, убедитесь, что они поддерживают нужные архитектуры**.

---

## 7. Полезные инструменты

- **APK Analyzer (Android Studio)** — позволяет проверить содержимое APK и узнать, какие библиотеки включены.
- **flutter build apk --verbose** — для получения детальной информации о сборке.
- `flutter doctor` — помогает проверить, установлен ли нужный SDK и т.д.
