# Лекция: Flutter. Работа в фоновом режиме

## Введение

Flutter — это мощная платформа для разработки кроссплатформенных приложений, включая мобильные (iOS и Android), веб-приложения и настольные программы. Однако, как и любое мобильное приложение, Flutter-приложение ограничено ресурсами и жизненным циклом операционной системы. Приложение может быть остановлено, свернуто или даже убито системой при неактивности.

В этом контексте **фоновая работа** становится критически важной для приложений, которым нужно выполнять задачи, даже когда пользователь не взаимодействует с ними. Это может включать:

- Получение и обработку данных из API.
- Синхронизацию данных.
- Отслеживание геопозиции.
- Уведомления.
- Регулярные задачи (например, отправка отчетов).

Flutter предоставляет несколько способов реализации фоновой работы:

1. **Headless execution**
2. **@pragma(vm:entry-point)**
3. **CallbackHandle**
4. **Плагин workmanager**

В этой лекции мы подробно рассмотрим каждую из этих концепций, а также приведем примеры на языке Dart и Flutter.

---

## 1. Headless execution

**Headless execution** — это способ выполнения Dart-кода вне контекста обычного UI-приложения. Он позволяет запускать Dart-логику в фоне, когда приложение не активно, но при этом оно не отображает пользовательский интерфейс.

Это особенно полезно для:

- Обработки фоновых задач.
- Планирования задач.
- Выполнения синхронизации данных.
- Использования в связке с планировщиками (например, `workmanager`).

### Как это работает

Когда приложение запускается в фоновом режиме, оно может использовать специальную точку входа — **headless Dart entry point**. Такой код выполняется в отдельном потоке и не связан с пользовательским интерфейсом.

### Пример

Вот простой пример headless-скрипта:

```dart
import 'package:flutter/foundation.dart';

void main() {
  // Запускаем headless-логику
  runApp(const MyApp());
}

@pragma('vm:entry-point')
void headlessCallback() {
  print('Выполняется headless-код');
  // Здесь можно выполнять любую логику, например:
  // fetchDataFromAPI();
  // saveDataToDB();
}
```

Обратите внимание на аннотацию `@pragma('vm:entry-point')` — она указывает компилятору, что функция `headlessCallback` должна быть доступна как точка входа для выполнения в фоновом режиме.

## 2. Директива @pragma(vm:entry-point)

### Что такое @pragma(vm:entry-point)?

Директива `@pragma('vm:entry-point')` — это специальная аннотация, используемая в Dart для обозначения функций, которые должны быть доступны для выполнения вне контекста обычного приложения. Это особенно важно при использовании плагинов, работающих в фоне (например, `workmanager`, `flutter_background_service`).

### Зачем она нужна?

При сборке Flutter-приложений для Android и iOS, Dart-код компилируется в нативный код. Однако, по умолчанию, компилятор может удалить функции, которые не вызываются напрямую из UI-логики (т.е. "мертвый код"). Чтобы предотвратить это, мы используем `@pragma(vm:entry-point)`.

### Пример использования

```dart
@pragma('vm:entry-point')
void backgroundTask() {
  print('Выполняется фоновая задача');
}
```

Такая функция может быть вызвана из плагина `workmanager`, например, при истечении таймера или при получении push-уведомления.

## 3. Запуск Dart-кода из приложения, запущенного в фоновом режиме

Приложение может быть запущено в фоновом режиме по разным причинам:

- Получение push-уведомлений.
- Планирование задач через `workmanager`.
- Срабатывание событий, таких как изменение геопозиции.

Все эти события могут вызывать выполнение Dart-кода в фоне. Однако, чтобы выполнить код, нужно сначала указать точку входа — то есть функцию, которая будет запускаться.

### CallbackHandle

**CallbackHandle** — это идентификатор, который используется для регистрации точки входа, когда приложение работает в фоновом режиме. Он позволяет Flutter-приложению получить ссылку на функцию, которую можно вызвать из фоновой среды (например, через `workmanager`).

### Как это работает

1. Вы регистрируете точку входа с помощью `CallbackHandle`.
2. Эта точка входа может быть вызвана из фонового контекста.
3. Приложение может использовать `BackgroundTask` или аналогичные механизмы для запуска функции в фоне.

### Пример

```dart
import 'package:flutter/material.dart';
import 'package:workmanager/workmanager.dart';

void main() {
  WidgetsFlutterBinding.ensureInitialized();
  Workmanager().initialize(callbackDispatcher, isInDebugMode: true);
  runApp(const MyApp());
}

@pragma('vm:entry-point')
void callbackDispatcher() {
  Workmanager().executeTask((taskName, inputData) {
    print("Выполняется задача в фоне: $taskName");
    return Future.value(true);
  });
}
```

В этом примере мы используем `callbackDispatcher`, который регистрирует точку входа для выполнения задач в фоне.

## 4. Плагин workmanager

**WorkManager** — это популярный плагин для Flutter, который позволяет выполнять задачи в фоновом режиме. Он работает на основе **Android WorkManager** и **iOS Background Task**.

### Основные возможности:

- Выполнение регулярных задач.
- Планирование задач по времени или событиям.
- Поддержка работы с push-уведомлениями.
- Выполнение задач даже при выключенной активности приложения.

### Установка

Добавьте в `pubspec.yaml`:

```yaml
dependencies:
  workmanager: ^0.5.1
```

### Использование

#### 1. Инициализация

```dart
import 'package:flutter/material.dart';
import 'package:workmanager/workmanager.dart';

void main() {
  WidgetsFlutterBinding.ensureInitialized();
  Workmanager().initialize(callbackDispatcher, isInDebugMode: true);
  runApp(const MyApp());
}
```

#### 2. Регистрация задачи

```dart
@pragma('vm:entry-point')
void callbackDispatcher() {
  Workmanager().executeTask((taskName, inputData) {
    print("Выполняется задача: $taskName");
    return Future.value(true);
  });
}
```

#### 3. Запуск задачи

```dart
Workmanager().registerPeriodicTask(
  "1",
  "periodic_task",
  frequency: Duration(minutes: 15),
);
```

Это зарегистрирует задачу, которая будет выполняться каждые 15 минут.

## Резюме

- **Headless execution** позволяет запускать Dart-логику вне UI.
- `@pragma(vm:entry-point)` используется для обозначения точек входа в фоновый режим.
- `CallbackHandle` — это способ регистрации функций, которые могут быть вызваны из фоновой среды.
- **Workmanager** — мощный плагин для выполнения задач в фоне с поддержкой Android и iOS.
