# Лекция: Публикация плагинов на pub.dev  
## Тема: Публикация Flutter-плагинов для расширения функциональности

---

### 🧠 Вступление

Публикация плагинов на **pub.dev** — это мощный инструмент, который позволяет делиться вашим кодом с сообществом разработчиков Flutter. Это не только способ поделиться своими достижениями, но и способ улучшить свою репутацию в экосистеме Flutter и получить обратную связь от других разработчиков.

В этой лекции мы рассмотрим, как подготовить плагин к публикации и как его опубликовать на **pub.dev**. Практические примеры будут приведены с использованием языка **Dart**, а также будут указаны соответствующие структуры проектов и правила, которые необходимо соблюдать.

---

## 🔧 1. Как подготовить плагин к публикации

### 1.1 Что такое Flutter-плагин?

Flutter-плагин — это пакет, который позволяет использовать функциональность, недоступную в чистом Dart (например, доступ к системным API, вызовы нативного кода, работу с камерой, GPS и т.п.). Плагины бывают двух типов:

- **Pure Dart** — плагин без прямого взаимодействия с нативным кодом.
- **Platform-specific** — содержит зависимости от нативных платформ (Android/iOS).

Для публикации на pub.dev нужно убедиться, что ваш плагин соответствует стандартам и имеет правильную структуру.

---

### 1.2 Структура Flutter-плагина

Пример структуры нового Flutter-плагина:

```
my_plugin/
├── lib/
│   └── my_plugin.dart
├── android/
│   └── src/
│       └── main/
│           └── java/
│               └── com/example/myplugin/
│                   └── MyPlugin.java
├── ios/
│   └── Classes/
│       └── MyPlugin.swift
├── example/
│   └── lib/
│       └── main.dart
├── pubspec.yaml
├── README.md
├── CHANGELOG.md
└── LICENSE
```

Важно: структура должна быть согласованной с тем, как Flutter понимает плагины. Внутри `lib/` должен находиться основной Dart-код, который будет экспортироваться как публичный API.

---

### 1.3 Файл pubspec.yaml

Это ключевой файл для любого пакета на pub.dev. Он определяет метаданные плагина и зависимости.

Пример содержимого `pubspec.yaml`:

```yaml
name: my_plugin
description: A new Flutter plugin for ...
version: 0.1.0
homepage: https://github.com/yourusername/my_plugin

environment:
  sdk: '>=2.18.0 <4.0.0'
  flutter: '>=3.0.0'

dependencies:
  flutter:
    sdk: flutter

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^2.0.0

# Для плагинов, использующих нативный код
flutter:
  plugin:
    platforms:
      android:
        package: com.example.myplugin
        pluginClass: MyPlugin
      ios:
        pluginClass: MyPlugin
```

### Пояснения:

- `name` — уникальное имя пакета (должно быть уникальным на pub.dev).
- `description` — описание.
- `version` — версия, формат SemVer (например, 1.0.0).
- `homepage` — ссылка на репозиторий.
- `environment` — ограничения по версиям Dart и Flutter.
- `flutter.plugin.platforms` — указывает, какие платформы поддерживает плагин.

---

### 1.4 README.md

Файл должен содержать:

- Краткое описание плагина
- Установку (например, через pubspec)
- Пример использования
- Список возможностей

Пример:

```markdown
# My Plugin

A simple Flutter plugin to do something amazing.

## Installation

Add this to your `pubspec.yaml`:

```yaml
dependencies:
  my_plugin: ^0.1.0
```

## Usage

```dart
import 'package:my_plugin/my_plugin.dart';

void main() {
  final result = MyPlugin.doSomething();
}
```
```

---

### 1.5 CHANGELOG.md

Файл должен содержать историю изменений версий.

Пример:

```markdown
# Changelog

## [0.1.0] - 2024-06-01

- Initial release.
```

---

### 1.6 LICENSE

Убедитесь, что у вас есть лицензия (например MIT, Apache 2.0), и она указана в файле `LICENSE`.

## 📦 2. Как опубликовать плагин

### 2.1 Подготовка к публикации

Перед тем как публиковать, нужно:

1. Убедиться, что все зависимости корректно указаны.
2. Проверить, что `pubspec.yaml` полностью соответствует требованиям.
3. Зарегистрироваться на [pub.dev](https://pub.dev/) через GitHub.
4. Создать аккаунт и авторизоваться через командную строку:

```bash
dart pub login
```

Если вы не используете `dart pub`, а используете `flutter pub`, то команда будет:

```bash
flutter pub login
```

---

### 2.2 Проверка на соответствие

Перед публикацией рекомендуется запустить проверку проекта:

```bash
flutter pub publish --dry-run
```

Это покажет, какие ошибки могут возникнуть при публикации.

---

### 2.3 Публикация

После прохождения всех проверок можно опубликовать плагин:

```bash
flutter pub publish
```

Если все успешно — ваш плагин будет доступен на [pub.dev](https://pub.dev/).

---

### 2.4 Обновление версий

Каждый раз, когда вы вносите изменения и хотите обновить публикацию, вам нужно:

1. Увеличить версию в `pubspec.yaml`
2. Запустить проверку:
   ```bash
   flutter pub publish --dry-run
   ```
3. Опубликовать:
   ```bash
   flutter pub publish
   ```

## 🛠️ Пример: Создание простого Flutter-плагина

### Шаг 1: Создаем проект

```bash
flutter create my_plugin
```

Удаляем ненужные файлы из `lib/`, оставляем только основной файл:

```dart
// lib/my_plugin.dart
library my_plugin;

class MyPlugin {
  static String doSomething() {
    return 'Hello from MyPlugin!';
  }
}
```

---

### Шаг 2: Добавляем зависимости в pubspec.yaml

```yaml
name: my_plugin
description: A simple Flutter plugin example.
version: 0.1.0
homepage: https://github.com/yourusername/my_plugin

environment:
  sdk: '>=2.18.0 <4.0.0'
  flutter: '>=3.0.0'

dependencies:
  flutter:
    sdk: flutter

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^2.0.0

flutter:
  plugin:
    platforms:
      android:
        package: com.example.myplugin
        pluginClass: MyPlugin
      ios:
        pluginClass: MyPlugin
```

---

### Шаг 3: Добавляем README.md, CHANGELOG.md и LICENSE

См. выше.

---

### Шаг 4: Публикуем

```bash
flutter pub publish --dry-run
flutter pub publish
```

Готово!

## ✅ Практическое задание

Создайте собственный Flutter-плагин, который:

1. Поддерживает Android и iOS.
2. Имеет минимальную реализацию нативного кода (например, вызывает Toast на Android или показывает сообщение на iOS).
3. Обеспечивает публичный Dart API для вызова.
4. Содержит README.md с примером использования.
5. Опубликуйте его на pub.dev.

> ⚠️ Убедитесь, что имя плагина уникально и не конфликтует с уже существующими.
