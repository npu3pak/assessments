## 1. Архитектура Flutter: Framework. Engine. Embedder

### Основные компоненты:

Flutter состоит из трех слоев:

1. **Embedder** — это часть, которая связывает Flutter с операционной системой. Это код на C/C++, который отвечает за:
   - Инициализацию графической подсистемы
   - Обработку событий (клавиатура, тач)
   - Отображение рендеринга на экране

2. **Engine** — это низкоуровневая часть Flutter, написанная на C++ и Dart VM. Она предоставляет:
   - Рендеринг (с помощью Skia)
   - Систему ввода/вывода
   - Управление памятью
   - Поддержку анимаций

3. **Framework** — это набор Dart-классов, предоставляющий API для разработчиков:
   - Widgets (виджеты)
   - Rendering (рендеринг)
   - Services (сервисы)
   - Animation (анимации)

### Пример: Как всё работает в Flutter приложении

При запуске Flutter-приложения:

1. **Embedder** инициализирует Flutter Engine.
2. Dart VM запускает `main()` функцию.
3. Framework строит дерево виджетов.
4. Engine отвечает за рендеринг и обработку событий.

## 2. 3 Trees Architecture: Widgets, Elements, Render Objects

Flutter использует **трехуровневую архитектуру** для представления интерфейса:

### 1. **Widgets Tree**
- Это дерево виджетов, описывающих визуальный интерфейс.
- Все виджеты — это **immutable** объекты (не изменяются после создания).
- Виджеты не содержат состояния (если это StatelessWidget), либо содержат его (StatefulWidget).

#### Пример:
```dart
class MyWidget extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Container(
      color: Colors.blue,
      child: Text('Hello'),
    );
  }
}
```

### 2. **Elements Tree**
- Это дерево, которое создаётся при вызове `build()`.
- Элементы — это экземпляры `Element`, соответствующие виджетам.
- Они содержат состояние и связаны с DOM-подобной структурой.

#### Пример:
При каждом вызове `build()` создаётся новый `Element`.

### 3. **Render Objects Tree**
- Это дерево, отвечающее за рендеринг.
- Каждый `RenderObject` знает о своём положении, размере и способе отображения.
- `RenderObject` — это низкоуровневая структура, которая взаимодействует с Skia.

#### Пример:
```dart
class MyRenderObject extends RenderBox {
  @override
  void performLayout() {
    size = constraints.biggest;
  }
}
```

### Связь между деревьями:

1. **Widgets** создают **Elements**
2. **Elements** создают **Render Objects**
3. **Render Objects** отображаются на экране

## 3. Bindings: SchedulerBinding, GestureBinding, RendererBinding и др.

Bindings — это классы, которые связывают Flutter с системой событий, рендерингом и т.п.

### 1. **SchedulerBinding**
- Управляет циклом событий.
- Обеспечивает выполнение задач в нужный момент времени (Frame, MicroTasks).
- Используется для анимаций и обновлений.

```dart
SchedulerBinding.instance.addPostFrameCallback((_) {
  print('Frame completed');
});
```

### 2. **GestureBinding**
- Обрабатывает жесты (клик, свайп, тап).
- Реализует систему событий ввода.

### 3. **RendererBinding**
- Отвечает за рендеринг.
- Управляет `RenderObject` деревом и его обновлением.

### 4. **WidgetsBinding**
- Основной binding, связывающий всё вместе.
- Используется для создания и обновления виджетов.

### 5. **ServicesBinding**
- Связывает Flutter с системными сервисами: клавиатура, геолокация, файлы и т.д.

## 4. Асинхронность. Event Loop. MicroTask. Event

Flutter использует **Event Loop**, управляемый Dart VM:

### Event Loop:
- Цикл событий в Flutter работает на основе `Event Queue` и `Microtask Queue`.
- В каждом кадре (`Frame`) обрабатываются:
  - События из очереди (`Event`)
  - Микрозадачи (`Microtask`)

### MicroTask:
- Задача, выполняющаяся **до следующего события**.
- Используется для асинхронных операций без блокировки UI.

```dart
Future.microtask(() {
  print('Microtask executed');
});
```

### Event:
- Задачи, которые выполняются в конце текущего кадра (например, `Future.delayed`).

```dart
Future.delayed(Duration(seconds: 1), () {
  print('Delayed task');
});
```

### Пример: Как это работает на практике

```dart
void main() {
  print('Start');

  Future.microtask(() {
    print('Microtask');
  });

  Future.delayed(Duration.zero, () {
    print('Future');
  });

  print('End');
}
```

**Вывод:**
```
Start
End
Microtask
Future
```

## 5. Внутренняя реализация анимаций. Ticker и TickerProvider

Flutter использует **Ticker** для управления анимациями.

### Ticker:
- Объект, который генерирует события через определённый интервал (часто 60 FPS).
- Применяется в `AnimationController`.

```dart
final animationController = AnimationController(
  duration: Duration(seconds: 1),
  vsync: this,
);

animationController.repeat();
```

### TickerProvider:
- Интерфейс, который предоставляет `Ticker`.
- Используется в `StatefulWidget`, чтобы дать `AnimationController` возможность создавать `Ticker`.

```dart
class MyWidget extends StatefulWidget {
  @override
  _MyWidgetState createState() => _MyWidgetState();
}

class _MyWidgetState extends State<MyWidget> with TickerProviderStateMixin {
  late AnimationController controller;

  @override
  void initState() {
    super.initState();
    controller = AnimationController(
      duration: Duration(seconds: 1),
      vsync: this,
    );
    controller.repeat();
  }

  @override
  void dispose() {
    controller.dispose();
    super.dispose();
  }
}
```

## 6. Sound Null Safety. Иерархия классов для nullable и не nullable типов

### Null Safety в Flutter (Dart 2.12+):
- Все типы по умолчанию **небезопасны** (`int`, `String`).
- Для безопасных типов используются `?`:

```dart
int? nullableInt; // может быть null
int notNullableInt = 5;
```

### Иерархия типов:

```dart
class Animal {
  String name;
  Animal(this.name);
}

class Dog extends Animal {
  Dog(String name) : super(name);

  void bark() => print('Woof!');
}
```

### Null Safety в контексте Flutter:
- В виджетах и `build` методах типы должны быть безопасными.
- Это помогает избежать `NullPointerException`.

```dart
class MyWidget extends StatelessWidget {
  final String? title;

  @override
  Widget build(BuildContext context) {
    return Text(title ?? 'No title');
  }
}
```
