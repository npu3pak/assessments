# **Flutter. Распространенные фреймворки и архитектуры**

## Введение

В мире разработки мобильных приложений Flutter стал одной из самых популярных платформ благодаря своей гибкости, производительности и простоте использования. Однако, как и в любой другой области разработки, важно не только знать, как создавать приложения, но и понимать, как правильно организовать код, чтобы он был поддерживаемым, масштабируемым и удобным для работы команды.

Одним из важнейших аспектов в разработке Flutter является **управление состоянием**. В этом контексте появляются такие инструменты, как **Riverpod**, **Provider**, **GetX**, и **Redux**. Они помогают решать проблемы управления данными в приложении, упрощая взаимодействие между виджетами и бизнес-логикой.

В данной лекции мы рассмотрим каждую из этих библиотек, их особенности, примеры использования и когда стоит выбрать ту или иную архитектуру. Мы также обсудим, как они работают в контексте Flutter и как использовать их для создания профессиональных приложений уровня Senior.

---

## 1. Riverpod

### Что такое Riverpod?

**Riverpod** — это современная библиотека управления состоянием для Flutter, разработанная командой **Flutter Community**. Она улучшает возможности `Provider`, исправляя ряд недостатков предыдущей системы.

### Основные особенности:

- **Не зависит от StatefulWidget**
- **Проще в тестировании**
- **Нет необходимости в `BuildContext` для получения данных**
- **Поддерживает асинхронные операции**
- **Более гибкая система зависимостей**

### Как использовать Riverpod?

Для начала добавим `riverpod` в `pubspec.yaml`:

```yaml
dependencies:
  flutter:
    sdk: flutter
  riverpod: ^2.4.0
```

#### Простой пример

Создадим простое состояние — количество кликов:

```dart
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

// Provider для хранения состояния
final counterProvider = StateNotifierProvider<CounterNotifier, int>((ref) {
  return CounterNotifier();
});

class CounterNotifier extends StateNotifier<int> {
  CounterNotifier() : super(0);

  void increment() => state++;
}

void main() {
  runApp(
    ProviderScope(
      child: MyApp(),
    ),
  );
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: Text('Riverpod Example')),
        body: Center(
          child: Consumer(
            builder: (context, watch, child) {
              final count = watch(counterProvider);
              return Text('$count');
            },
          ),
        ),
        floatingActionButton: FloatingActionButton(
          onPressed: () {
            context.read(counterProvider.notifier).increment();
          },
          child: Icon(Icons.add),
        ),
      ),
    );
  }
}
```

#### Что происходит?

- `counterProvider` — это `StateNotifierProvider`, который управляет состоянием типа `int`.
- `CounterNotifier` — класс, расширяющий `StateNotifier<int>`. Он отвечает за изменение состояния.
- В `MyApp` мы используем `Consumer` для отслеживания изменений в состоянии.
- `context.read(counterProvider.notifier)` — позволяет получить доступ к `CounterNotifier`.

### Преимущества Riverpod:

1. **Тестируемость** — легко тестировать `StateNotifier`.
2. **Без зависимости от `BuildContext`** — можно использовать в сервисах или других классах.
3. **Меньше boilerplate** — меньше кода для создания и использования провайдеров.

## 2. Provider

### Что такое Provider?

**Provider** — это один из самых популярных инструментов управления состоянием в Flutter. Он был разработан **Remi Rousselet** и основан на `InheritedWidget`.

### Как работает Provider?

`Provider` использует `InheritedWidget`, чтобы передавать данные между виджетами, но с более удобным API.

#### Пример использования Provider

```dart
import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

class Counter with ChangeNotifier {
  int _count = 0;
  int get count => _count;

  void increment() {
    _count++;
    notifyListeners();
  }
}

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => Counter(),
      child: MyApp(),
    ),
  );
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: Text('Provider Example')),
        body: Center(
          child: Consumer<Counter>(
            builder: (context, counter, child) {
              return Text('${counter.count}');
            },
          ),
        ),
        floatingActionButton: FloatingActionButton(
          onPressed: () => context.read<Counter>().increment(),
          child: Icon(Icons.add),
        ),
      ),
    );
  }
}
```

### Плюсы Provider:

- Простота использования.
- Хорошо интегрируется с `ChangeNotifier`.
- Подходит для небольших и средних проектов.

### Минусы Provider:

- Требует `BuildContext` для получения данных.
- Сложнее в тестировании, чем Riverpod.
- Может быть менее эффективным при больших объемах данных.

## 3. GetX

### Что такое GetX?

**GetX** — это мощная и простая библиотека для управления состоянием, маршрутизацией и зависимостями в Flutter. Она включает в себя:

- Управление состоянием (`GetxController`, `Obx`)
- Маршрутизацию
- Управление зависимостями (`Get.put`, `Get.lazyPut`)
- Локализацию
- Хранение данных (LocalStorage, SharedPreferences)

### Пример использования GetX

```dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';

class CounterController extends GetxController {
  var count = 0.obs;

  void increment() => count++;
}

void main() {
  runApp(
    GetMaterialApp(
      home: MyApp(),
    ),
  );
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('GetX Example')),
      body: Center(
        child: Obx(() => Text('${Get.find<CounterController>().count}')),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () => Get.find<CounterController>().increment(),
        child: Icon(Icons.add),
      ),
    );
  }
}
```

### Как зарегистрировать контроллер?

```dart
void main() {
  Get.put(CounterController()); // Регистрация
  runApp(GetMaterialApp(home: MyApp()));
}
```

### Преимущества GetX:

- Все в одном пакете.
- Быстрое внедрение зависимостей.
- Удобное управление состоянием с `Obx`.
- Легко тестируется.

### Недостатки:

- Может быть перегружена для простых проектов.
- Не всегда интуитивно понятна новичкам.

## 4. Redux

### Что такое Redux?

**Redux** — это паттерн управления состоянием, который был популяризирован в React. В Flutter он реализуется через библиотеку `redux` и `flutter_redux`.

### Основные компоненты:

1. **Store** — хранит состояние.
2. **Actions** — описывают изменения.
3. **Reducers** — чистые функции, обновляющие состояние.

#### Пример Redux

```dart
import 'package:flutter/material.dart';
import 'package:redux/redux.dart';
import 'package:flutter_redux/flutter_redux.dart';

// Состояние
class AppState {
  final int count;

  AppState({this.count = 0});
}

// Actions
class IncrementAction {}

// Reducer
AppState appReducer(AppState state, dynamic action) {
  if (action is IncrementAction) {
    return AppState(count: state.count + 1);
  }
  return state;
}

void main() {
  final store = Store<AppState>(
    appReducer,
    initialState: AppState(),
  );

  runApp(
    StoreProvider<AppState>(
      store: store,
      child: MyApp(),
    ),
  );
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: Text('Redux Example')),
        body: Center(
          child: StoreConnector<AppState, int>(
            converter: (store) => store.state.count,
            builder: (context, count) => Text('$count'),
          ),
        ),
        floatingActionButton: FloatingActionButton(
          onPressed: () => StoreProvider.of<AppState>(context)
              .dispatch(IncrementAction()),
          child: Icon(Icons.add),
        ),
      ),
    );
  }
}
```

### Преимущества Redux:

- Строгая архитектура.
- Легко тестировать.
- Отлично подходит для больших приложений.

### Недостатки:

- Много boilerplate.
- Сложнее начать работу.
- Не так интуитивен, как Riverpod или GetX.
