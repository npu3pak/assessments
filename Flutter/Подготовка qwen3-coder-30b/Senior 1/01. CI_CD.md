# Лекция: CI/CD для Flutter-разработчиков (Senior 1 уровень)

---

## Введение

**CI/CD (Continuous Integration / Continuous Delivery)** — это набор практик в разработке программного обеспечения, направленных на автоматизацию процессов сборки, тестирования и развертывания приложения. Основная цель CI/CD — ускорить выпуск продуктов, повысить качество кода и снизить риски, связанные с внесением изменений.

Для Flutter-разработчиков CI/CD особенно важен, поскольку мобильные приложения требуют сборки под разные платформы (iOS и Android), тестирования на разных устройствах и выкатывания обновлений в App Store / Google Play.

---

## 1. Понятие Continuous Integration

**Continuous Integration (CI)** — это практика, при которой разработчики регулярно интегрируют свой код в общую ветку проекта (например, `main` или `develop`). Каждая интеграция автоматически запускает процесс сборки и тестирования.

**Цель CI:**
- Обнаруживать ошибки на ранней стадии
- Снизить риски конфликтов между ветками
- Ускорить процесс разработки

**Пример:**  
Представьте, что у вас 5 разработчиков работают над одной функцией. Каждый день они пушат изменения в репозиторий. CI автоматически запускает сборку и тесты. Если один из разработчиков сломал код — ошибка будет замечена сразу, а не через несколько дней.

---

## 2. Понятие Continuous Delivery

**Continuous Delivery (CD)** — это расширение CI, которое гарантирует, что приложение может быть опубликовано в любое время. Это подразумевает автоматическую подготовку к релизу, например, сборку для разных платформ, тестирование и развертывание на сервер или в магазины.

**Цель CD:**
- Обеспечить готовность приложения к релизу
- Сделать релиз максимально простым и быстрым

**Пример:**  
После успешной сборки и тестирования Flutter-приложения, CI/CD система автоматически создает `.ipa` для iOS и `.apk` или `.aab` для Android, а также отправляет их в Firebase App Distribution или App Store Connect.

---

## 3. GitLab CI — Основные термины

GitLab CI — это инструмент непрерывной интеграции, который интегрирован с GitLab и позволяет автоматизировать процессы разработки через YAML-файлы.

### Основные понятия:

#### 🧠 Runner
Это сервер или машина, которая выполняет задачи CI/CD. В GitLab CI можно настроить свои runners (например, в облаке или локально), чтобы они запускали сборку и тесты.

#### 🧠 Pipeline
Это полный процесс CI/CD, который состоит из нескольких этапов.

#### 🧠 Stage
Этап — логическая группа задач, выполняемых последовательно. Например:
```yaml
stages:
  - build
  - test
  - deploy
```

#### 🧠 Job
Задача (job) — это отдельный шаг в стейже. Каждый job может содержать команды, зависимости и переменные.

#### 🧠 Artifact
Артефакт — это результат работы pipeline: например, скомпилированное приложение или отчет о тестировании.

## 4. Настройка сборки в .gitlab-ci.yml

`.gitlab-ci.yml` — это конфигурационный файл, который описывает все этапы CI/CD.

### Пример простого `.gitlab-ci.yml` для Flutter:

```yaml
# Основной pipeline
stages:
  - build
  - test
  - deploy

# Задача сборки
build_app:
  stage: build
  script:
    - flutter pub get
    - flutter build apk --release
    - flutter build ios --release --no-codesign
  artifacts:
    paths:
      - build/app/outputs/flutter-apk/app-release.apk
      - build/ios/iphoneos/Runner.app
    expire_in: 1 week

# Задача тестирования
test_app:
  stage: test
  script:
    - flutter pub get
    - flutter test
  artifacts:
    reports:
      junit: build/test-results.xml

# Задача деплоя в Firebase
deploy_to_firebase:
  stage: deploy
  script:
    - curl -sL https://firebase.tools | bash
    - firebase login --token $FIREBASE_TOKEN
    - firebase appdistribution:release $FIREBASE_APP_ID --app $FIREBASE_APP_ID --release-notes "New release" --groups testers
  only:
    - main
```

### Пояснение:

- `flutter pub get` — загружает зависимости.
- `flutter build apk` — собирает Android-приложение.
- `flutter build ios` — собирает iOS-приложение.
- `artifacts` — сохраняет файлы для использования на следующих этапах.
- `firebase appdistribution:release` — отправляет сборку в Firebase App Distribution.

## 5. GitLab CI Variables

Переменные позволяют хранить чувствительные данные (например, токены) и использовать их в CI/CD без риска их утечки.

### Настройка переменных:

1. В GitLab перейдите в **Project → Settings → CI / CD → Variables**
2. Добавьте переменную:
   - `FIREBASE_TOKEN` — токен Firebase CLI
   - `FIREBASE_APP_ID` — ID приложения в Firebase

### Использование:

```yaml
deploy_to_firebase:
  script:
    - firebase login --token $FIREBASE_TOKEN
```

## 6. Подключение нового runner

Чтобы GitLab CI мог выполнять задачи, нужен **runner**.

### Шаги:

1. Зайдите в **GitLab → Project → Settings → CI / CD → Runners**
2. Нажмите **Register new runner**
3. Скопируйте команду регистрации (например, для Linux):
   ```bash
   sudo gitlab-runner register \
     --url https://gitlab.example.com/ \
     --registration-token YOUR_TOKEN \
     --executor "shell" \
     --description "My Runner"
   ```

4. Установите runner:
   ```bash
   sudo apt-get install gitlab-runner
   ```

5. Запустите его:
   ```bash
   sudo gitlab-runner start
   ```

## 7. Fastlane — Возможности и настройка

**Fastlane** — это инструмент для автоматизации процессов, связанных с релизом мобильных приложений.

### Основные возможности:
- Автоматическая сборка (build)
- Отправка в App Store / Google Play
- Управление сертификатами
- Автоматическое обновление версий

### Установка:

```bash
sudo gem install fastlane
```

### Пример `Fastfile` для Flutter:

```ruby
lane :release do
  flutter_build(mode: "release")
  supply(
    apk: "./build/app/outputs/flutter-apk/app-release.apk",
    track: "internal"
  )
end
```

### Пример запуска:

```bash
fastlane release
```

## 8. Firebase App Distribution — Возможности и настройка

Firebase App Distribution — это инструмент для распространения бета-версий приложения.

### Возможности:
- Отправка сборки в Firebase
- Подключение тестировщиков (группы)
- Уведомления о новых релизах

### Настройка:

1. Зайдите в [Firebase Console](https://console.firebase.google.com/)
2. Создайте проект или выберите существующий
3. Включите App Distribution
4. Загрузите APK или AAB через Firebase CLI:
   ```bash
   firebase appdistribution:release $FIREBASE_APP_ID \
     --app $APP_ID \
     --release-notes "Bug fixes" \
     --groups testers
   ```

## Практическое задание

Создайте Flutter-проект и настройте CI/CD:

1. Залейте проект в GitLab
2. Создайте `.gitlab-ci.yml` с 3 этапами:
   - `build`
   - `test`
   - `deploy`
3. Настройте сборку для Android и iOS
4. Соберите артефакты и отправьте их в Firebase App Distribution
5. Добавьте переменные в GitLab (например, `FIREBASE_TOKEN`)
6. Подключите новый runner
