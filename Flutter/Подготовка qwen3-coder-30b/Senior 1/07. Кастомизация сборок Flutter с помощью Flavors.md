# Лекция: Кастомизация сборок Flutter с помощью Flavors

## Введение

В мире мобильной разработки важно уметь управлять различными версиями приложения — например, для разных окружений (dev, staging, prod) или различных целевых пользователей. Flutter предоставляет мощный инструмент для этой задачи — **Flavors** (или сборочные профили), которые позволяют создавать разные версии одного и того же проекта с разными конфигурациями, переменными окружения, ресурсами и даже логикой.

В данной лекции мы рассмотрим, как настроить проект Flutter под использование **Flavors**, включая:

- Настройку проекта Android/iOS
- Определение типа сборки
- Передачу информации о типе сборки во Flutter-модуль
- Сборку с указанием Flavor

---

## 1. Что такое Flavors?

**Flavor** — это способ создания различных сборок одного и того же проекта, которые могут иметь разные конфигурации, переменные окружения, ресурсы или логику.

Например:
- `dev` — для разработки с отладочными логами и тестовыми API
- `staging` — для предварительного тестирования перед релизом
- `prod` — для финальной версии, без отладки

Flutter использует механизм **build flavors**, который поддерживается как Android (через Build Variants), так и iOS (через Schemes).

## 2. Настройка проекта Android/iOS

### 2.1. Настройка Android Flavors

В файле `android/app/build.gradle` можно определить различные flavor-ы.

```gradle
android {
    compileSdkVersion 33

    defaultConfig {
        applicationId "com.example.myapp"
        minSdkVersion 21
        targetSdkVersion 33
        versionCode flutterVersionCode.toInteger()
        versionName flutterVersionName
    }

    flavorDimensions "environment"
    productFlavors {
        dev {
            dimension "environment"
            applicationIdSuffix ".dev"
            versionNameSuffix "-dev"
        }
        prod {
            dimension "environment"
            applicationIdSuffix ""
        }
    }

    buildTypes {
        release {
            signingConfig signingConfigs.release
        }
    }
}
```

- `flavorDimensions` — определяет группу flavor'ов (в данном случае, это "environment").
- `productFlavors` — задает конкретные flavor'ы (`dev`, `prod`).
- `applicationIdSuffix` — добавляется к ID приложения для каждого flavor.
- `versionNameSuffix` — позволяет отличать версии в названии.

### 2.2. Настройка iOS Flavors

В Xcode проекте нужно создать **Schemes** и **Configurations**:

1. Откройте проект в Xcode.
2. Выберите **Product > Schemes > Manage Schemes**.
3. Добавьте новые схемы (например, `MyApp-Dev`, `MyApp-Prod`).
4. Для каждой схемы создайте соответствующую конфигурацию (`Dev`, `Prod`) в разделе **Build Settings**.

В файле `ios/Runner.xcodeproj/project.pbxproj` можно увидеть, как связаны эти схемы и их конфигурации.

Также можно использовать [Flutter Flavorizr](https://pub.dev/packages/flavorizr) — инструмент для автоматической генерации flavor-ов на iOS/Android.

## 3. Определение типа сборки

Чтобы Flutter мог отличать тип сборки, мы должны передать информацию о flavor'e в код приложения. Это можно сделать через:

### 3.1. Использование `buildRunner` и генерации конфигураций

Создадим файл `lib/config/flavor_config.dart`:

```dart
class FlavorConfig {
  static const String dev = 'dev';
  static const String prod = 'prod';

  static String current = dev; // по умолчанию dev
}
```

При сборке мы можем передать значение в `main()` или использовать переменные окружения.

### 3.2. Использование `flutter pub run build_runner`

Если вы используете генерацию кода (например, через `freezed`, `json_serializable`), можно создать `build.yaml`:

```yaml
targets:
  $default:
    builders:
      flutter_gen:
        options:
          flavor: ${FLAVOR}
```

## 4. Передача информации о типе сборки во Flutter-модуль

Для передачи информации о Flavor в Flutter-код, можно использовать:

### 4.1. Переменные окружения

В `lib/main.dart` можно получить текущий flavor через переменную окружения или параметры сборки.

Например:

```dart
void main() {
  // Пример: получаем значение flavor из командной строки
  final String? flavor = String.fromEnvironment('FLAVOR', defaultValue: 'dev');
  
  FlavorConfig.current = flavor;
  
  runApp(MyApp());
}
```

Затем используем в коде:

```dart
if (FlavorConfig.current == FlavorConfig.dev) {
  print("Разработка");
} else if (FlavorConfig.current == FlavorConfig.prod) {
  print("Продакшн");
}
```

### 4.2. Конфигурационные файлы

Создайте конфигурационные файлы:

```dart
// lib/config/app_config.dart

class AppConfig {
  static const String apiUrl = 'https://api.example.com';
  static const String debugUrl = 'https://dev-api.example.com';

  static String get apiUrl => 
    FlavorConfig.current == FlavorConfig.dev 
      ? debugUrl 
      : apiUrl;
}
```

### 4.3. Использование `flutter_launcher_icons` и `flutter_native_splash` для разных ресурсов

Если вы хотите использовать разные иконки или экраны запуска для каждого flavor, можно настроить это через конфигурационные файлы.

Пример:

```yaml
# pubspec.yaml
dev_dependencies:
  flutter_launcher_icons: ^0.13.1

flutter_launcher_icons:
  android: true
  ios: true
  image_path: "assets/icons/icon_dev.png"
  adaptive_icon_background: "#ffffff"
  adaptive_icon_foreground: "assets/icons/adaptive_icon_dev.png"
```

## 5. Сборка с указанием Flavor

### 5.1. Сборка Android

Для сборки вручную:

```bash
flutter build apk --flavor dev
flutter build appbundle --flavor prod
```

Для запуска на конкретном flavor:

```bash
flutter run --flavor dev
```

### 5.2. Сборка iOS

```bash
flutter build ios --flavor dev --release
flutter run --flavor prod
```

> Важно: перед сборкой нужно убедиться, что соответствующие схемы и конфигурации настроены в Xcode.

## 6. Пример полного проекта с Flavor

### Структура проекта:

```
lib/
├── main_dev.dart
├── main_prod.dart
└── config/
    └── flavor_config.dart
```

#### `main_dev.dart`:
```dart
import 'package:flutter/material.dart';
import 'package:myapp/main.dart' as app;

void main() {
  FlavorConfig.current = FlavorConfig.dev;
  app.main();
}
```

#### `main_prod.dart`:
```dart
import 'package:flutter/material.dart';
import 'package:myapp/main.dart' as app;

void main() {
  FlavorConfig.current = FlavorConfig.prod;
  app.main();
}
```

#### `flavor_config.dart`:
```dart
class FlavorConfig {
  static const String dev = 'dev';
  static const String prod = 'prod';

  static String current = dev;
}
```

Теперь при запуске:

```bash
flutter run -t lib/main_dev.dart
```

или

```bash
flutter run -t lib/main_prod.dart
```

4. Добавьте разные цвета темы для разных flavor'ов.
5. Соберите приложение для обоих flavor'ов и проверьте, что все работает корректно.
