# Лекция: Подготовка сборок к публикации

## Введение

Подготовка сборки приложения к публикации — это один из важнейших этапов разработки мобильных приложений. Эта фаза включает в себя подготовку кода, настройку конфигураций, подписывание приложений и соответствие требованиям платформ (iOS и Android). В этой лекции мы рассмотрим подробно, как правильно готовить сборки под iOS и Android, а также как выполнять процесс подписания приложений для каждой из этих платформ.

---

## 1. Требования к публикации для iOS

### 1.1 Общие требования

При публикации приложения в App Store Apple строго контролирует качество и соответствие стандартам. Вот основные требования:

#### 📌 Требования к содержанию:
- Приложение должно быть оригинальным, не содержать вредоносного кода.
- Необходимо указать полное описание, скриншоты, категории, ключевые слова.
- В приложении должны быть четко прописаны политики конфиденциальности и условия использования.

#### 📌 Требования к UI/UX:
- Интерфейс должен соответствовать гайдлайнам Apple Human Interface Guidelines (HIG).
- Приложение должно корректно отображаться на всех устройствах и разрешениях.
- Соблюдение правил по использованию иконок, логотипов, цветовой схемы.

#### 📌 Требования к коду:
- Использование современных API и методов Swift/Objective-C.
- Приложение не должно использовать приватные API.
- Обязательное наличие валидации на уровне кода (например, обработка ошибок, безопасность данных).

#### 📌 Требования к безопасности:
- Все данные должны шифроваться при передаче и хранении.
- Нельзя использовать сторонние библиотеки с известными уязвимостями.
- Если используются сторонние сервисы, необходимо указать их использование в настройках.

#### 📌 Требования к функциональности:
- Приложение должно быть полностью работоспособным.
- Нет неработающих кнопок или функций.
- Необходимо проверить работу приложения в режиме сна, на разных устройствах и версиях iOS.

### 1.2 Подготовка к отправке

#### 📌 Сборка Release-версии
В Flutter вы можете собрать релизную сборку для iOS:

```bash
flutter build ios --release
```

Эта команда создаст `.xcarchive` файл, который будет использоваться при публикации.

#### 📌 Настройка проекта:
- Убедитесь, что `Info.plist` содержит все нужные поля: Bundle Identifier, Version, Build Number.
- Установите правильную `CFBundleShortVersionString` (версия) и `CFBundleVersion` (номер сборки).
- Убедитесь, что вы настроили `FlutterAppDelegate` и другие необходимые файлы.

#### 📌 Проверка на ошибки:
Используйте Xcode для проверки проекта перед публикацией:

1. Откройте `.xcodeproj` в Xcode.
2. Выберите `Product > Analyze`.
3. Устраните все найденные ошибки и предупреждения.

## 2. Требования к публикации для Android

### 2.1 Общие требования

При публикации в Google Play Store также есть строгие требования, которые необходимо соблюдать:

#### 📌 Содержание приложения:
- Приложение должно быть оригинальным и полезным.
- Указывается описание, скриншоты, категория, ключевые слова.
- Обязательно наличие политики конфиденциальности (даже если вы не собираете данные).

#### 📌 Требования к UI/UX:
- Приложение должно быть доступным (поддержка специальных возможностей).
- Интерфейс должен адаптироваться под различные размеры экранов.
- Не допускается использование неправильных иконок или логотипов.

#### 📌 Требования к безопасности:
- Все данные должны быть защищены (шифрование, безопасные соединения).
- Приложение не должно использовать устаревшие методы шифрования.
- Необходимо проверить, чтобы в приложении не было уязвимостей.

#### 📌 Требования к функциональности:
- Все функции должны быть реализованы корректно.
- Приложение не должно падать или зависать.
- Обязательно наличие валидации данных и обработки ошибок.

### 2.2 Подготовка к отправке

#### 📌 Создание подписи (Keystore)
Перед публикацией Android-приложения необходимо создать keystore файл:

```bash
keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Затем вы получите файл `upload-keystore.jks`, который будет использоваться при подписи.

#### 📌 Сборка Release-версии
В Flutter сборка релизной версии:

```bash
flutter build appbundle
```

или

```bash
flutter build apk --release
```

Файл `.aab` (Android App Bundle) — это рекомендуемый формат для публикации в Google Play.

#### 📌 Проверка и тестирование:
- Убедитесь, что все функции работают корректно.
- Протестируйте приложение на разных устройствах и версиях Android.
- Проверьте, чтобы не было лишних разрешений в `AndroidManifest.xml`.

## 3. Подписание приложений iOS

Подпись (code signing) — это процесс, который позволяет Apple убедиться, что приложение действительно было создано автором и не было изменено.

### 3.1 Что такое code signing?

Code signing — это механизм безопасности, используемый Apple для подтверждения подлинности приложения. Он позволяет:

- Подтвердить, что приложение не было изменено после выпуска.
- Убедиться, что оно было собрано с использованием корректного сертификата.
- Обеспечить защиту от вредоносных программ.

### 3.2 Требования для подписи

Для подписи iOS приложения вам потребуются:

1. **Apple Developer Account** (платная подписка)
2. **Certificate** (разработки или выпуска)
3. **Provisioning Profile**
4. **Xcode**

### 3.3 Шаги по подписи

#### 📌 Создание сертификата:
1. Перейдите на [developer.apple.com](https://developer.apple.com/)
2. Перейдите в раздел **Certificates, Identifiers & Profiles**
3. Нажмите **+** и выберите **iOS App Development** или **App Store Connect**
4. Загрузите CSR-файл из Xcode

#### 📌 Настройка Provisioning Profile:
1. Перейдите в **Profiles**
2. Нажмите **+** и выберите **App Store**
3. Выберите ваш Bundle ID
4. Скачайте профиль и установите его в Xcode

#### 📌 Подписание в Xcode:
1. Откройте проект в Xcode
2. Перейдите в **Signing & Capabilities**
3. Установите **Automatically manage signing** или вручную выберите нужные сертификаты и профили

#### 📌 Сборка для публикации:
1. В Xcode выберите **Product > Archive**
2. После архивации нажмите **Distribute App**
3. Выберите **App Store Connect** и следуйте инструкциям

## 4. Подписание приложений Android

### 4.1 Что такое подписывание APK?

Подписывание — это процесс, при котором вы используете ключ (keystore) для цифровой подписи вашего приложения. Это необходимо для:

- Подтверждения, что вы являетесь владельцем приложения.
- Предотвращения модификации приложения после публикации.

### 4.2 Шаги по созданию и использованию keystore

#### 📌 Создание keystore:
```bash
keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Эта команда создаст файл `upload-keystore.jks` — ваш ключ для подписи.

#### 📌 Хранение keystore:
- Сохраните его в безопасном месте.
- Не передавайте его никому.
- Если потеряете, вы не сможете обновить приложение.

#### 📌 Подпись APK:
После сборки `.apk` или `.aab`, можно подписать его:

```bash
jarsigner -verbose -sigalg SHA1withRSA -digestalg SHA1 -keystore ~/upload-keystore.jks build/app/outputs/flutter-apk/app-release.apk upload
```

Или используйте Android Studio:

1. Откройте **Build > Generate Signed Bundle / APK**
2. Выберите **APK** или **App Bundle**
3. Укажите путь к keystore и пароль
