# Лекция: Публикация Flutter-приложений в магазинах приложений

## Введение

Публикация мобильного приложения в магазинах — это не просто процесс загрузки файла. Это комплексный процесс, который включает подготовку, тестирование, сертификацию и последующую поддержку приложения на протяжении его жизненного цикла.

В этой лекции мы рассмотрим все аспекты публикации Flutter-приложений в Google Play, Huawei AppGallery, RuStore и Apple AppStore. Мы подробно разберем:

1. Как подготовить приложение к публикации
2. Как правильно управлять версиями и обновлениями
3. Временные рамки рассмотрения сборок
4. Отложенная публикация и бета-тестирование
5. ФорматыAppBundle и APK
6. Дополнительные возможности после публикации

## 1. Публикация новой версии приложения

### Подготовка к выпуску новой версии

Перед публикацией новой версии необходимо выполнить следующие шаги:

#### 1.1. Управление версиями

В Flutter-проектах версия указывается в файле `pubspec.yaml`:

```yaml
name: my_app
description: A new Flutter project.
version: 2.1.0+123  # формат version+build_number

publish_to: 'none'  # не публиковать автоматически в pub.dev

environment:
  sdk: ">=2.19.0 <3.0.0"

dependencies:
  flutter:
    sdk: flutter
```

- **version**: основная версия (например, `2.1.0`)
- **build_number**: номер сборки (например, `123`)

#### 1.2. Обновление метаданных

При каждой новой версии необходимо обновить:

```yaml
# pubspec.yaml
version: 2.1.0+123

flutter:
  uses-material-design: true
  # описание приложения для магазинов
  assets:
    - assets/images/
```

#### 1.3. Создание подписанных APK/AppBundle

Для публикации необходимо создать подписанные сборки:

```bash
# Для Android (AppBundle)
flutter build appbundle --release

# Для Android (APK)
flutter build apk --release
```

### Подготовка к отправке в магазины

#### Google Play Console

1. **Создание аккаунта**: Зарегистрируйтесь на [Google Play Console](https://play.google.com/console/)
2. **Оплата регистрации**: Сумма $25 (однократно)
3. **Загрузка ключа подписи**: 
   - Создайте `key.properties` файл:
   ```properties
   storePassword=your_store_password
   keyPassword=your_key_password
   keyAlias=key
   storeFile=/path/to/your/keystore.jks
   ```
   - Добавьте в `android/key.properties` (в .gitignore)
   - Обновите `android/app/build.gradle`:
   ```gradle
   // Внутри android {
   signingConfigs {
       release {
           keyAlias keystoreProperties['keyAlias']
           keyPassword keystoreProperties['keyPassword']
           storeFile keystoreProperties['storeFile'] ? file(keystoreProperties['storeFile']) : null
           storePassword keystoreProperties['storePassword']
       }
   }
   
   buildTypes {
       release {
           signingConfig signingConfigs.release
       }
   }
   ```

#### Apple Developer Program

1. **Регистрация в Apple Developer Program** ($99/год)
2. **Создание App ID**
3. **Создание сертификатов для подписи**
4. **Создание Provisioning Profile**

### Важные моменты

- **Имя пакета** (package name) должно быть уникальным
- **Логотип и изображения** должны соответствовать требованиям магазинов
- **Описание приложения** должно быть на всех поддерживаемых языках
- **Требования к качеству**: отсутствие рекламы, спама, вирусов

## 2. Время рассмотрения сборок

### Google Play

- **Обычное время рассмотрения**: от 1 до 3 дней
- **Критические ошибки**: могут быть отклонены немедленно
- **Сложные приложения**: могут занять до недели
- **Повторная отправка**: если отклонено, повторное рассмотрение начинается с нуля

### Huawei AppGallery

- **Время рассмотрения**: 1–3 дня
- **Модерация**: автоматическая и ручная проверка
- **Коммуникация**: иногда требуется доработка по запросам модератора

### RuStore

- **Время рассмотрения**: 2–5 дней
- **Автоматическая проверка**: с использованием антивирусных сканеров
- **Поддержка разработчиков**: доступ к личному кабинету и чату

### Apple AppStore

- **Обычное время рассмотрения**: 7–14 дней (в среднем)
- **Критические ошибки**: могут быть отклонены сразу
- **Сложные приложения**: до 30 дней и более
- **Дополнительные проверки**: для приложений с доступом к данным пользователя

## 3. Возможности отложенной публикации

### Google Play

1. Войдите в [Google Play Console](https://play.google.com/console/)
2. Перейдите в раздел "App content" > "Release management"
3. Выберите "Create release"
4. Укажите дату и время публикации
5. Нажмите "Save" и затем "Review"

Пример: отложенная публикация на 10.06.2025 в 10:00 по московскому времени

### Huawei AppGallery

1. Перейдите в раздел "App Management"
2. Выберите ваше приложение
3. В разделе "Release" выберите "Scheduled release"
4. Укажите дату и время публикации

### RuStore

1. После загрузки сборки выберите "Schedule publication"
2. Укажите дату и время публикации
3. Подтвердите действие

### Apple AppStore

1. При публикации в Xcode:
   - Выберите "Product" > "Archive"
   - Откроется Organizer
   - Нажмите "Distribute App"
   - Выберите "App Store Connect"
   - В настройках можно установить "Release date"

## 4. Возможности бета-тестирования

### Google Play (Internal Testing Track)

1. Создайте тестовую группу в Google Play Console
2. Загрузите APK или AppBundle
3. Пригласите пользователей по email
4. Установите приложение через ссылку для тестирования

Пример:
```bash
# Установка через командную строку (если есть доступ)
adb install -r app-release.apk
```

### Huawei AppGallery (Beta Testing)

1. В разделе "App Management" > "Beta testing"
2. Создайте тестовую группу
3. Загрузите APK
4. Разослите ссылку участникам

### RuStore (Beta Testing)

1. В личном кабинете RuStore
2. Выберите "Beta testing"
3. Загрузите сборку
4. Пригласите пользователей

### Apple AppStore (TestFlight)

1. В Xcode:
   - Выберите "Product" > "Archive"
   - Откроется Organizer
   - Нажмите "Distribute App"
   - Выберите "App Store Connect"
2. В iTunes Connect:
   - Перейдите в "My Apps"
   - Выберите ваше приложение
   - Перейдите в "TestFlight"
   - Добавьте бета-тестеров

### Пример Flutter-приложения с бета-тестированием

```dart
// main.dart
import 'package:flutter/material.dart';

void main() {
  runApp(MyApp());
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Beta Test App',
      home: Scaffold(
        appBar: AppBar(title: Text('Beta Test')),
        body: Center(child: Text('This is beta version')),
      ),
    );
  }
}
```

## 5. Формат AppBundle и его преобразование в APK

### Что такое Android App Bundle?

Android App Bundle — это новый формат распространения приложений, который позволяет Google Play автоматически оптимизировать сборку под конкретные устройства пользователя.

### Преимущества App Bundle

- **Меньший размер**: только нужные ресурсы для конкретного устройства
- **Упрощенная публикация**: один файл вместо нескольких APK
- **Оптимизация**: автоматическая генерация оптимизированных APK

### Создание AppBundle

```bash
flutter build appbundle --release
```

Результат: `build/app/outputs/bundle/release/app-release.aab`

### Преобразование App Bundle в APK (для тестирования)

```bash
# Установите Android Studio или используйте команду из SDK
# Важно: это не рекомендуется для публикации, но полезно для тестирования

# Используйте Android Studio:
# Build > Generate Signed Bundle / APK > APK

# Или через командную строку (если установлен Android SDK):
# android-sdk/build-tools/34.0.0/zipalign -v 4 app-release.aab app-release-aligned.aab
```

### Важно знать:

- **AppBundle не может быть установлен напрямую** на устройства (только через Google Play)
- **APK можно использовать для тестирования на устройствах** без Google Play
- **AppBundle требует подписи** перед отправкой в магазины

## 6. Дополнительные возможности кроме публикации

### Google Play

#### 1. **In-App Purchases**
```dart
// Внутри приложения (пример с flutter_inapp_purchase)
import 'package:flutter_inapp_purchase/flutter_inapp_purchase.dart';

class IAPManager {
  static Future<void> init() async {
    await FlutterInappPurchase.initConnection();
  }
  
  static Future<List<PurchaseItem>> getProducts() async {
    return await FlutterInappPurchase.getProducts(['product_id']);
  }
}
```

#### 2. **Analytics**
- Google Analytics for Firebase
- Crashlytics
- Performance Monitoring

#### 3. **App Signing**
Google автоматически подписывает ваше приложение, но вы можете использовать собственный ключ.

#### 4. **Dynamic Links**
Создание ссылок для перехода к конкретному контенту.

### Huawei AppGallery

#### 1. **Huawei AppLink**
- Ссылки для открытия приложения с определенным контентом
- Поддержка deep linking

#### 2. **Huawei Mobile Services (HMS)**
- Push-уведомления
- Аутентификация через Huawei ID
- Cloud Storage

#### 3. **App Update API**
- Автоматическое обновление приложений

### RuStore

#### 1. **Статистика и аналитика**
- Отслеживание установок, сессий, возвратов
- Сравнение с конкурентами

#### 2. **Push-уведомления**
- Настройка уведомлений через личный кабинет

### Apple AppStore

#### 1. **App Store Connect API**
Для автоматизации публикации и управления приложением.

#### 2. **App Store Review Guidelines**
Следование правилам для прохождения модерации.

#### 3. **App Store Optimization (ASO)**
- Оптимизация названия, описания, ключевых слов
- Ключевые слова для поиска
