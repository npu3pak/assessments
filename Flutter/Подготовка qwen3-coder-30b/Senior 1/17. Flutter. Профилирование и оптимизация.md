# **Flutter. Профилирование и оптимизация**

## **1. Введение в профилирование Flutter приложений**

В современном мире мобильной разработки важно не только создавать функциональные приложения, но и убедиться, что они работают эффективно, плавно и без задержек. Особенно это критично для Flutter-приложений, где пользовательский опыт напрямую зависит от производительности интерфейса.

**Профилирование** — это процесс сбора и анализа данных о работе приложения в реальном времени. Оно позволяет выявить узкие места, утечки памяти, низкую частоту кадров (jank), а также понять, как ресурсы системы используются во время выполнения.

Flutter предоставляет мощный набор инструментов для профилирования и оптимизации приложений:

- **DevTools** — встроенный интерфейс для анализа производительности.
- **Flutter Performance overlay** — отображение метрик производительности на экране.
- **CPU Profiler** — анализ времени выполнения методов.
- **Memory Profiler** — отслеживание потребления памяти и утечек.
- **Impeller** — рендеринг движок, который может влиять на производительность.

---

## **2. Возможности инструментария Flutter**

Flutter предоставляет несколько инструментов для профилирования:

### **DevTools**
DevTools — это веб-интерфейс для анализа производительности, памяти и работы приложения. Он может быть запущен с помощью команды:

```bash
flutter pub global run devtools
```

DevTools предоставляет следующие возможности:

- **Performance View** — отображает FPS, время выполнения, количество рендеринга.
- **CPU Profiler** — анализирует выполнение методов и показывает самые медленные участки.
- **Memory View** — отслеживает использование памяти, выявляет утечки.
- **Widget Inspector** — анализ структуры виджетов.
- **Network Profiler** — анализ сетевых вызовов.

### **Flutter DevTools в VS Code / Android Studio**
Если вы используете IDE, то DevTools можно запустить прямо из неё. Он интегрирован с Flutter и позволяет отслеживать производительность без необходимости запускать отдельный сервер.

## **3. Запуск в режиме профилирования**

Для запуска Flutter-приложения в режиме профилирования используется флаг `--profile`:

```bash
flutter run --profile
```

Этот флаг включает оптимизации производительности, но не отключает отладку. Он позволяет собирать данные для DevTools, такие как FPS, память и CPU-время.

Также можно использовать флаг `--release`:

```bash
flutter run --release
```

Он включает оптимизации компиляции и удаляет отладочные данные. Используется для тестирования реального поведения приложения на устройстве.

## **4. Performance Overlay и Performance View**

Performance Overlay — это визуальное представление метрик производительности, которое отображается на экране приложения.

### **Как включить Performance Overlay:**
В Flutter-приложении можно включить его через:

```dart
debugShowCheckedModeBanner = false;
```

или в `main.dart`:

```dart
void main() {
  runApp(MyApp());
}
```

А затем в `MaterialApp`:

```dart
MaterialApp(
  debugShowCheckedModeBanner: true, // Показывает Performance Overlay
  home: MyHomePage(),
);
```

### **Что показывает Performance Overlay:**

- **UI Thread** — поток отвечающий за обработку событий, рендеринг UI.
- **Raster Thread** — поток, отвечающий за растеризацию (перевод графики в пиксели).
- **Jank** — это "подтормаживания" в интерфейсе, когда кадры пропускаются.

### **Performance View в DevTools**

DevTools показывает:

- FPS (кадры в секунду)
- Frame time
- Memory usage
- CPU usage

## **5. CPU Profiler View. Поиск медленных участков кода**

CPU Profiler помогает выявить, какие методы выполняются дольше всего.

### **Как использовать CPU Profiler:**
1. Запустите приложение в режиме `--profile`.
2. Откройте DevTools.
3. Перейдите на вкладку "CPU Profiler".
4. Нажмите "Start" и выполните действия, которые хотели профилировать.

### **Пример:**

```dart
class SlowWidget extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    List<int> largeList = List.generate(100000, (index) => index);
    int sum = 0;
    for (int i = 0; i < largeList.length; i++) {
      sum += largeList[i];
    }
    return Text('Sum: $sum');
  }
}
```

Если вы запустите профилирование, то увидите, что `for`-цикл занимает много времени.

## **6. Memory View. Определение утечек памяти**

Memory Profiler помогает отследить использование памяти и найти утечки.

### **Что такое утечка памяти?**
Это ситуация, когда объекты остаются в памяти даже после того, как они больше не используются. Это может привести к исчерпанию ресурсов устройства.

### **Причины утечек:**

- Неправильное использование `StreamController` или `Timer`.
- Запоминание ссылок на объекты в `StatefulWidget`.
- Регистрация слушателей без отписки.
- Использование `static` переменных, которые не очищаются.

### **Пример утечки:**

```dart
class LeakExample extends StatefulWidget {
  @override
  _LeakExampleState createState() => _LeakExampleState();
}

class _LeakExampleState extends State<LeakExample> {
  StreamSubscription<dynamic>? subscription;

  @override
  void initState() {
    super.initState();
    subscription = Stream.periodic(Duration(seconds: 1)).listen((_) {
      print('Tick');
    });
  }

  // Нет dispose()
}
```

В этом случае `subscription` не будет освобожден, что приведет к утечке.

## **8. Shader compilation jank**

Flutter использует шейдеры для рендеринга графики. Иногда приложение может "подтормаживать" из-за того, что шейдеры компилируются в процессе работы.

### **Причины:**
- Использование сложных анимаций.
- Применение `BoxShadow`, `ClipRRect`, `Opacity` и т.д.
- Визуальные эффекты без предварительной компиляции.

### **Решения:**

1. Используйте `const` для статических виджетов.
2. Предварительно скомпилируйте шейдеры с помощью `ShaderMask`.
3. Не используйте сложные анимации на больших экранах.

## **9. Определение областей перерисовки экрана. Виджет RepaintBoundary**

Flutter обновляет только те области экрана, которые изменились. Но иногда происходит ненужная перерисовка.

### **Что такое repaint boundary?**
Это виджет, который ограничивает область перерисовки — то есть, если внутрь него вложен виджет, который часто меняется, он не будет вызывать перерисовку родительского элемента.

### **Пример:**

```dart
RepaintBoundary(
  child: Container(
    height: 100,
    width: 100,
    color: Colors.red,
    child: Text('I am repainted independently'),
  ),
)
```

## **10. Impeller. Преимущества и недостатки**

Impeller — это новый рендеринг движок в Flutter, который заменяет старый Skia.

### **Преимущества:**

- Более высокая производительность.
- Улучшенная поддержка 3D и анимаций.
- Лучшая интеграция с современными GPU.

### **Недостатки:**

- Может вызывать проблемы на старых устройствах.
- Не все виджеты поддерживаются.
- Время от времени может быть нестабильным.

### **Как включить/отключить Impeller:**

В `pubspec.yaml`:

```yaml
flutter:
  enableImpeller: true # или false
```

## **11. Performance best practices**

### **Основные рекомендации:**

1. **Используйте `const` для статических виджетов**
2. **Не используйте `setState()` без необходимости**
3. **Ограничивайте количество обновлений UI**
4. **Используйте `ListView.builder()` вместо `ListView()`**
5. **Не вызывайте тяжелые вычисления в `build()` методе**
6. **Отписывайтесь от подписок и таймеров**
7. **Не используйте `Stream` без необходимости**
