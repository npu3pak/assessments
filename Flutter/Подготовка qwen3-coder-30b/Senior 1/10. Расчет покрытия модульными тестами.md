# Лекция: Расчет покрытия модульными тестами

## Введение

Покрытие тестами (code coverage) — это метрика, показывающая, какой процент исходного кода приложения был протестирован с помощью автоматических тестов. Это важный инструмент для оценки качества тестирования и обеспечения надежности программного обеспечения.

В мире мобильной разработки на Flutter покрытие тестами особенно важно, потому что:
- Позволяет убедиться, что основные функции приложения работают корректно
- Снижает вероятность появления багов после изменений
- Упрощает рефакторинг и добавление новых функций
- Помогает придерживаться стандартов качества разработки

## 1. Что такое code coverage?

### Определение

**Code coverage (покрытие кода)** — это метрика, определяющая долю исходного кода программы, которая была выполнена во время тестирования.

В контексте Flutter и Dart:
- **Код покрывается**, если хотя бы один тест вызывает конкретную строку кода.
- **Непокрытый код** — это участки кода, которые никогда не были выполнены в процессе тестирования.

### Типы покрытия

1. **Строковое покрытие (Line Coverage)**  
   Показывает, какие строки кода были выполнены хотя бы один раз.

2. **Функциональное покрытие (Function Coverage)**  
   Определяет, какие функции были вызваны хотя бы один раз.

3. **Покрытие ветвлений (Branch Coverage)**  
   Показывает, какие условия и ветви кода были протестированы (например, if/else).

4. **Покрытие операторов (Statement Coverage)**  
   Аналогично строковому, но учитывает выполнение конкретных операторов.

### Почему важно?

- Увеличивает уверенность в работоспособности кода
- Помогает идентифицировать слабые места в логике
- Снижает вероятность багов после рефакторинга или новых фич
- Является частью практик Continuous Integration (CI)

## 2. Как рассчитать покрытие тестами для проекта

### Стандартный процесс расчета покрытия:

1. **Настройка среды**: Убедиться, что в проекте установлено необходимое ПО.
2. **Запуск тестов с отслеживанием покрытия**.
3. **Анализ результата**: Сгенерировать отчет о покрытии.
4. **Интерпретация результатов**: Определить, какие части кода не покрыты.

### Шаги по расчету покрытия в Flutter/Dart проекте:

#### 1. Установка необходимых инструментов

Для работы с покрытием в Dart/Flutter используется пакет `coverage`.

```bash
dart pub global activate coverage
```

Также может потребоваться установить `flutter_test` и `test`:

```yaml
dev_dependencies:
  flutter_test:
    sdk: flutter
  test: ^1.24.0
  coverage: ^1.6.0
```

#### 2. Запуск тестов с генерацией отчета о покрытии

Для того чтобы получить покрытие кода, нужно запустить тесты с определенным флагом.

##### Пример запуска:
```bash
flutter test --coverage --test-randomize-ordering-seed=random
```

Эта команда запускает все тесты и сохраняет данные о покрытии в файл `lcov.info`.

> **Примечание:** Если вы используете `flutter pub run test`, то команда будет такой же, но с другими флагами.

#### 3. Преобразование данных в читаемый формат

После запуска тестов создается файл `lcov.info`. Его можно использовать для генерации HTML-отчета:

```bash
genhtml lcov.info -o coverage_report
```

или через пакет `coverage`:

```bash
dart pub global run coverage:format_coverage --packages=.packages --report-on=lib --lcov -o lcov.info
```

### Пример структуры отчета

Файл `lcov.info` содержит информацию о покрытии в следующем формате:

```
TN:TestApp
SF:lib/main.dart
FN:1,main
FNDA:1,main
FNF:1
FNH:1
DA:1,1
DA:2,1
DA:3,0
LF:3
LH:2
end_of_record
```

Здесь:
- `SF` — путь к файлу
- `DA` — строки и количество вызовов
- `LF`, `LH` — общее количество строк и покрытых строк

## 3. Как сгенерировать отчет о покрытии тестами

### Вариант 1: Использование `flutter test --coverage`

```bash
flutter test --coverage --test-randomize-ordering-seed=random
```

Эта команда:
- Запускает все тесты в проекте
- Генерирует файл `lcov.info` с информацией о покрытии

#### После этого можно использовать `genhtml` или другие инструменты для визуализации:

```bash
# Установите genhtml (если не установлен)
sudo apt-get install lcov

# Генерация HTML-отчета
genhtml lcov.info -o coverage_report
```

Открытие отчета:
```bash
xdg-open coverage_report/index.html
```

### Вариант 2: Использование `coverage` пакета напрямую

Установка:
```bash
dart pub global activate coverage
```

Запуск тестов с генерацией покрытия:

```bash
flutter test --coverage
dart pub global run coverage:format_coverage --packages=.packages --report-on=lib --lcov -o lcov.info
```

### Вариант 3: Автоматизация через CI/CD (GitHub Actions, GitLab CI)

В примере ниже показано, как настроить CI для генерации отчета о покрытии:

```yaml
name: Test Coverage

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Setup Flutter
        uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.19.0'

      - name: Install dependencies
        run: flutter pub get

      - name: Run tests with coverage
        run: flutter test --coverage --test-randomize-ordering-seed=random

      - name: Format coverage report
        run: |
          dart pub global activate coverage
          dart pub global run coverage:format_coverage --packages=.packages --report-on=lib --lcov -o lcov.info

      - name: Upload coverage to Codecov
        uses: codecov/codecov-action@v3
        with:
          file: ./lcov.info
```

## 4. Пример практического кода и покрытия

Рассмотрим пример простого Flutter-приложения с логикой:

```dart
// lib/calculator.dart

class Calculator {
  int add(int a, int b) => a + b;

  int subtract(int a, int b) => a - b;

  double divide(double a, double b) {
    if (b == 0) {
      throw Exception("Division by zero");
    }
    return a / b;
  }

  bool isEven(int number) {
    return number % 2 == 0;
  }
}
```

### Тесты:

```dart
// test/calculator_test.dart

import 'package:flutter_test/flutter_test.dart';
import 'package:myapp/calculator.dart';

void main() {
  group('Calculator', () {
    late Calculator calc;

    setUp(() {
      calc = Calculator();
    });

    test('add returns correct result', () {
      expect(calc.add(2, 3), equals(5));
    });

    test('subtract returns correct result', () {
      expect(calc.subtract(5, 3), equals(2));
    });

    test('divide throws exception when dividing by zero', () {
      expect(
        () => calc.divide(10, 0),
        throwsA(isA<Exception>()),
      );
    });

    test('divide returns correct result', () {
      expect(calc.divide(10, 2), equals(5.0));
    });

    test('isEven returns true for even numbers', () {
      expect(calc.isEven(4), isTrue);
    });

    test('isEven returns false for odd numbers', () {
      expect(calc.isEven(3), isFalse);
    });
  });
}
```

При запуске тестов с флагом `--coverage` и генерации отчета, вы получите полную информацию о том, какие строки были покрыты.
