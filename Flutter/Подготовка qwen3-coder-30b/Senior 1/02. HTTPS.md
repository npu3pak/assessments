# Лекция: HTTPS

## 02. HTTPS — Защита данных в мобильной разработке

HTTPS (HyperText Transfer Protocol Secure) — это расширение протокола HTTP, которое обеспечивает безопасную передачу данных между клиентом и сервером с помощью шифрования. Он применяется повсеместно в мобильных приложениях Flutter, особенно когда необходимо обмениваться чувствительной информацией, такой как логины, пароли, платежные данные и т.д.

---

## 1. Краткое описание HTTPS

HTTPS — это комбинация HTTP (протокол передачи гипертекста) и SSL/TLS (Secure Sockets Layer / Transport Layer Security). Он обеспечивает:

- **Шифрование** данных, передаваемых между клиентом и сервером.
- **Аутентификацию** сервера (чтобы убедиться, что вы подключаетесь к правильному сайту).
- **Целостность данных** — гарантирует, что данные не были изменены в процессе передачи.

HTTPS работает поверх TCP/IP. Важно понимать, что HTTPS не защищает от всех угроз, но значительно повышает уровень безопасности по сравнению с обычным HTTP.

### Пример:
В Flutter вы можете делать API-запросы к серверу, например:

```dart
import 'package:http/http.dart' as http;

Future<void> fetchData() async {
  final response = await http.get(
    Uri.parse('https://api.example.com/data'),
  );
  if (response.statusCode == 200) {
    print(response.body);
  }
}
```

В этом примере используется `https`, и данные будут защищены.

## 2. TLS Handshake

TLS Handshake — это процесс установления безопасного соединения между клиентом и сервером, который происходит до передачи фактических данных.

### Этапы TLS Handshake:

1. **Client Hello**:
   - Клиент отправляет серверу список поддерживаемых версий TLS, набор шифров и случайные данные (nonce).

2. **Server Hello**:
   - Сервер отвечает выбранной версией TLS, используемым шифром и своим случайным значением.

3. **Certificate Exchange**:
   - Сервер отправляет свой SSL-сертификат, который включает публичный ключ и информацию о владельце.

4. **Server Hello Done**:
   - Сервер завершает первый этап рукопожатия.

5. **Client Key Exchange**:
   - Клиент использует публичный ключ сервера для шифрования сессионного ключа, который затем отправляется серверу.

6. **Finished**:
   - Обе стороны посылают подтверждения, что рукопожатие прошло успешно и они могут начать обмен данными.

### Почему важно понимать TLS Handshake?

При разработке приложений важно учитывать, как происходит подключение к серверам. Если сертификат недействителен или устарел — может возникнуть ошибка, например:

```
Exception: HandshakeException: Handshake error in client (OS Error:
CERTIFICATE_VERIFY_FAILED
```

Это может происходить при использовании неправильного времени на устройстве, самоподписанных сертификатах или вредоносных сетях.

## 3. Атака Man-in-the-middle

**Man-in-the-middle (MITM)** — это атака, при которой злоумышленник перехватывает и может изменять связь между клиентом и сервером без их знания.

### Как происходит MITM-атака:

1. Пользователь подключается к ненадежной сети (например, публичному Wi-Fi).
2. Злоумышленник перехватывает трафик.
3. Он может подделывать данные, пересылать их дальше или даже модифицировать.

### Пример в Flutter:

Если вы используете `http` или `dio` без правильной проверки сертификатов, ваше приложение может быть уязвимо к MITM-атакам.

Например, если сервер использует самоподписанный сертификат, а вы не проверяете его:

```dart
// НЕБЕЗОПАСНЫЙ ПРИМЕР
final response = await http.get(
  Uri.parse('https://api.example.com/data'),
  headers: {'Authorization': 'Bearer token'},
);
```

Для защиты от MITM-атак используются:

- **SSL Pinning** (см. ниже).
- Проверка сертификатов и их валидность.
- Использование доверенных центров сертификации.

## 4. SSL Pinning

**SSL Pinning** — это метод защиты от MITM-атак, при котором клиент проверяет, что подключается именно к определенному серверу, используя его публичный ключ или сертификат.

### Зачем нужно SSL Pinning?

- Защита от использования поддельных сертификатов.
- Повышение безопасности при передаче конфиденциальных данных.
- Используется особенно в финансовых и медицинских приложениях.

### Реализация SSL Pinning в Dart/Flutter:

Для реализации SSL Pinning в Flutter можно использовать библиотеку `http` с кастомным `HttpClient`, либо `dio`.

#### Пример с `http`:

```dart
import 'dart:io';
import 'package:http/http.dart' as http;

Future<void> fetchDataWithPinning() async {
  final HttpClient client = HttpClient();
  client.badCertificateCallback =
      (X509Certificate cert, String host, int port) {
    // Проверяем сертификат
    final expectedCertHash = 'SHA256/ABC123...';
    final actualCertHash = cert.sha256;
    return actualCertHash == expectedCertHash;
  };

  final request = await client.getUrl(Uri.parse('https://api.example.com/data'));
  final response = await request.close();
  print(response.body);
}
```

#### Пример с `dio`:

```dart
import 'package:dio/dio.dart';

final dio = Dio();
final HttpClient httpClient = HttpClient();

// Настройка SSL Pinning
httpClient.badCertificateCallback =
    (X509Certificate cert, String host, int port) {
  final expectedCertHash = 'SHA256/ABC123...';
  final actualCertHash = cert.sha256;
  return actualCertHash == expectedCertHash;
};

dio.httpClientAdapter = HttpClientAdapter()..httpClient = httpClient;

// Теперь запрос будет использовать SSL Pinning
final response = await dio.get('https://api.example.com/data');
```

> ⚠️ Важно: хэш сертификата должен быть известен заранее и фиксирован. При обновлении сертификата приложение перестанет работать, если не будет обновлено.

## 5. Перехват SSL трафика на мобильных устройствах с помощью HTTP Toolkit

Для тестирования и анализа HTTPS-трафика часто используются инструменты вроде **HTTP Toolkit**, **Charles Proxy**, или **mitmproxy**.

### Как перехватить SSL-трафик:

1. Установите HTTP Toolkit на компьютер.
2. Подключите устройство к той же сети.
3. Настройте прокси на устройстве (обычно через Wi-Fi).
4. Установите сертификат HTTP Toolkit на устройство (это необходимо для расшифровки SSL-трафика).

### Важно:

- При перехвате SSL-трафика, приложение может не работать, если используется SSL Pinning.
- При разработке важно понимать, что SSL Pinning блокирует подобные перехваты.

### Как проверить работу SSL Pinning?

Если вы используете SSL Pinning, и попробуете подключиться через прокси (например, HTTP Toolkit), вы получите ошибку:

```
Certificate pinning failed
```

Это означает, что приложение не доверяет сертификату, который был предоставлен прокси.
