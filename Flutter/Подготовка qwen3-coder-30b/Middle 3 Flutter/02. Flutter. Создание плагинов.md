# Лекция 02: Flutter. Создание плагинов

В этой лекции мы рассмотрим, как создавать собственные плагины для Flutter. Плагины позволяют расширить функциональность Flutter-приложений, интегрируя нативные возможности операционных систем (iOS и Android) с помощью Dart-кода. Это особенно важно при разработке сложных мобильных приложений, где нужно использовать специфические функции платформы.

---

## 📌 1. Отличие терминов: module, package и plugin

Прежде чем перейти к созданию плагинов, важно понимать различия между **module**, **package** и **plugin** в контексте Flutter.

### Module
- **Module** — это просто обобщённое название для модуля кода или библиотеки.
- В контексте Flutter под module часто подразумевается часть приложения, которая может быть вынесена в отдельный пакет или модуль, например, для многоплатформенной разработки.

### Package
- **Package** — это пакет кода на Dart, который можно использовать в проектах Flutter.
- Он может содержать:
  - Dart-код,
  - Ресурсы (изображения, шрифты),
  - Конфигурационные файлы,
  - Тесты.
- Пример: `http`, `provider`, `shared_preferences`.
- Packages могут быть как **pub.dev** (публичные), так и **локальными**.

### Plugin
- **Plugin** — это специальный тип пакета в Flutter, предназначенный для взаимодействия с нативными API операционных систем.
- Плагины позволяют использовать функционал устройств (камера, геолокация, Bluetooth и т.д.) через Dart.
- Они реализуются как:
  - Dart-часть (обёртка),
  - Нативная часть (iOS — Swift/Objective-C, Android — Java/Kotlin).
- Примеры: `camera`, `geolocator`, `firebase_messaging`.

### Вывод:
- **Module** — общее понятие.
- **Package** — это пакет с Dart-логикой.
- **Plugin** — это особый тип package, который взаимодействует с нативными API.

## 📌 2. Создание нового плагина

Создать новый плагин в Flutter можно через командную строку. Для этого используется инструмент `flutter create`.

### Шаги:

1. Откройте терминал.
2. Выполните команду:
```bash
flutter create --platforms=android,ios my_plugin
```
Эта команда создаст проект с названием `my_plugin`, включающий:
- Dart-часть,
- Android-модуль (код на Java/Kotlin),
- iOS-модуль (Swift/Objective-C).

> ⚠️ Плагин должен быть создан как отдельный проект, не как часть основного приложения.

### Структура плагина:

```
my_plugin/
├── android/
│   ├── src/
│   │   └── main/
│   │       └── java/com/example/my_plugin/
│   │           └── MyPlugin.java
│   └── build.gradle
├── ios/
│   ├── Classes/
│   │   └── MyPlugin.swift
│   └── my_plugin.podspec
├── lib/
│   └── my_plugin.dart
├── pubspec.yaml
└── README.md
```

### Пакетные файлы:

#### `pubspec.yaml`
```yaml
name: my_plugin
description: A new Flutter plugin.
version: 0.0.1

environment:
  sdk: '>=2.12.0 <4.0.0'
  flutter: '>=1.20.0'

dependencies:
  flutter:
    sdk: flutter

dev_dependencies:
  flutter_test:
    sdk: flutter
```

#### `lib/my_plugin.dart`
```dart
import 'package:flutter/services.dart';

class MyPlugin {
  static const MethodChannel _channel = MethodChannel('my_plugin');

  static Future<String> getPlatformVersion() async {
    final String version = await _channel.invokeMethod('getPlatformVersion');
    return version;
  }
}
```

#### `android/src/main/java/com/example/my_plugin/MyPlugin.java`
```java
package com.example.my_plugin;

import androidx.annotation.NonNull;
import io.flutter.embedding.engine.plugins.FlutterPlugin;
import io.flutter.plugin.common.MethodCall;
import io.flutter.plugin.common.MethodChannel;
import io.flutter.plugin.common.MethodChannel.MethodCallHandler;
import io.flutter.plugin.common.MethodChannel.Result;

public class MyPlugin implements FlutterPlugin, MethodCallHandler {
  private MethodChannel channel;

  @Override
  public void onAttachedToEngine(@NonNull FlutterPluginBinding flutterPluginBinding) {
    channel = new MethodChannel(flutterPluginBinding.getBinaryMessenger(), "my_plugin");
    channel.setMethodCallHandler(this);
  }

  @Override
  public void onMethodCall(@NonNull MethodCall call, @NonNull Result result) {
    if (call.method.equals("getPlatformVersion")) {
      result.success("Android " + android.os.Build.VERSION.RELEASE);
    } else {
      result.notImplemented();
    }
  }

  @Override
  public void onDetachedFromEngine(@NonNull FlutterPluginBinding binding) {
    channel.setMethodCallHandler(null);
  }
}
```

#### `ios/Classes/MyPlugin.swift`
```swift
import Flutter
import UIKit

public class MyPlugin: NSObject, FlutterPlugin {
  public static func register(with registrar: FlutterPluginRegistrar) {
    let channel = FlutterMethodChannel(name: "my_plugin", binaryMessenger: registrar.messenger())
    let instance = MyPlugin()
    registrar.addMethodCallDelegate(instance, channel: channel)
  }

  public func handle(_ call: FlutterMethodCall, result: @escaping FlutterResult) {
    if call.method == "getPlatformVersion" {
      result("iOS " + UIDevice.current.systemVersion)
    } else {
      result(FlutterMethodNotImplemented)
    }
  }
}
```

## 📌 3. Federated Plugins. Решаемые проблемы

### Что такое Federated Plugins?

**Federated Plugins** — это подход к разработке плагинов, который позволяет разделить реализацию на несколько частей (platform-specific), каждая из которых реализует логику для конкретной платформы.

Это помогает:
- Сделать плагины более гибкими,
- Упростить поддержку разных версий ОС,
- Позволить использовать разные реализации для разных устройств или сред (например, для iOS и Android).

### Проблемы, которые решает Federated Plugins:

1. **Повторное использование кода** — вместо того чтобы писать один плагин, который работает для всех платформ, можно создать "базовый" интерфейс и разные реализации.
2. **Управление зависимостями** — если вы хотите использовать разные версии нативных библиотек, это становится проще.
3. **Легче поддерживать** — каждый плагин может быть реализован независимо и обновляться по отдельности.

---

## 📌 4. Federated Plugins. Как определяется реализация в зависимости от платформы?

В Federated Plugin используется концепция **platform channel**, где:
- Основной плагин (на Dart) вызывает методы через `MethodChannel`.
- Реализация определяется в зависимости от того, на какой платформе запущено приложение.
- Используются **platform-specific** модули (`android`, `ios`), которые обрабатывают вызовы.

Принцип:
1. Dart-часть вызывает метод.
2. Flutter определяет, какая реализация использовать (на основе платформы).
3. Вызывается соответствующий код на Android или iOS.

## 📌 6. PlatformView

**PlatformView** — это возможность отображать нативные элементы пользовательского интерфейса (например, карту Google или WebView) внутри Flutter-приложения.

### Пример: отображение WebView на Android/iOS

#### Dart часть:
```dart
import 'package:flutter/material.dart';
import 'package:flutter/services.dart';

class MyWebView extends StatelessWidget {
  final String url;

  const MyWebView({Key? key, required this.url}) : super(key: key);

  @override
  Widget build(BuildContext context) {
    if (defaultTargetPlatform == TargetPlatform.android) {
      return AndroidView(
        viewType: 'com.example.my_plugin/webview',
        onPlatformViewCreated: (int id) {},
        creationParams: <String, dynamic>{'url': url},
        creationParamsCodec: const StandardMessageCodec(),
      );
    } else if (defaultTargetPlatform == TargetPlatform.iOS) {
      return UiKitView(
        viewType: 'com.example.my_plugin/webview',
        onPlatformViewCreated: (int id) {},
        creationParams: <String, dynamic>{'url': url},
        creationParamsCodec: const StandardMessageCodec(),
      );
    }
    return const Text('Unsupported platform');
  }
}
```

#### Android:
В `android/src/main/java/com/example/my_plugin/WebViewFactory.java`:
```java
public class WebViewFactory {
  public static void registerWith(PluginRegistry registry) {
    final String key = "com.example.my_plugin/webview";
    if (!registry.containsPlugin(key)) {
      registry.registrarFor(key).platformViewRegistry().registerViewFactory(
          key,
          new WebViewFactory());
    }
  }

  private static class WebViewFactory implements PlatformViewFactory {
    @Override
    public PlatformView create(Context context, int id, Object args) {
      return new MyWebView(context);
    }
  }
}
```
