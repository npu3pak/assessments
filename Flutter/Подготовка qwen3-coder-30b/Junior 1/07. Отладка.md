# Лекция 07: Отладка в Flutter

## Введение

Отладка — это один из ключевых навыков любого разработчика. Особенно это важно при создании мобильных приложений, где пользователь может столкнуться с множеством различных ошибок, зависящих от устройств, операционных систем и условий запуска. Flutter предоставляет мощные инструменты для отладки, которые позволяют не только находить ошибки, но и понимать, почему они возникают.

В этой лекции мы подробно рассмотрим:
- Как использовать **breakpoints** (точки останова) для пошагового выполнения кода
- Как отлаживать при возникновении **исключений**
- Использование **print()** и других способов **логирования**
- Как писать логи в **файлы**
- Что такое **бисекция** и как её использовать для поиска ошибок
- Зачем нужны **assert** (утверждения) и как их применять
- Как анализировать **Stack Trace** — стек вызовов при ошибках

## 1. Возможности отладки с помощью Breakpoints

### Что такое Breakpoint?

Breakpoint (точка останова) — это специальная отметка в коде, при достижении которой выполнение программы временно приостанавливается. Это позволяет разработчику вручную изучить состояние переменных, значения, стек вызовов и другие аспекты выполнения.

### Как установить breakpoint в Flutter?

В Flutter вы можете устанавливать breakpoints как в IDE (например, **Android Studio**, **IntelliJ IDEA**, **VS Code**), так и вручную добавляя `debugger();` в коде.

#### Пример:

```dart
void main() {
  runApp(MyApp());
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    int x = 10;
    int y = 20;
    debugger(); // выполнение остановится здесь
    int sum = x + y;
    return MaterialApp(
      home: Scaffold(
        body: Center(
          child: Text('$sum'),
        ),
      ),
    );
  }
}
```

#### Как работают breakpoints в IDE:
1. Установите курсор на строку, где вы хотите остановиться.
2. Нажмите `Ctrl + F8` (или кликните слева от номера строки).
3. При запуске приложения выполнение остановится на этой точке.
4. В IDE можно просматривать значения переменных, шагать по коду, изменять их и т.д.

#### Плюсы использования breakpoints:
- Пошаговое выполнение кода
- Возможность проверить состояние переменных в момент остановки
- Анализ стека вызовов
- Быстрое выявление проблем в логике

## 2. Возможности отладки при возникновении исключений

Flutter позволяет настраивать отладку **при возникновении исключения** (exception breakpoints). Это означает, что выполнение программы будет автоматически останавливаться, если в коде произойдет ошибка.

### Как настроить exception breakpoint:

1. В IDE откройте **Run > View Breakpoints**.
2. Добавьте **Exception Breakpoint** для `Unhandled Exception` или `All Exceptions`.
3. При возникновении ошибки выполнение автоматически остановится в точке, где произошла ошибка.

#### Пример:

```dart
void main() {
  runApp(MyApp());
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        body: Center(
          child: ElevatedButton(
            onPressed: () {
              int a = 10;
              int b = 0;
              int result = a ~/ b; // Ошибка деления на ноль
            },
            child: Text('Click'),
          ),
        ),
      ),
    );
  }
}
```

Если установить exception breakpoint, то выполнение остановится на строке с `int result = a ~/ b;`.

## 3. Логирование в консоли. Приемы использования Print

`print()` — это самый простой способ логирования информации в консоль во время отладки.

### Пример:

```dart
void main() {
  runApp(MyApp());
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    print('Начинаем строить интерфейс');
    int x = 10;
    print('Значение x: $x');
    return MaterialApp(
      home: Scaffold(
        body: Center(
          child: Text('Hello'),
        ),
      ),
    );
  }
}
```

### Как использовать print эффективно:

- Выводить значения переменных
- Проверять, какие функции вызываются и когда
- Понимать поток выполнения

#### Полезные приемы:

```dart
print('Переменная x = $x'); // вывод значения переменной
print('Тип данных: ${x.runtimeType}'); // тип данных
print('Функция вызвана в: ${DateTime.now()}'); // время вызова
```

### Важно:

- `print()` не рекомендуется использовать в production (лучше использовать логирование через библиотеки)
- `print()` работает только в консоли отладки, не в архиве ошибок

## 4. Логирование в файлы

Для более серьезного логирования, особенно при сборе данных об ошибках на устройствах пользователей, рекомендуется использовать **файловое логирование**.

### Пример с использованием `logger` библиотеки:

```yaml
dependencies:
  logger: ^1.3.0
```

```dart
import 'package:logger/logger.dart';

final logger = Logger();

void main() {
  runApp(MyApp());
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    logger.i('Приложение запущено');
    return MaterialApp(
      home: Scaffold(
        body: Center(
          child: ElevatedButton(
            onPressed: () {
              logger.d('Кнопка нажата'); // debug log
              logger.e('Ошибка в коде'); // error log
            },
            child: Text('Нажми'),
          ),
        ),
      ),
    );
  }
}
```

### Как сохранять логи в файл:

```dart
import 'package:logger/logger.dart';
import 'dart:io';

void main() {
  final logFile = File('logs/app.log');
  final logger = Logger(
    printer: PrettyPrinter(),
    output: MultiOutput([
      FileOutput(logFile),
      ConsoleOutput(),
    ]),
  );

  runApp(MyApp(logger: logger));
}
```

## 5. Бисекция (Binary Search) для поиска ошибок

**Бисекция** — это метод поиска ошибки в коде, при котором разработчик последовательно отключает части кода, чтобы определить, где именно возникает проблема.

### Пример:

Допустим, вы заметили, что приложение падает при нажатии на кнопку. Вы можете:

1. Удалить часть логики в `onPressed`
2. Проверить, не появляется ли ошибка
3. Если ошибка исчезла — значит проблема была в этой части
4. Далее уточняете точку

### В Flutter можно использовать:

- `debugPrint` вместо `print()` для более точного контроля логирования
- Удаление/отключение функций по частям
- Логирование времени выполнения (например, при помощи `Stopwatch`)

## 6. Assert (утверждения)

`assert` — это способ проверить условие в коде во время разработки. Если условие ложно, программа выбросит ошибку и остановится.

### Пример:

```dart
void divide(int a, int b) {
  assert(b != 0, 'Делитель не может быть нулём');
  print(a / b);
}

void main() {
  divide(10, 2); // OK
  divide(10, 0); // Ошибка: AssertionError
}
```

### Когда использовать:

- Для проверки входных данных
- Для упрощения отладки (например, если вы знаете, что `x` не должен быть null)
- Для предотвращения логических ошибок

> ⚠️ В production assert **не выполняются**, поэтому используйте их только для отладки.

## 7. Анализ Stack Trace

**Stack Trace** — это список вызовов функций, которые привели к ошибке. Он показывает, каким образом вы попали в точку падения.

### Пример ошибки:

```dart
void main() {
  runApp(MyApp());
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        body: Center(
          child: ElevatedButton(
            onPressed: () {
              throw Exception('Ошибка в коде');
            },
            child: Text('Кликни'),
          ),
        ),
      ),
    );
  }
}
```

#### Stack Trace:

```
Unhandled exception:
Exception: Ошибка в коде
#0      _MyAppState.build.<anonymous closure> (file:///.../main.dart:12:15)
#1      _InkResponseState._handleTap (package:flutter/src/material/material.dart:697:19)
#2      GestureRecognizer.invokeCallback (package:flutter/src/gestures/recognizer.dart:182:24)
...
```

### Как читать Stack Trace:

- Начинается с `Unhandled exception:` — это сообщение об ошибке
- Следом идут строки вида `#0`, `#1` и т.д. — это вызовы функций
- Показывает, откуда пришла ошибка (`main.dart:12`)
- Важно понимать, **в какой функции** произошла проблема

## Заключение

Отладка — это не просто поиск ошибок. Это процесс понимания того, **как работает ваш код**, и **как его можно улучшить**. Используйте:

- Breakpoints для точного анализа
- Exception breakpoints для автоматической остановки при ошибках
- `print()` и логирование для быстрого отслеживания
- `assert` для проверки условий
- Stack Trace для понимания причин ошибок
- Файловое логирование для продакшена
