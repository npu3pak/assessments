# Модульные тесты в Flutter: полное руководство для Junior разработчика

## Введение

Модульные тесты — это фундаментальный инструмент, который помогает обеспечить качество кода и предотвратить ошибки при разработке мобильных приложений. Особенно важно уметь писать тесты при использовании архитектурных подходов, таких как **Bloc/Cubit**, **Repository Pattern** или **Clean Architecture**.

В этой лекции мы подробно рассмотрим, как писать модульные тесты в Flutter, используя язык Dart. Мы разберем структуру тестов, способы их запуска, работу с mock-объектами и особенности тестирования Cubit и репозиториев.

---

## 1. Структура модульных тестов

Модульные тесты в Flutter создаются с использованием фреймворка **test** (встроенный в Dart/Flutter), который позволяет создавать независимые юнит-тесты для отдельных функций, классов или методов.

### Основная структура теста:

```dart
import 'package:flutter_test/flutter_test.dart';

void main() {
  group('Название группы тестов', () {
    test('Описание теста', () {
      // Логика теста
      expect(1 + 1, equals(2));
    });
  });
}
```

### Объяснение:

- `main()` — точка входа для запуска тестов.
- `group()` — группирует тесты по смыслу (например, "Тесты для AuthBloc").
- `test()` — определяет отдельный тест.
- `expect()` — проверяет, соответствует ли фактическое значение ожидаемому.

### Пример: Тестирование простой функции

```dart
int add(int a, int b) => a + b;

void main() {
  group('Функция add', () {
    test('должна возвращать правильную сумму', () {
      expect(add(2, 3), equals(5));
      expect(add(-1, 1), equals(0));
    });
  });
}
```

### Правила структуры:

- Используйте `group()` для логической группировки тестов.
- Именуйте тесты понятно: `test('должен вернуть true при успешной авторизации', () { ... })`.
- Всегда проверяйте граничные случаи и ошибочные сценарии.

## 2. Запуск модульных тестов

Тесты в Flutter запускаются с помощью командной строки.

### Основные команды:

```bash
# Запуск всех тестов
flutter test

# Запуск теста по названию
flutter test --plain-name "имя теста"

# Запуск тестов в определенном файле
flutter test test/my_test.dart

# Запуск тестов с покрытием кода (coverage)
flutter test --coverage
```

### Запуск через IDE:

Если вы используете **VS Code** или **Android Studio**, можно запускать тесты прямо из интерфейса:
- Нажмите на значок ▶️ рядом с `test()` или `main()`.
- Или используйте команду `Flutter: Run All Tests`.

### Покрытие кода:

Для получения информации о том, какие части кода покрыты тестами, используйте:

```bash
flutter test --coverage
```

Это создаст файл `lcov.info`, который можно открыть в IDE или использовать с инструментами, например, **lcov**, для визуализации.

## 3. Использование mock-объектов

Mock-объекты используются для имитации поведения зависимостей (например, сервисов, репозиториев) во время тестирования. Это позволяет изолировать тестируемую логику от внешних факторов.

### Пример:

Предположим, у нас есть сервис `UserService`, который делает HTTP-запросы.

```dart
abstract class UserService {
  Future<User> fetchUser(int id);
}

class RealUserService implements UserService {
  @override
  Future<User> fetchUser(int id) async {
    // Реальный запрос
  }
}
```

### В тесте мы используем мок:

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:mockito/mockito.dart';

class MockUserService extends Mock implements UserService {}

void main() {
  group('UserBloc', () {
    test('должен получить пользователя при успешном вызове', () async {
      final mockService = MockUserService();
      when(mockService.fetchUser(1)).thenAnswer((_) async => User(id: 1, name: 'John'));

      final bloc = UserBloc(mockService);
      await bloc.fetchUserData(1);

      expect(bloc.state, isA<UserLoaded>());
    });
  });
}
```

### Библиотека Mockito:

Для работы с моками используйте библиотеку **mockito**.

```yaml
dev_dependencies:
  mockito: ^5.4.4
```

### Как создать мок:

1. Создайте класс, который расширяет `Mock`.
2. Используйте `when(...)` для определения поведения.
3. Используйте `verify()` для проверки вызовов.

## 4. Тестирование Cubit

Cubit — это часть библиотеки **Bloc** (или **Riverpod**, если используете его). Тестирование Cubit включает проверку состояний и реакции на события.

### Пример простого Cubit:

```dart
class CounterCubit extends Cubit<int> {
  CounterCubit() : super(0);

  void increment() => emit(state + 1);
  void decrement() => emit(state - 1);
}
```

### Тест:

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:bloc_test/bloc_test.dart';

void main() {
  group('CounterCubit', () {
    test('должен начинаться с состояния 0', () {
      final cubit = CounterCubit();
      expect(cubit.state, equals(0));
    });

    blocTest<CounterCubit, int>(
      'должен увеличивать значение при вызове increment',
      build: () => CounterCubit(),
      act: (cubit) => cubit.increment(),
      expect: [1],
    );

    blocTest<CounterCubit, int>(
      'должен уменьшать значение при вызове decrement',
      build: () => CounterCubit(),
      act: (cubit) => cubit.decrement(),
      expect: [-1],
    );
  });
}
```

### Библиотека `bloc_test`:

Упрощает тестирование Cubit и Bloc, особенно для проверки состояний.

```yaml
dev_dependencies:
  bloc_test: ^9.1.5
```

## 5. Тестирование репозиториев

Репозиторий — это слой между бизнес-логикой и источником данных (например, API или БД). При тестировании репозитория нужно проверить его методы.

### Пример репозитория:

```dart
abstract class UserRepository {
  Future<List<User>> fetchUsers();
}

class RealUserRepository implements UserRepository {
  final UserService service;

  RealUserRepository(this.service);

  @override
  Future<List<User>> fetchUsers() async {
    final response = await service.fetchUsers();
    return response.map((json) => User.fromJson(json)).toList();
  }
}
```

### Тест репозитория:

```dart
import 'package:flutter_test/flutter_test.dart';
import 'package:mockito/mockito.dart';

class MockUserService extends Mock implements UserService {}

void main() {
  group('UserRepository', () {
    test('должен возвращать список пользователей', () async {
      final mockService = MockUserService();
      when(mockService.fetchUsers()).thenAnswer((_) async => [
            {'id': 1, 'name': 'John'},
            {'id': 2, 'name': 'Jane'}
          ]);

      final repository = RealUserRepository(mockService);
      final users = await repository.fetchUsers();

      expect(users.length, equals(2));
      expect(users[0].name, equals('John'));
    });
  });
}
```

Создайте приложение с простым Cubit `CounterCubit`, который реализует следующую логику:

- Состояние: `int`
- События:
  - `increment`
  - `decrement`
  - `reset`

Тесты должны включать:

1. Начальное состояние 0.
2. Проверку увеличения на 1.
3. Проверку уменьшения на 1.
4. Проверку сброса состояния.

Дополнительно:
- Используйте `bloc_test` для тестирования.
- Напишите mock-объекты и проверьте, что Cubit вызывает нужные методы.
