# Лекция 14: Mockoon для Flutter-разработки

## Введение

В мире мобильной разработки, особенно при работе с Flutter, часто возникает необходимость тестировать приложение без подключения к реальному серверу. Это связано с тем, что:

- Сервер может быть недоступен
- Нужно тестировать различные сценарии (успешные/неудачные ответы)
- Разработка и тестирование должны происходить независимо
- Необходимость изолировать API-взаимодействие

**Mockoon** — это мощный инструмент для создания эмуляторов REST API, который позволяет создавать "заглушки" (mocks) для ваших API-запросов. Он особенно полезен при разработке Flutter-приложений, когда вам нужно быстро протестировать взаимодействие с сервером, не имея доступа к реальному API.

---

## Что такое Mockoon?

**Mockoon** — это бесплатное и легкое приложение для создания REST API-заглушек. Оно позволяет:

- Создавать эмулируемые endpoints (конечные точки)
- Задавать различные ответы на запросы
- Настроить логи, таймауты и переопределения
- Использовать Mockoon как прокси-сервер для перехвата реальных запросов

Это особенно удобно в Flutter-разработке, где вы можете использовать Mockoon вместо реального API во время разработки и тестирования.

---

## Зачем нужен Mockoon?

Mockoon необходим для:

1. **Тестирования приложений без реального сервера**
2. **Создания разных сценариев ответов** (например, 404, 500, успешный ответ)
3. **Изоляции разработки от инфраструктуры**
4. **Работы в условиях нестабильного интернета или отсутствия API**
5. **Поддержки CI/CD и автоматизации тестирования**

## Как запустить Mockoon в режиме прокси-сервера

Mockoon может работать как **прокси**, перехватывая запросы от вашего приложения и направляя их на реальный сервер или возвращая заглушки.

### Шаги:

1. Установите Mockoon (https://mockoon.com/)
2. Запустите приложение
3. Создайте новую среду (Environment)
4. Включите режим прокси:
   - Откройте настройки среды
   - Перейдите в раздел "Proxy"
   - Включите "Use proxy mode"
5. Укажите адрес реального сервера, например: `https://api.example.com`
6. Запустите прокси

Теперь все запросы с вашего эмулятора будут перенаправлены через Mockoon.

## Как отправлять запросы в Mockoon из эмулятора Android

В Flutter вы можете использовать `http` пакет для отправки HTTP-запросов. Например, если ваш Mockoon работает на `localhost:3000`, то:

```dart
import 'package:http/http.dart' as http;

Future<void> fetchData() async {
  final url = Uri.parse('http://10.0.2.2:3000/api/users'); // Для эмулятора Android
  final response = await http.get(url);

  if (response.statusCode == 200) {
    print(response.body);
  } else {
    print('Ошибка: ${response.statusCode}');
  }
}
```

> **Важно:** `10.0.2.2` — это специальный адрес для доступа к хосту из эмулятора Android. Если вы используете iOS Simulator, то используйте `localhost`.

## Как посмотреть логи

В Mockoon можно просматривать логи запросов:

1. Откройте среду
2. Нажмите на "Logs" (вкладка внизу)
3. Здесь отображаются:
   - Запросы
   - Ответы
   - Время обработки
   - Статусы

Такие логи помогают отлаживать проблемы и понимать, как ваше приложение взаимодействует с API.

## Как переопределить запросы сервера

Mockoon позволяет **переопределять** (override) реальные запросы:

1. Создайте endpoint в Mockoon
2. Укажите метод и путь, например: `GET /api/users`
3. В настройках ответа укажите:
   - Статус
   - Тело ответа
   - Заголовки

Пример ответа:

```json
{
  "id": 1,
  "name": "John Doe",
  "email": "john@example.com"
}
```

## Как сделать несколько заглушек для одного запроса и переключаться между ними

Mockoon позволяет создать несколько **сценариев** (scenarios) для одного endpoint.

### Пример:

1. Создайте endpoint `GET /api/users`
2. Нажмите на "Add scenario"
3. Создайте сценарии:
   - `success` — успешный ответ
   - `error` — ошибка 500
   - `empty` — пустой массив

При каждом вызове будет возвращаться другой ответ в зависимости от текущего сценария.

---

## Как указать таймаут обработки запросов

Mockoon позволяет задать **таймаут** для каждого endpoint:

1. В настройках endpoint
2. Укажите значение в миллисекундах (например, 3000)
3. При этом Mockoon будет "зависать" на заданное время перед отправкой ответа

Это полезно для имитации медленного API или проверки отображения загрузок.

## Пример: Полный пример использования Mockoon в Flutter

### 1. Настройка Mockoon:

Создаем endpoint `GET /api/users`:

```json
{
  "id": 1,
  "name": "John Doe",
  "email": "john@example.com"
}
```

Таймаут: 2000 мс

### 2. Код Flutter:

```dart
import 'package:flutter/material.dart';
import 'package:http/http.dart' as http;
import 'dart:convert';

class UserListScreen extends StatefulWidget {
  @override
  _UserListScreenState createState() => _UserListScreenState();
}

class _UserListScreenState extends State<UserListScreen> {
  List<dynamic> users = [];

  Future<void> fetchUsers() async {
    final url = Uri.parse('http://10.0.2.2:3000/api/users');
    final response = await http.get(url);

    if (response.statusCode == 200) {
      setState(() {
        users = json.decode(response.body);
      });
    } else {
      print('Ошибка загрузки данных');
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Пользователи')),
      body: Center(
        child: ElevatedButton(
          onPressed: fetchUsers,
          child: Text('Загрузить пользователей'),
        ),
      ),
    );
  }
}
```
