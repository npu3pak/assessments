# Лекция 21: pub — Управление зависимостями в Flutter

---

## Введение

При разработке приложений на Flutter важно понимать, как управлять зависимостями проекта. Зависимости — это сторонние пакеты (библиотеки), которые вы используете в своем коде, чтобы не писать всё с нуля. Например, для работы с сетью, базой данных или UI-элементами можно использовать уже готовые библиотеки из экосистемы Dart/Flutter.

Все зависимости проекта управляются через файл `pubspec.yaml`, который находится в корне Flutter-проекта. Файл `pubspec.yaml` — это YAML-файл, содержащий информацию о проекте, его метаданных и зависимостях. Он также используется системой `pub` (или `flutter pub`) для загрузки и управления пакетами.

---

## 1. Общие сведения

### Что такое pub?

**Pub** — это инструмент управления зависимостями в Dart/Flutter. Он позволяет:
- Устанавливать сторонние библиотеки (пакеты).
- Управлять версиями этих пакетов.
- Обновлять зависимости.
- Синхронизировать зависимости с сервером pub.dev.

### Что такое pubspec.yaml?

Файл `pubspec.yaml` — это основной файл, в котором описываются:
- Название проекта (`name`)
- Версия (`version`)
- Описание (`description`)
- Авторы (`authors`)
- Зависимости (`dependencies`, `dev_dependencies`)
- Скрипты (в том числе для сборки)
- И другие параметры

### Пример простого pubspec.yaml

```yaml
name: my_flutter_app
description: A new Flutter project.
version: 1.0.0+1

environment:
  sdk: ">=2.18.0 <3.0.0"

dependencies:
  flutter:
    sdk: flutter
  http: ^0.13.5
  provider: ^6.0.0

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^2.0.0

flutter:
  uses-material-design: true
```

Здесь мы видим, что проект зависит от:
- `http` — для работы с HTTP-запросами.
- `provider` — для управления состоянием (MVVM).
- `flutter_test`, `flutter_lints` — для тестирования и линтинга.

## 2. Указание версии зависимостей

В `pubspec.yaml` можно указывать конкретные версии зависимостей или использовать семантическое версионирование (SemVer).

### Семантическая версия

Семантическая версия состоит из трёх чисел: `MAJOR.MINOR.PATCH`.

- `PATCH` — исправления ошибок.
- `MINOR` — новые функции, обратно совместимые.
- `MAJOR` — изменения, которые ломают обратную совместимость.

Примеры:

```yaml
dependencies:
  http: ^0.13.5     # Возьмёт версию >=0.13.5 и <0.14.0
  provider: ^6.0.0   # Возьмёт версию >=6.0.0 и <7.0.0
```

### Символы версий

| Символ | Значение |
|--------|----------|
| `^`    | Разрешает обновления minor-версий (но не major) |
| `~`    | Разрешает обновления patch-версий |
| `>`    | Более поздняя версия |
| `<`    | Ранее версия |
| `=`    | Точная версия |

Примеры:

```yaml
dependencies:
  http: ^0.13.5   # 0.13.5 <= версия < 0.14.0
  path: ~1.8.0    # 1.8.0 <= версия < 1.9.0
  flutter: =3.0.0 # Только версия 3.0.0
```

> ⚠️ При указании `^` и `~`, важно следить за изменениями в пакетах, особенно если они обновляются часто.

## 3. dev_dependencies

В разделе `dev_dependencies` указываются зависимости, которые нужны только во время разработки или сборки проекта. Например:
- Линтеры
- Тестовые фреймворки
- Утилиты для генерации кода

Эти пакеты **не будут включены** в финальную сборку приложения.

### Пример:

```yaml
dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^2.0.0
  build_runner: ^2.3.0
```

- `flutter_test` — для тестирования Flutter-приложений.
- `flutter_lints` — набор правил линтинга.
- `build_runner` — для генерации кода (например, `json_serializable`, `freezed`).

### Когда использовать `dev_dependencies`?

Используйте `dev_dependencies`, если:
- Пакет нужен только для разработки (например, линтеры).
- Вы не хотите, чтобы он был включён в релизную сборку.

## 4. dependency_overrides

Иногда нужно принудительно использовать определённую версию зависимости, даже если другие пакеты требуют другой. Для этого используется `dependency_overrides`.

### Пример:

```yaml
dependencies:
  http: ^0.13.5
  dio: ^4.0.0

dependency_overrides:
  http: ^0.14.0
```

В этом случае, несмотря на то, что `dio` требует `http: ^0.13.5`, система будет использовать `http: ^0.14.0`.

> ⚠️ Используйте `dependency_overrides` с осторожностью, так как это может привести к конфликтам или нестабильной работе.

## 5. pub.dev

**pub.dev** — это официальный репозиторий пакетов для Dart и Flutter. Здесь можно найти:
- Официальные пакеты (например, `flutter`, `http`)
- Популярные сторонние библиотеки
- Документацию по каждому пакету
- Версии и изменения

### Как использовать pub.dev?

1. Откройте [https://pub.dev](https://pub.dev)
2. Поискайте нужный пакет (например, `provider`, `http`)
3. Найдите последнюю версию
4. Скопируйте строку зависимости и добавьте в `pubspec.yaml`

### Пример:

```yaml
dependencies:
  provider: ^6.0.0   # Взято с pub.dev
```

Также можно использовать команды Flutter CLI для поиска и установки пакетов:

```bash
flutter pub add http
flutter pub add provider
```

## Заключение

Файл `pubspec.yaml` — это основа управления зависимостями в Flutter. Он позволяет:
- Управлять версиями пакетов.
- Разделять зависимости на обычные и для разработки.
- Принудительно переопределять зависимости при необходимости.
- Использовать официальный репозиторий pub.dev.

Понимание этих концепций важно для стабильной работы проекта, особенно при работе с командой или в долгосрочных проектах.

# 1. Практическое задание

### Задача:

1. Создайте новый Flutter-проект:  
   ```bash
   flutter create my_app
   ```

2. Откройте файл `pubspec.yaml` и:
   - Добавьте зависимость `http: ^0.13.5`
   - Добавьте зависимость `provider: ^6.0.0`
   - Добавьте `flutter_lints: ^2.0.0` в `dev_dependencies`
   - Используйте `dependency_overrides`, чтобы принудительно использовать `http: ^0.14.0`

3. Запустите команду:
   ```bash
   flutter pub get
   ```

4. Проверьте, что все зависимости установлены корректно.

5. Создайте файл `main.dart` и используйте `http` и `provider`.
