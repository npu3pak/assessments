# Лекция 13: FVM (Flutter Version Manager)

---

## 🧠 Введение

В мире мобильной разработки, особенно при работе с Flutter, очень важно уметь управлять версиями Flutter SDK. Это позволяет избежать проблем с совместимостью между проектами, тестированием и поддержкой кода на разных устройствах или в команде.

Одним из самых популярных инструментов для управления версиями Flutter является **FVM (Flutter Version Manager)**. Он позволяет легко переключаться между различными версиями Flutter, устанавливать нужные версии, указывать их глобально или локально для конкретного проекта.

---

## 📚 Описание FVM

### Что такое FVM?

**FVM (Flutter Version Manager)** — это инструмент командной строки, который помогает управлять несколькими версиями Flutter SDK на одном компьютере. Он позволяет:

- Устанавливать разные версии Flutter.
- Устанавливать конкретную версию для каждого проекта.
- Переключаться между этими версиями.
- Использовать глобальную версию Flutter, если это необходимо.

### Зачем нужен FVM?

Представьте, что вы работаете над двумя проектами:

1. Один проект использует Flutter 3.10.0.
2. Другой — Flutter 3.13.0.

Если вы будете использовать одну и ту же версию Flutter глобально, у вас могут возникнуть конфликты зависимостей или ошибки компиляции. FVM позволяет вам установить нужную версию для каждого проекта отдельно.

Также FVM удобен при командной разработке, где разные разработчики могут использовать разные версии Flutter.

---

## 🔧 Подключение FVM к проекту

### Шаг 1: Установка FVM

Чтобы начать работу с FVM, его нужно установить на ваш компьютер.

#### Для macOS/Linux:

```bash
brew tap leoafarias/fvm
brew install fvm
```

#### Для Windows (через Chocolatey):

```powershell
choco install fvm
```

#### Проверка установки:

```bash
fvm --version
```

Если выводится версия FVM, значит установка прошла успешно.

---

### Шаг 2: Инициализация проекта с помощью FVM

После установки FVM вы можете инициализировать проект, чтобы использовать его. Для этого в корне вашего Flutter-проекта выполните команду:

```bash
fvm install
```

Эта команда скачает и установит последнюю доступную версию Flutter, указанную в файле `.fvmrc`. Если файла нет — FVM предложит выбрать версию.

> ⚠️ Обратите внимание: если вы не создали `.fvmrc`, то FVM не будет знать, какую версию использовать для проекта. Это может привести к ошибкам при сборке или запуске.

---

### Шаг 3: Установка конкретной версии Flutter

Если вы хотите установить определённую версию Flutter (например, `3.10.0`), используйте:

```bash
fvm install 3.10.0
```

После этого FVM создаст папку `.fvm/flutter_sdk` и установит нужную версию Flutter туда.

---

### Шаг 4: Использование установленной версии

Если вы хотите использовать установленную версию Flutter в текущем проекте, выполните:

```bash
fvm use 3.10.0
```

Эта команда обновит файл `.fvmrc`, указав нужную версию. Также она автоматически изменит переменные окружения так, чтобы `flutter` указывал на нужный путь.

---

## 📦 Настройка используемой версии Flutter

После установки и использования FVM вы можете проверить текущую версию Flutter:

```bash
fvm flutter --version
```

Или просто:

```bash
flutter --version
```

Если вы настроили правильную версию через FVM, вывод должен показать именно ту версию, которую вы указали.

### Проверка текущего пути Flutter

Чтобы убедиться, что система использует нужный путь к Flutter, выполните:

```bash
which flutter
```

Должно отображаться что-то вроде:

```
/home/user/.fvm/flutter_sdk/bin/flutter
```

---

## 🔁 Глобальная версия Flutter

В некоторых случаях вы можете захотеть использовать одну и ту же версию Flutter глобально (например, для общих скриптов или команд). Для этого FVM позволяет установить глобальную версию.

### Установка глобальной версии:

```bash
fvm global 3.10.0
```

Теперь при запуске `flutter` будет использоваться именно эта версия, независимо от того, в каком проекте вы находитесь.

> 💡 Примечание: глобальная версия не рекомендуется для работы с несколькими проектами с разными версиями Flutter. Вместо этого лучше использовать локальные версии через `.fvmrc`.

---

## 🛠️ Как FVM работает под капотом

FVM использует следующую структуру:

```
.fvm/
├── flutter_sdk/
│   └── bin/
│       ├── flutter
│       └── dart
├── .fvmrc
└── versions/
    ├── 3.10.0/
    └── 3.13.0/
```

Когда вы выполняете `fvm use <версия>`, FVM создает символическую ссылку или меняет PATH так, чтобы при вызове `flutter` выполнялась нужная версия.

## 📌 Пример: Полный рабочий процесс с FVM

Допустим, у нас есть проект под Flutter 3.10.0 и мы хотим использовать FVM для управления этой версией.

### 1. Создаем новый Flutter-проект:

```bash
flutter create my_app
cd my_app
```

### 2. Инициализируем FVM в проекте:

```bash
fvm install 3.10.0
fvm use 3.10.0
```

Теперь в папке проекта появляется файл `.fvmrc`, который содержит:

```yaml
flutterVersion: 3.10.0
```

### 3. Проверяем, что все работает:

```bash
flutter --version
```

Результат должен быть:

```
Flutter 3.10.0 • channel stable • https://github.com/flutter/flutter.git
Framework • revision 728d459b7e (2 weeks ago) • 2023-05-02 13:14:44 -0700
Engine • revision 3f02205204
Tools • Dart 3.0.0 • DevTools 2.22.3
```

### Задача:

Создайте два Flutter-проекта:

1. **Project A** — использует Flutter версии `3.10.0`.
2. **Project B** — использует Flutter версию `3.13.0`.

Выполните следующие шаги:

1. Установите FVM.
2. Создайте оба проекта.
3. Для каждого проекта установите соответствующую версию Flutter через FVM.
4. Проверьте, что каждая версия используется правильно (`flutter --version`).
5. Откройте каждый проект в IDE (например, VS Code) и убедитесь, что автодополнение работает корректно.
