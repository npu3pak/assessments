# Лекция: REST-клиент в Flutter

## Введение

Если вы начинаете разрабатывать мобильные приложения, особенно в экосистеме Flutter, то рано или поздно столкнётесь с необходимостью взаимодействовать с сервером через интернет. Это взаимодействие происходит через API — Application Programming Interface, который предоставляет данные и сервисы для внешних клиентов.

Одним из самых распространённых способов общения с серверами является REST (Representational State Transfer). В этой лекции мы подробно рассмотрим, что такое REST-клиент, как он работает, какие есть особенности, а также рассмотрим два основных способа отправки HTTP-запросов в Flutter: `http` и `dio`.

---

## 1. Основные понятия

**REST (Representational State Transfer)** — это архитектурный стиль для проектирования сетевых приложений. Он опирается на стандартные HTTP-методы, такие как GET, POST, PUT, DELETE и другие, чтобы обмениваться данными между клиентом и сервером.

### Ключевые характеристики REST:

1. **Без состояния (Stateless)** — каждый запрос от клиента к серверу должен содержать всю информацию, необходимую для его обработки.
2. **Единый интерфейс** — взаимодействие происходит через стандартные методы HTTP и формат данных (обычно JSON).
3. **Масштабируемость** — благодаря отсутствию состояния, сервер может легко масштабироваться.
4. **Кэширование** — данные могут быть кэшированы на стороне клиента или промежуточных узлов.

### Примеры REST и не-REST

#### REST:
- Запрос: `GET /api/users/123`  
  Описание: Получить информацию о пользователе с ID 123.
- Запрос: `POST /api/users`  
  Описание: Создать нового пользователя.

#### Не-REST:
- Запрос: `GET /getUser?id=123`  
  Это не REST, потому что параметры передаются через строку запроса и не следуют семантике ресурсов.
- Запрос: `POST /api/executeAction?userId=123&operation=delete`  
  Нарушение REST: действия выполняются не через ресурсы, а через параметры.

## 2. Понятие RESTful

**RESTful API** — это API, реализующее принципы REST. Он использует HTTP-методы (GET, POST, PUT, DELETE) для работы с ресурсами и обычно возвращает данные в формате JSON.

### Пример RESTful API:

| Метод | URL                  | Описание                            |
|-------|----------------------|-------------------------------------|
| GET   | `/api/users`         | Получить список пользователей       |
| GET   | `/api/users/123`     | Получить пользователя с ID 123      |
| POST  | `/api/users`         | Создать нового пользователя         |
| PUT   | `/api/users/123`     | Обновить данные пользователя        |
| DELETE| `/api/users/123`     | Удалить пользователя                |

## 3. Использование `http`. Отправка запроса, обработка результата и ошибок

В Flutter для работы с HTTP-запросами можно использовать пакет `http`, который является стандартным решением.

### Подключение `http`

Добавьте в `pubspec.yaml`:

```yaml
dependencies:
  http: ^0.13.5
```

Затем выполните команду:

```bash
flutter pub get
```

### Пример отправки GET-запроса

```dart
import 'package:http/http.dart' as http;
import 'dart:convert';

Future<void> fetchUsers() async {
  final response = await http.get(
    Uri.parse('https://jsonplaceholder.typicode.com/users'),
  );

  if (response.statusCode == 200) {
    // Если запрос успешен, парсим JSON
    List<dynamic> users = jsonDecode(response.body);
    print(users[0]['name']); // Выводит имя первого пользователя
  } else {
    // Обработка ошибки
    throw Exception('Ошибка при загрузке данных');
  }
}
```

### Отправка POST-запроса

```dart
Future<void> createUser() async {
  final response = await http.post(
    Uri.parse('https://jsonplaceholder.typicode.com/users'),
    headers: {'Content-Type': 'application/json'},
    body: jsonEncode({
      'name': 'John Doe',
      'email': 'john@example.com'
    }),
  );

  if (response.statusCode == 201) {
    print('Пользователь создан');
  } else {
    throw Exception('Ошибка создания пользователя');
  }
}
```

### Обработка ошибок

Важно обрабатывать разные типы ошибок:

- `statusCode != 200` — сервер вернул ошибку
- `NetworkException` — нет подключения к интернету
- `FormatException` — ошибка при парсинге JSON

Пример с полной обработкой:

```dart
Future<void> fetchUserData(int id) async {
  try {
    final response = await http.get(
      Uri.parse('https://jsonplaceholder.typicode.com/users/$id'),
    );

    if (response.statusCode == 200) {
      final userData = jsonDecode(response.body);
      print(userData['name']);
    } else {
      throw Exception('Ошибка: ${response.statusCode}');
    }
  } catch (e) {
    print('Произошла ошибка: $e');
  }
}
```

## 4. Использование `dio`. Преимущества перед `http`

Пакет `dio` — это более продвинутая альтернатива `http`, которая предоставляет больше возможностей, таких как:

- Логирование запросов
- Интерцепторы (middleware)
- Обработка ошибок с помощью `DioError`
- Удобное управление таймаутами и переотправкой запросов
- Поддержка файловых операций

### Подключение dio

Добавьте в `pubspec.yaml`:

```yaml
dependencies:
  dio: ^5.0.0
```

Затем:

```bash
flutter pub get
```

### Пример использования `dio`

```dart
import 'package:dio/dio.dart';

final dio = Dio();

Future<void> fetchUsers() async {
  try {
    final response = await dio.get('https://jsonplaceholder.typicode.com/users');

    if (response.statusCode == 200) {
      print(response.data[0]['name']);
    }
  } catch (e) {
    print('Ошибка: $e');
  }
}
```

### Пример с интерцептором

```dart
dio.interceptors.add(InterceptorsWrapper(
  onRequest: (options, handler) {
    print('Запрос: ${options.uri}');
    return handler.next(options);
  },
  onResponse: (response, handler) {
    print('Ответ: ${response.statusCode}');
    return handler.next(response);
  },
  onError: (error, handler) {
    print('Ошибка: ${error.message}');
    return handler.next(error);
  },
));
```

### Преимущества `dio`:

| Возможность         | http     | dio      |
|---------------------|----------|----------|
| Логирование         | ❌       | ✅       |
| Интерцепторы        | ❌       | ✅       |
| Таймауты            | ✅       | ✅       |
| Повторные запросы   | ❌       | ✅       |
| Управление заголовками | ✅     | ✅       |
| Поддержка файлов    | ❌       | ✅       |

---

## 5. Когда использовать `http`, а когда `dio`?

- **`http`** — хорош для простых, небольших проектов, где не нужна дополнительная функциональность.
- **`dio`** — рекомендуется при необходимости логирования, обработки ошибок, работы с файлами, интерцепторами и т.д.
