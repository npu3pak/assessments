# Лекция: Flutter. Bloc

## Введение

Bloc — это паттерн проектирования, который помогает управлять состоянием приложения в Flutter. Он был разработан Робертом Паком (Robert Pacheco) и используется для разделения логики бизнес-процессов от представления (UI). Bloc позволяет создавать предсказуемое и тестируемое состояние приложений.

Bloc применяется, когда ваше приложение требует сложной логики управления состоянием — например, взаимодействие с API, обработка ошибок, синхронизация данных, управление пользовательскими действиями. Он особенно полезен в крупных проектах, где необходимо строгое разделение ответственности между компонентами.

## 1. Архитектура: Представление, Bloc, Repository, Data Provider

В архитектуре приложения на основе Bloc выделяют несколько уровней:

### Представление (View)
Представление — это UI-часть приложения, например `StatefulWidget` или `StatelessWidget`. В нем не должно быть логики бизнес-процессов. Оно только отображает данные и передает пользовательские действия в Bloc.

```dart
class TodoScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Todos')),
      body: BlocBuilder<TodoBloc, TodoState>(
        builder: (context, state) {
          if (state is TodoLoading) {
            return Center(child: CircularProgressIndicator());
          }
          if (state is TodoLoaded) {
            return ListView.builder(
              itemCount: state.todos.length,
              itemBuilder: (context, index) {
                return Text(state.todos[index].title);
              },
            );
          }
          return Container();
        },
      ),
    );
  }
}
```

### Bloc
Bloc — это основной компонент, который обрабатывает события и изменяет состояние. Он не знает о UI, а только реагирует на события и отправляет обновления в представление.

```dart
class TodoBloc extends Bloc<TodoEvent, TodoState> {
  TodoBloc() : super(TodoInitial()) {
    on<LoadTodos>((event, emit) async {
      emit(TodoLoading());
      final todos = await TodoRepository().fetchTodos();
      emit(TodoLoaded(todos));
    });
  }
}
```

### Repository
Repository — это слой, который абстрагирует работу с данными. Он может быть источником данных из API, базы данных или локального хранилища.

```dart
class TodoRepository {
  Future<List<Todo>> fetchTodos() async {
    // Здесь может быть запрос к API или работа с БД
    return [];
  }
}
```

### Data Provider
Data Provider — это слой, который отвечает за получение и предоставление данных. Он может быть связан с `Repository` и инкапсулировать логику взаимодействия с источником данных.

```dart
class TodoDataProvider {
  Future<List<Todo>> fetchTodos() async {
    final response = await http.get(Uri.parse('https://api.example.com/todos'));
    return todoFromJson(response.body);
  }
}
```

### Взаимодействие между слоями

1. **Представление** вызывает событие в Bloc.
2. **Bloc** обрабатывает событие, используя Repository или Data Provider.
3. **Repository/Data Provider** получает данные и передает их обратно в Bloc.
4. **Bloc** изменяет состояние и уведомляет представление через `BlocBuilder`.

## 2. Взаимодействие между несколькими Bloc/Cubit

В больших приложениях может потребоваться взаимодействие между несколькими Bloc или Cubit.

Пример: один Bloc отвечает за пользователей, второй — за их задачи.

```dart
class UserBloc extends Bloc<UserEvent, UserState> {
  UserBloc() : super(UserInitial()) {
    on<FetchUser>((event, emit) async {
      emit(UserLoading());
      final user = await UserRepository().fetchUser(event.id);
      emit(UserLoaded(user));
    });
  }
}

class TodoBloc extends Bloc<TodoEvent, TodoState> {
  TodoBloc() : super(TodoInitial()) {
    on<LoadTodos>((event, emit) async {
      emit(TodoLoading());
      final todos = await TodoRepository().fetchTodosByUserId(event.userId);
      emit(TodoLoaded(todos));
    });
  }
}
```

В представлении можно использовать несколько Bloc через `MultiBlocProvider`:

```dart
class MyScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MultiBlocProvider(
      providers: [
        BlocProvider(create: (_) => UserBloc()),
        BlocProvider(create: (_) => TodoBloc()),
      ],
      child: Scaffold(
        body: Column(
          children: [
            BlocBuilder<UserBloc, UserState>(
              builder: (context, state) {
                if (state is UserLoaded) {
                  return Text(state.user.name);
                }
                return Container();
              },
            ),
            BlocBuilder<TodoBloc, TodoState>(
              builder: (context, state) {
                if (state is TodoLoaded) {
                  return ListView.builder(
                    itemCount: state.todos.length,
                    itemBuilder: (context, index) {
                      return Text(state.todos[index].title);
                    },
                  );
                }
                return Container();
              },
            ),
          ],
        ),
      ),
    );
  }
}
```

## 3. Взаимодействие между несколькими Repository

Когда в приложении есть несколько Repository, они могут взаимодействовать друг с другом.

Пример: `UserRepository` и `TodoRepository` могут работать вместе:

```dart
class UserRepository {
  Future<User> fetchUser(int id) async {
    // Получение пользователя
    return User(id: id, name: 'John');
  }
}

class TodoRepository {
  Future<List<Todo>> fetchTodosByUserId(int userId) async {
    // Зависит от данных из UserRepository
    return [];
  }
}
```

Bloc может использовать оба Repository:

```dart
class TodoBloc extends Bloc<TodoEvent, TodoState> {
  TodoBloc() : super(TodoInitial()) {
    on<LoadTodos>((event, emit) async {
      final user = await UserRepository().fetchUser(event.userId);
      final todos = await TodoRepository().fetchTodosByUserId(user.id);
      emit(TodoLoaded(todos));
    });
  }
}
```

## 4. Отличия Bloc и Cubit. Когда их применять

### Bloc

Bloc — это более строгий паттерн, где каждое событие ведет к изменению состояния через `emit`. Он требует явного определения событий и состояний.

Пример:

```dart
abstract class TodoEvent {}

class LoadTodos extends TodoEvent {}

class TodoBloc extends Bloc<TodoEvent, TodoState> {
  TodoBloc() : super(TodoInitial()) {
    on<LoadTodos>((event, emit) async {
      emit(TodoLoading());
      final todos = await TodoRepository().fetchTodos();
      emit(TodoLoaded(todos));
    });
  }
}
```

### Cubit

Cubit — это более простая альтернатива Bloc. Он не требует событий, а напрямую изменяет состояние через методы `emit`.

Пример:

```dart
class TodoCubit extends Cubit<TodoState> {
  TodoCubit() : super(TodoInitial());

  Future<void> loadTodos() async {
    emit(TodoLoading());
    final todos = await TodoRepository().fetchTodos();
    emit(TodoLoaded(todos));
  }
}
```

### Когда использовать Bloc?

- Когда нужно строго контролировать поток событий.
- Для сложных состояний, где необходимо отслеживать историю изменений.
- В больших проектах, где важно разделение ответственности.

### Когда использовать Cubit?

- Для простых состояний, где не требуется сложная логика событий.
- Когда нужна минимальная абстракция и быстрое прототипирование.

## 5. Принципы именования классов состояний Bloc/Cubit

Имена классов должны быть понятными и отражать суть состояния:

- `TodoInitial` — начальное состояние.
- `TodoLoading` — загрузка данных.
- `TodoLoaded` — данные загружены успешно.
- `TodoError` — ошибка.

Для Cubit:

- `TodoState`
- `TodoLoadingState`
- `TodoSuccessState`

## 6. BlocProvider, BlocConsumer, BlocListener, BlocBuilder, MultiBlocProvider, BlocSelector

### BlocProvider

Используется для предоставления Bloc в дереве виджетов.

```dart
BlocProvider(
  create: (_) => TodoBloc(),
  child: MyScreen(),
)
```

### BlocBuilder

Создает виджет при изменении состояния.

```dart
BlocBuilder<TodoBloc, TodoState>(
  builder: (context, state) {
    if (state is TodoLoaded) {
      return Text(state.todos.length.toString());
    }
    return Container();
  },
)
```

### BlocListener

Выполняет действие при изменении состояния, например, показать сообщение.

```dart
BlocListener<TodoBloc, TodoState>(
  listener: (context, state) {
    if (state is TodoError) {
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(content: Text(state.message)),
      );
    }
  },
  child: Container(),
)
```

### BlocConsumer

Объединяет `BlocBuilder` и `BlocListener`.

```dart
BlocConsumer<TodoBloc, TodoState>(
  listener: (context, state) {
    if (state is TodoError) {
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(content: Text(state.message)),
      );
    }
  },
  builder: (context, state) {
    if (state is TodoLoading) return CircularProgressIndicator();
    if (state is TodoLoaded) return Text('${state.todos.length} items');
    return Container();
  },
)
```

### MultiBlocProvider

Позволяет предоставить несколько Bloc в одном виджете.

```dart
MultiBlocProvider(
  providers: [
    BlocProvider(create: (_) => UserBloc()),
    BlocProvider(create: (_) => TodoBloc()),
  ],
  child: MyScreen(),
)
```

### BlocSelector

Упрощает фильтрацию состояния, чтобы не пересоздавать виджеты при изменении других полей.

```dart
BlocSelector<TodoBloc, TodoState, int>(
  selector: (state) => state.todos.length,
  builder: (context, count) {
    return Text('$count items');
  },
)
```

## 7. Вызов методов Bloc/Cubit в представлении

В представлении вызываются методы `emit` через события или напрямую для Cubit.

### Для Bloc:

```dart
BlocProvider.of<TodoBloc>(context).add(LoadTodos());
```

### Для Cubit:

```dart
BlocProvider.of<TodoCubit>(context).loadTodos();
```

## Практическое задание

Создайте простое приложение для управления задачами (Todo List), используя Bloc. В приложении должны быть следующие функции:

1. Загрузка списка задач.
2. Добавление новой задачи.
3. Удаление задачи.
4. Отображение состояния загрузки и ошибок.

Используйте:
- `Bloc` для управления состоянием.
- `Repository` для получения данных.
- `BlocBuilder` для отображения данных.
- `BlocListener` для обработки ошибок.
